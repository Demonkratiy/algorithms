# Middle of the Linked List

**Тема:** linked-lists (fast / slow) · **Сложность:** easy · **Приоритет:** 🔴 основная

## Условие

Дан `head` односвязного списка. Верни **средний узел**.
Если узлов чётное количество — верни **второй** из двух средних.

Нужно уложиться в **один проход** и `O(1)` памяти (то есть без подсчёта длины заранее и без
копирования в массив).

## Примеры

```
Вход:  1 → 2 → 3 → 4 → 5      Выход: узел 3  (список 3 → 4 → 5)
Вход:  1 → 2 → 3 → 4 → 5 → 6  Выход: узел 4  (вторая из средних)
Вход:  1                      Выход: узел 1
Вход:  1 → 2                  Выход: узел 2
```

## Ограничения

- `1 <= n <= 100`

## 🎯 Цель по сложности

- Время `O(N)`, память `O(1)`.
- «Наивно»: пройти список, посчитать длину `n`, пройти ещё раз до `n / 2`. Это тоже `O(N)`
  по времени, но **два прохода** — на интервью просят один.

## 🧠 Ментальная модель

Два бегуна по одной дорожке: `slow` делает 1 шаг, `fast` — 2. Когда `fast` добежал до конца,
`slow` прошёл ровно половину.

```
1 → 2 → 3 → 4 → 5 → null
s        (slow)
f            (fast)
```

| итерация | slow | fast |
|:---:|:---:|:---:|
| старт | 1 | 1 |
| 1 | 2 | 3 |
| 2 | 3 | 5 |
| 3 | — | `null` → стоп |

## ⚠️ Подводные камни именно этой задачи

1. **Условие цикла — `while (fast && fast.next)`.** Порядок принципиален:
   - `fast` может стать `null` при **чётной** длине,
   - `fast.next` может стать `null` при **нечётной**.
   Если проверять только `fast.next`, на чётной длине получишь `Cannot read properties of null`.
2. **Первая vs вторая середина.** Стартовая позиция (`slow = head`, `fast = head`) даёт
   **вторую** середину при чётной длине. Если бы задача просила первую — надо было бы
   стартовать `fast = head.next` (или менять условие цикла). Понимай, **почему**, а не запоминай.
3. **Возвращаем узел, а не значение** — по условию нужен `ListNode`.
4. Список из одного узла: цикл не выполнится ни разу, вернётся `head` — это правильно.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function middleNode(head) {
  let slow = head;
  let fast = head;

  while (fast !== null && fast.next !== null) {
    slow = slow.next;
    fast = fast.next.next;
  }

  return slow;
}
```

**Почему выходит именно середина.** `fast` двигается вдвое быстрее, значит когда он прошёл `N`
узлов, `slow` прошёл `N / 2`. Условие выхода означает «у `fast` больше нет пары шагов впереди»,
то есть он на конце или за ним.

**Трассировка для чётной длины** `1→2→3→4`:

| итерация | slow | fast | условие `fast && fast.next` |
|:---:|:---:|:---:|:---:|
| старт | 1 | 1 | true |
| 1 | 2 | 3 | true |
| 2 | 3 | null | false → стоп |

Вернём узел `3` — вторая из средних (`2` и `3`) ✅

**Сложность:** время `O(N)` (`fast` пробегает список за `N/2` итераций → всё равно `O(N)`),
память `O(1)`.

</details>

<details>
<summary>Как получить ПЕРВУЮ середину (полезно знать)</summary>

```js
function firstMiddle(head) {
  let slow = head;
  let fast = head;
  while (fast.next !== null && fast.next.next !== null) {   // смотрим на шаг вперёд
    slow = slow.next;
    fast = fast.next.next;
  }
  return slow;   // для 1→2→3→4 вернёт узел 2
}
```

Это понадобится в задаче «Palindrome Linked List», где список делят пополам: там удобнее
остановиться на **конце первой половины**.

</details>

<details>
<summary>Двухпроходный вариант (чтобы понимать разницу)</summary>

```js
function middleNodeTwoPass(head) {
  let n = 0;
  for (let node = head; node; node = node.next) n++;      // проход 1: длина

  let node = head;
  for (let i = 0; i < Math.floor(n / 2); i++) node = node.next;   // проход 2
  return node;
}
```

Тоже `O(N)`/`O(1)`, но требует **знать длину заранее**. Fast/slow ценен тем, что работает
и в потоковом сценарии, когда длину узнать нельзя.

</details>
