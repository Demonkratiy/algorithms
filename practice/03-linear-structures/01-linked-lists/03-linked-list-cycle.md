# Linked List Cycle (обнаружение цикла)

**Тема:** linked-lists (fast / slow, алгоритм Флойда) · **Сложность:** easy → medium · **Приоритет:** 🔴 основная

## Условие

**Часть A (easy).** Дан `head` списка. Верни `true`, если в списке есть цикл, иначе `false`.
Цикл означает, что какой-то узел ссылается `next` на уже пройденный узел.

**Часть B (medium).** Верни **узел, с которого начинается цикл** (или `null`, если цикла нет).

Требование: `O(1)` дополнительной памяти.

## Примеры

```
Часть A:
  3 → 2 → 0 → -4
      ↑         |
      +---------+          → true (цикл начинается с узла 2)

  1 → 2 → null              → false
  1 (сам на себя)           → true
  null                      → false
```

## Ограничения

- `0 <= n <= 10^4`
- Решение с `Set` посещённых узлов допустимо как первый вариант, но цель — `O(1)` памяти.

## 🎯 Цель по сложности

- Часть A: время `O(N)`, память **`O(1)`**.
- Часть B: время `O(N)`, память **`O(1)`**.
- Вариант с `Set`: `O(N)` / `O(N)` — назови его как наивный и оптимизируй.

## 🧠 Ментальная модель

**Черепаха и заяц на круговой дорожке.** Если дорожка замкнута, быстрый бегун рано или поздно
догонит медленного (обгонит на круг). Если дорожка прямая — быстрый просто добежит до конца.

Ключевое наблюдение: за одну итерацию `fast` приближается к `slow` ровно на **1** узел
(двигается на 2, `slow` на 1). Значит, перескочить его невозможно — они обязательно совпадут.

### Часть B: где начинается цикл

Обозначим: `F` — расстояние от головы до входа в цикл, `a` — расстояние от входа до места
встречи, `C` — длина цикла.

В момент встречи: `slow` прошёл `F + a`, `fast` прошёл `2(F + a)`, и разница — целое число
кругов: `2(F + a) - (F + a) = F + a = k·C`.

Отсюда `F = k·C - a`. То есть **расстояние от головы до входа в цикл равно расстоянию от места
встречи до входа** (с точностью до целых кругов).

Практический вывод: после встречи ставим один указатель обратно в `head`, второй оставляем в
точке встречи, двигаем **оба по одному шагу** — они встретятся ровно во входе в цикл.

## ⚠️ Подводные камни именно этой задачи

1. **Проверка на равенство узлов, а не значений.** `slow === fast` сравнивает ссылки на
   объекты — это правильно. `slow.val === fast.val` — грубая ошибка: одинаковые значения бывают
   в списке без цикла.
2. **Условие цикла `while (fast && fast.next)`** — то же, что в поиске середины.
3. **Проверять совпадение ПОСЛЕ шага, а не до.** Если сравнивать в начале итерации, когда оба
   стоят на `head`, они «совпадут» сразу и ты вернёшь `true` для любого списка.
4. **Часть B: второй этап идёт по 1 шагу у обоих.** Частая ошибка — продолжать двигать `fast`
   по два.
5. Нельзя «портить» список (например, помечать узлы), если по условию он должен остаться целым.

<details>
<summary>Подсказка 1 — наивный вариант</summary>

`const seen = new Set();` — идти по списку, класть в `Set` **сами узлы** (объекты).
Если узел уже есть — цикл. Память `O(N)`, зато решение пишется за минуту.

</details>

<details>
<summary>Подсказка 2 — часть A без памяти</summary>

Два указателя, шаг 1 и шаг 2. Внутри цикла **после** продвижения проверь `slow === fast`.

</details>

<details>
<summary>Подсказка 3 — часть B</summary>

После встречи: `let p = head;` и `while (p !== slow) { p = p.next; slow = slow.next; }`,
вернуть `p`.

</details>

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Часть A — решение</summary>

```js
function hasCycle(head) {
  let slow = head;
  let fast = head;

  while (fast !== null && fast.next !== null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow === fast) return true;      // проверка ПОСЛЕ шага
  }

  return false;                          // fast дошёл до конца — цикла нет
}
```

Время `O(N)`: без цикла — `fast` доходит до конца за `N/2` итераций; с циклом — встреча
происходит не позже чем за `N` итераций. Память `O(1)`.

</details>

<details>
<summary>Часть B — решение</summary>

```js
function detectCycle(head) {
  let slow = head;
  let fast = head;

  while (fast !== null && fast.next !== null) {
    slow = slow.next;
    fast = fast.next.next;

    if (slow === fast) {                 // встретились внутри цикла
      let p = head;
      while (p !== slow) {               // оба по ОДНОМУ шагу
        p = p.next;
        slow = slow.next;
      }
      return p;                          // точка входа в цикл
    }
  }

  return null;
}
```

**Почему второй этап работает** — см. вывод в разделе «Ментальная модель»: `F = k·C - a`,
поэтому пройдя `F` шагов от головы и `F` шагов от точки встречи, оба указателя окажутся во
входе в цикл.

Проверь руками на `3 → 2 → 0 → -4`, где `-4.next = 2`:

| итерация | slow | fast |
|:---:|:---:|:---:|
| старт | 3 | 3 |
| 1 | 2 | 0 |
| 2 | 0 | 0 → **встреча** |

Дальше `p = 3`, `slow = 0`. Шаг: `p = 2`, `slow = -4`. Не равны. Шаг: `p = 0`, `slow = 2`.
Не равны. Шаг: `p = -4`, `slow = 0`. Не равны. Шаг: `p = 2`, `slow = 2` → **равны**, ответ — узел `2` ✅

</details>

<details>
<summary>Наивный вариант с Set (для сравнения)</summary>

```js
function hasCycleSet(head) {
  const seen = new Set();
  let node = head;
  while (node !== null) {
    if (seen.has(node)) return true;    // важно: храним ССЫЛКИ на узлы, не значения
    seen.add(node);
    node = node.next;
  }
  return false;
}
```

Время `O(N)`, память `O(N)`. На интервью это отличный первый ответ — но сразу добавь:
_«могу улучшить память до O(1) через fast/slow»_.

</details>
