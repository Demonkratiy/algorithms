# Reverse Linked List

**Тема:** linked-lists (три указателя) · **Сложность:** easy · **Приоритет:** 🔴 основная

> ⚠️ Разобрана в теории ([linked-lists.md](../../../03-linear-structures/01-linked-lists.md)).
> Пиши **по памяти**, не подглядывая. Это фундамент: разворот входит частью в 3-4 другие задачи.

## Условие

Дан `head` односвязного списка. Разверни список и верни новую голову.

```js
class ListNode {
  constructor(val = 0, next = null) { this.val = val; this.next = next; }
}
```

Требуется решить **итеративно**, за `O(1)` дополнительной памяти. Рекурсивную версию напиши
следом — как второй вариант.

## Примеры

```
Вход:  1 → 2 → 3 → 4 → 5 → null
Выход: 5 → 4 → 3 → 2 → 1 → null

Вход:  1 → 2 → null
Выход: 2 → 1 → null

Вход:  null
Выход: null
```

## Ограничения

- Число узлов: `0 <= n <= 5000`
- `-5000 <= Node.val <= 5000`

## 🎯 Цель по сложности

- Время `O(N)`, память **`O(1)`** (итеративно).
- Рекурсия: время `O(N)`, память `O(N)` — назвать как trade-off.

## 🧠 Ментальная модель

Три указателя: `prev` (уже развёрнутая часть), `curr` (текущий узел), `next` (сохранённый
остаток). На каждом шаге разворачиваем ровно одну стрелку и сдвигаем окно из трёх указателей
вправо.

## ⚠️ Подводные камни именно этой задачи

1. **Порядок 4 строк внутри цикла** — единственная сложность задачи. Сохранить → развернуть →
   сдвинуть `prev` → сдвинуть `curr`. Любая перестановка ломает всё.
2. **Возвращаем `prev`, а не `curr`.** В момент выхода `curr === null`.
3. **`prev` стартует с `null`, а не с `head`.** Иначе бывший первый узел будет ссылаться сам на
   себя → бесконечный цикл.
4. В рекурсивной версии обязательно `head.next = null`, иначе два последних узла зациклятся.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function reverseList(head) {
  let prev = null;
  let curr = head;

  while (curr !== null) {
    const next = curr.next;   // 1. сохранить остаток
    curr.next = prev;         // 2. развернуть стрелку
    prev = curr;              // 3. prev → текущий
    curr = next;              // 4. curr → сохранённый следующий
  }

  return prev;
}
```

**Проверка на edge cases:**

- `head = null`: цикл не выполняется, возвращаем `prev = null` ✅
- один узел `1→null`: одна итерация, `1.next = null` (не изменилось), `prev = 1`,
  `curr = null` → возвращаем `1` ✅
- два узла `1→2`: после итерации 1 — `1→null`, `prev=1`, `curr=2`; после итерации 2 —
  `2→1→null`, `prev=2`, `curr=null` → возвращаем `2` ✅

**Сложность:** время `O(N)` — каждый узел посещается один раз; память `O(1)` — три ссылки.

</details>

<details>
<summary>Рекурсивная версия</summary>

```js
function reverseListRecursive(head) {
  if (head === null || head.next === null) return head;

  const newHead = reverseListRecursive(head.next);
  head.next.next = head;    // сосед справа начинает указывать на нас
  head.next = null;         // мы становимся хвостом
  return newHead;           // новая голова "просачивается" наверх без изменений
}
```

Как это читать: вызов «доныривает» до последнего узла (он и есть новая голова), а на обратном
пути каждый узел разворачивает ровно одну стрелку.

Для `1→2→3`: вернулись из глубины с `newHead = 3`, на уровне узла `2` делаем `3.next = 2`,
`2.next = null`; на уровне `1` — `2.next = 1`, `1.next = null`. Итог `3→2→1→null`.

Память `O(N)` из-за стека вызовов — это единственный минус.

</details>
