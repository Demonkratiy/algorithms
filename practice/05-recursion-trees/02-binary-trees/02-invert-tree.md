# Invert Binary Tree

**Тема:** binary-trees (DFS) · **Сложность:** easy · **Приоритет:** 🔴 основная

> Самая знаменитая задача про деревья (та самая, из-за которой автор Homebrew не прошёл
> собеседование в Google). Решается в 4 строки — но нужно понимать, **почему**.

## Условие

Дан корень бинарного дерева. **Зеркально отрази** его — поменяй местами левое и правое
поддерево у каждого узла. Верни корень.

## Примеры

```
Вход:                    Выход:
      4                        4
    /   \                    /   \
   2     7        →         7     2
  / \   / \                / \   / \
 1   3 6   9              9   6 3   1

Вход: [2, 1, 3]  →  [2, 3, 1]
Вход: []         →  []
Вход: [1]        →  [1]
```

## Ограничения

- `0 <= число узлов <= 100`

## 🎯 Цель по сложности

- Время `O(N)`, память `O(h)` (рекурсия) или `O(w)` (итеративно через очередь).

## 🧠 Ментальная модель

Контракт:
1. Что вернуть для `null`? → `null` (нечего разворачивать).
2. Как скомбинировать? → развернуть оба поддерева и **поменять их местами**.

Ключевая мысль: **обмен и рекурсия независимы**. Можно сначала поменять местами `left` и
`right`, а потом рекурсивно развернуть их — или наоборот. Оба варианта верны, потому что
операция «зеркалирование» применяется к каждому узлу независимо.

## ⚠️ Подводные камни именно этой задачи

1. **Обмен через временную переменную или деструктуризацию.**
   `root.left = root.right; root.right = root.left;` ❌ — первое присваивание уже затёрло
   `root.left`, и оба потомка станут одинаковыми. Правильно:
   `[root.left, root.right] = [root.right, root.left];`
2. **Не забыть вернуть `root`.** Функция должна возвращать корень, а не `undefined`.
   Классическая опечатка — забыть `return`.
3. **База `null` возвращает `null`**, а не `0` и не пустой объект.
4. **Дерево мутируется на месте.** Если интервьюер попросит не менять вход — нужно создавать
   новые узлы. Уточни это заранее.
5. Итеративная версия через очередь работает точно так же — важно поменять потомков **до**
   того, как положишь их в очередь (или после — но последовательно, не смешивая).

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function invertTree(root) {
  if (root === null) return null;                              // база

  [root.left, root.right] = [root.right, root.left];           // меняем местами

  invertTree(root.left);                                       // разворачиваем поддеревья
  invertTree(root.right);

  return root;
}
```

Эквивалентная версия (рекурсия сначала, обмен потом) — тоже верна:
```js
function invertTree(root) {
  if (root === null) return null;

  const left = invertTree(root.left);
  const right = invertTree(root.right);

  root.left = right;
  root.right = left;

  return root;
}
```

**Трассировка** для узла `2` (с потомками `1` и `3`):
- меняем местами → `left = 3`, `right = 1`;
- рекурсия в `3` и `1` — оба листья, у них потомки `null`, обмен ничего не меняет;
- возвращаем узел `2` с зеркальными потомками ✅

Для корня `4` то же самое происходит на уровень выше, и поддеревья уже развёрнуты.

**Сложность:** время `O(N)` — по одному посещению узла. Память `O(h)` — глубина стека.

</details>

<details>
<summary>Итеративная версия (BFS)</summary>

```js
function invertTreeIterative(root) {
  if (root === null) return null;

  const queue = [root];

  while (queue.length > 0) {
    const node = queue.shift();

    [node.left, node.right] = [node.right, node.left];

    if (node.left) queue.push(node.left);
    if (node.right) queue.push(node.right);
  }

  return root;
}
```

Здесь порядок обхода вообще не важен — можно и стеком (DFS), и очередью (BFS). Операция
«поменять потомков» локальна для каждого узла и не зависит от того, обработаны ли соседи.

Время `O(N)`, память `O(w)`.

</details>

<details>
<summary>Как объяснять вслух (задача проще, чем её обсуждение)</summary>

> _«Зеркальное отражение — локальная операция: у каждого узла меняются местами потомки.
> Значит, достаточно обойти дерево любым способом и в каждом узле сделать swap. Беру DFS
> рекурсивно: база — null, шаг — обменять потомков и рекурсивно обработать обоих. O(N) по
> времени, O(h) по памяти на стек»._

Если интервьюер спросит про итеративный вариант — очередь или стек, разницы нет; это тоже
стоит проговорить.

</details>
