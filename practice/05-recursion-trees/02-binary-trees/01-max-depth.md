# Maximum Depth of Binary Tree

**Тема:** binary-trees (DFS-контракт) · **Сложность:** easy · **Приоритет:** 🔴 основная

> ⚠️ Разобрана в теории ([binary-trees.md](../../../05-recursion-trees/02-binary-trees.md)).
> Пиши **по памяти** обе версии (DFS и BFS). Это фундамент всех задач на деревья.

## Условие

Дан корень бинарного дерева `root`. Верни его **максимальную глубину** — количество узлов на
самом длинном пути от корня до листа.

```js
class TreeNode {
  constructor(val = 0, left = null, right = null) {
    this.val = val; this.left = left; this.right = right;
  }
}
```

## Примеры

```
Вход: [3, 9, 20, null, null, 15, 7]

        3
       / \
      9  20
        /  \
       15   7

Выход: 3

Вход: [1, null, 2]    →  2
Вход: []              →  0
Вход: [1]             →  1
```

## Ограничения

- `0 <= число узлов <= 10^4`
- `-100 <= Node.val <= 100`

## 🎯 Цель по сложности

- Время `O(N)` — нужно посмотреть каждый узел.
- Память: DFS — `O(h)` (`O(log N)` сбалансированное, `O(N)` вырожденное);
  BFS — `O(w)` (ширина уровня).

## 🧠 Ментальная модель

Два вопроса рекурсивного контракта:

1. Что вернуть для `null`? → `0` (у пустого дерева нет узлов).
2. Как скомбинировать? → `1` (текущий узел) + максимум из глубин поддеревьев.

Не раскручивай стек мысленно. Считай, что вложенные вызовы **уже дали правильные глубины**.

## ⚠️ Подводные камни именно этой задачи

1. **База — `root === null`, возвращаем `0`.** Соблазн проверять `root.left === null &&
   root.right === null` (лист) — тогда придётся отдельно обрабатывать `null`-вход и код
   раздуется. Правильный шаблон: **входим в `null` и там останавливаемся**.
2. **`Math.max`, а не `+`.** Глубина — это самый длинный путь, а не сумма.
3. **Глубина считается в УЗЛАХ, не в рёбрах.** Дерево из одного узла имеет глубину `1`
   (в некоторых учебниках — `0`; здесь — по условию LeetCode). Всегда уточняй определение.
4. **BFS-версия: `levelSize` фиксируется до внутреннего цикла**, иначе уровни смешаются.
5. Пустое дерево → `0`. Проверь, что твой код не падает.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>DFS — решение + объяснение</summary>

```js
function maxDepth(root) {
  if (root === null) return 0;                                    // база

  const leftDepth = maxDepth(root.left);
  const rightDepth = maxDepth(root.right);

  return 1 + Math.max(leftDepth, rightDepth);
}
```

Или в одну строку:
```js
const maxDepth = (root) =>
  root === null ? 0 : 1 + Math.max(maxDepth(root.left), maxDepth(root.right));
```

**Трассировка** (вычисления идут **снизу вверх**, при возврате из рекурсии):

```
        3
       / \
      9  20
        /  \
       15   7

maxDepth(null) = 0        ← базы под листьями
maxDepth(15)   = 1 + max(0, 0) = 1
maxDepth(7)    = 1 + max(0, 0) = 1
maxDepth(9)    = 1 + max(0, 0) = 1
maxDepth(20)   = 1 + max(1, 1) = 2
maxDepth(3)    = 1 + max(1, 2) = 3 ✅
```

**Сложность:** время `O(N)` — каждый узел ровно один вызов.
Память `O(h)` — глубина стека рекурсии. Для сбалансированного дерева `O(log N)`,
для «палки» (`1 → 2 → 3 → ...`) — `O(N)`.
Именно так и отвечай: не просто «`O(N)`», а с оговоркой про высоту.

</details>

<details>
<summary>BFS — решение</summary>

```js
function maxDepthBFS(root) {
  if (root === null) return 0;

  let depth = 0;
  const queue = [root];

  while (queue.length > 0) {
    const levelSize = queue.length;         // фиксируем размер ТЕКУЩЕГО уровня

    for (let i = 0; i < levelSize; i++) {
      const node = queue.shift();
      if (node.left) queue.push(node.left);
      if (node.right) queue.push(node.right);
    }

    depth++;                                 // уровень пройден целиком
  }

  return depth;
}
```

**Почему `levelSize` фиксируется.** Внутри цикла мы добавляем потомков, и `queue.length` растёт.
Если писать `for (let i = 0; i < queue.length; i++)`, условие будет пересчитываться и уровни
сольются.

**Сложность:** время `O(N)`, память `O(w)` — в очереди одновременно лежит один уровень.
Для полного дерева последний уровень содержит ~`N/2` узлов → `O(N)`.

⚠️ `queue.shift()` — `O(N)`. На дереве из `10^4` узлов это заметно. Правильнее — указатель
головы (`let head = 0; const node = queue[head++];`). На интервью **проговори** это.

</details>

<details>
<summary>Бонус: минимальная глубина — не симметричная задача!</summary>

```js
function minDepth(root) {
  if (root === null) return 0;

  // ловушка: у узла с одним потомком нельзя брать min(0, x) = 0
  if (root.left === null) return 1 + minDepth(root.right);
  if (root.right === null) return 1 + minDepth(root.left);

  return 1 + Math.min(minDepth(root.left), minDepth(root.right));
}
```

Для дерева `1 → right: 2` наивный `1 + Math.min(0, 1)` дал бы `1` ❌, но узел `1` **не лист** —
правильный ответ `2`. Минимальная глубина — это путь до **листа**, а не до `null`.

Отличный пример того, что «симметричное» изменение задачи может изменить логику. На интервью
такие ловушки любят: попросят max, а потом min.

</details>
