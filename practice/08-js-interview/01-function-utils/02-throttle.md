# Throttle

**Тема:** js-interview / function-utils · **Сложность:** medium · **Приоритет:** 🔴 основная

> Спрашивают почти так же часто, как debounce — и обычно **сразу после него**, чтобы проверить,
> понимаешь ли ты разницу.

## Условие

Реализуй `throttle(fn, interval)` — обёртку, которая вызывает `fn` **не чаще одного раза
в `interval` миллисекунд**, сколько бы раз её ни дёргали.

Требования:
- **A.** Базовая версия (leading edge): первый вызов проходит сразу, следующие в течение
  `interval` — игнорируются.
- **B.** Версия с trailing: последний из пропущенных вызовов выполняется в конце интервала.

## Примеры

```js
const log = throttle((x) => console.log(x), 1000);

log(1);   // t = 0     → выводится сразу
log(2);   // t = 200   → игнорируется
log(3);   // t = 500   → игнорируется
log(4);   // t = 1100  → выводится (интервал прошёл)
```

С trailing: вызов `log(3)` в `t = 500` не пропадёт — он выполнится в `t = 1000` с последними
аргументами.

## 🎯 Требования к реализации

- Прозрачность: аргументы и `this` прокидываются.
- Гарантия: между двумя фактическими вызовами `fn` проходит не меньше `interval` мс.

## 🧠 Ментальная модель

**Отличие от debounce — в одном предложении:**

> debounce — «выполнить, когда **перестали** дёргать»;
> throttle — «выполнять **регулярно**, но не чаще, чем раз в N мс».

```
события:  ● ● ● ● ● ● ● ● ● ●
debounce:                     ✔
throttle: ✔     ✔     ✔     ✔
```

Два способа реализации:
1. **По времени** — запоминаем `lastCall` и сравниваем с `Date.now()`.
2. **По флагу/таймеру** — держим флаг «сейчас нельзя», снимаем его через `setTimeout`.

## ⚠️ Подводные камни именно этой задачи

1. **Перепутать с debounce.** Если в твоём решении есть `clearTimeout` при каждом вызове — ты
   написал debounce. В throttle предыдущий таймер **не сбрасывается**.
2. **`this` и аргументы** — те же правила: обёртка `function`, вызов через `fn.apply(this, args)`.
3. **Версия по времени не даёт trailing-вызова.** Последний вызов в конце «тишины» просто
   потеряется. Если задача требует «не потерять последнее событие» (например, финальную позицию
   скролла) — нужна версия B.
4. **В trailing-версии нужно сохранять последние аргументы и `this`** в переменных замыкания,
   иначе отложенный вызов уйдёт со старыми данными.
5. **`Date.now()` vs `performance.now()`** — для интервью подойдёт `Date.now()`; упомянуть, что
   `performance.now()` монотонен и не зависит от перевода системных часов, будет плюсом.
6. **Первый вызов должен пройти сразу.** Инициализация `lastCall = 0` это обеспечивает
   (`Date.now() - 0` заведомо больше любого интервала).

## 💡 Подсказки (открывай по очереди)

<details>
<summary>Подсказка 1 — версия по времени</summary>

```js
let lastCall = 0;
return function (...args) {
  const now = Date.now();
  if (now - lastCall < interval) return;
  lastCall = now;
  fn.apply(this, args);
};
```

</details>

<details>
<summary>Подсказка 2 — версия по флагу</summary>

Держи `let isThrottled = false`. Если `true` — выходим. Иначе вызываем `fn`, ставим флаг и
снимаем его через `setTimeout(..., interval)`.

</details>

<details>
<summary>Подсказка 3 — trailing</summary>

Сохраняй `savedArgs` и `savedThis`. Когда таймер срабатывает: если есть сохранённые аргументы —
вызови `fn` с ними и запусти новый интервал.

</details>

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>A: версия по времени (самая короткая)</summary>

```js
function throttle(fn, interval) {
  let lastCall = 0;

  return function (...args) {
    const now = Date.now();

    if (now - lastCall < interval) return;      // ещё рано

    lastCall = now;
    fn.apply(this, args);
  };
}
```

**Плюсы:** три строки, нет таймеров, нечего чистить.
**Минус:** нет trailing — последний вызов внутри интервала теряется навсегда.

Начальное значение `lastCall = 0` гарантирует, что первый вызов пройдёт: `Date.now()` — это
миллисекунды с 1970 года, разница заведомо больше любого `interval`.

</details>

<details>
<summary>A': версия по флагу и таймеру</summary>

```js
function throttle(fn, interval) {
  let isThrottled = false;

  return function (...args) {
    if (isThrottled) return;

    fn.apply(this, args);
    isThrottled = true;

    setTimeout(() => {
      isThrottled = false;
    }, interval);
  };
}
```

Эквивалентна по поведению, но зависит от точности таймеров. Обрати внимание: `clearTimeout`
здесь **нет** — именно это отличает throttle от debounce.

</details>

<details>
<summary>B: с trailing-вызовом (production-версия)</summary>

```js
function throttle(fn, interval) {
  let isThrottled = false;
  let savedArgs = null;
  let savedThis = null;

  function wrapper(...args) {
    if (isThrottled) {
      savedArgs = args;                  // запоминаем последний пропущенный вызов
      savedThis = this;
      return;
    }

    fn.apply(this, args);
    isThrottled = true;

    setTimeout(() => {
      isThrottled = false;

      if (savedArgs) {                   // был пропущенный вызов — выполняем его
        wrapper.apply(savedThis, savedArgs);
        savedArgs = null;
        savedThis = null;
      }
    }, interval);
  }

  return wrapper;
}
```

**Как это работает.** Внутри `setTimeout` мы вызываем не `fn`, а **саму `wrapper`** — благодаря
этому запускается новый интервал, и последующие вызовы снова корректно троттлятся.
Рекурсия здесь безопасна: `savedArgs` обнуляется, поэтому цепочка обрывается, как только
события прекратились.

**Трассировка** (`interval = 1000`):
```
t=0    log(1)  → isThrottled=false → вызов, флаг=true, таймер до 1000
t=200  log(2)  → флаг стоит → savedArgs = [2]
t=500  log(3)  → флаг стоит → savedArgs = [3]   (перезаписали)
t=1000 таймер  → флаг=false, есть savedArgs → wrapper(3) → вызов, новый интервал
```

Итого: выполнились вызовы с `1` и `3` — первый и последний, ничего важного не потеряно.

</details>

<details>
<summary>Как проверить себя офлайн</summary>

```js
const t = throttle((x) => console.log(Date.now() - start, x), 300);
const start = Date.now();

t(1);                          // ~0    → выполнится
setTimeout(() => t(2), 100);   // 100   → пропуск (или trailing на 300)
setTimeout(() => t(3), 200);   // 200   → пропуск
setTimeout(() => t(4), 400);   // 400   → выполнится
```

Проверь два момента: между выполнениями проходит не менее 300 мс, и первый вызов не задержан.

</details>

<details>
<summary>Где применяется (и что отвечать на «зачем»)</summary>

- обработка `scroll` и `mousemove` — событие срабатывает десятки раз в секунду, а обновлять UI
  нужно 10-20 раз;
- отправка аналитики;
- ограничение частоты запросов к API (rate limiting);
- перетаскивание элементов, отрисовка на canvas.

Формулировка для интервью: _«throttle нужен, когда важна регулярность обновлений во время
потока событий; debounce — когда важен только финальный результат»_.

</details>
