# Non-overlapping Intervals

**Тема:** greedy по интервалам (activity selection) · **Сложность:** medium · **Приоритет:** ⚪ дополнительная

> Классический жадный алгоритм, где **ключ сортировки** и есть всё решение. Прямо дополняет
> [Merge Intervals](../../04-search-sort/02-sorting/02-merge-intervals.md), но сортировка там
> другая — и в этом вся соль.

## Условие

Дан массив интервалов `intervals[i] = [start, end]`. Верни **минимальное количество интервалов,
которые нужно удалить**, чтобы оставшиеся не пересекались.

Касание концами пересечением **не считается**: `[1,2]` и `[2,3]` совместимы.

## Примеры

```
Вход:  [[1,2], [2,3], [3,4], [1,3]]
Выход: 1        // удалить [1,3]

Вход:  [[1,2], [1,2], [1,2]]
Выход: 2        // оставить один

Вход:  [[1,2], [2,3]]
Выход: 0

Вход:  [[1,100], [11,22], [1,11], [2,12]]
Выход: 2
```

## Ограничения

- `1 <= intervals.length <= 10^5`
- `-5 * 10^4 <= start < end <= 5 * 10^4`

## 🎯 Цель по сложности

- Время **`O(N log N)`** (сортировка доминирует), память `O(1)` дополнительно.

## 🧠 Ментальная модель

Переформулируй задачу: «удалить минимум» = «**оставить максимум** непересекающихся» и вычесть
из общего количества. Это стандартная задача **activity selection**.

**Жадный выбор: сортируем по КОНЦУ интервала.**

Почему по концу: взяв интервал, который заканчивается раньше всех, мы оставляем максимум
свободного места для остальных. Такой выбор никогда не ухудшает будущие возможности — это и есть
доказательство корректности жадности.

```
[[1,2], [2,3], [3,4], [1,3]]  →  по концу: [1,2], [1,3], [2,3], [3,4]

берём [1,2]           lastEnd = 2, kept = 1
[1,3]: 1 < 2 → пересечение, пропускаем
[2,3]: 2 >= 2 → берём,  lastEnd = 3, kept = 2
[3,4]: 3 >= 3 → берём,  lastEnd = 4, kept = 3

удалить = 4 - 3 = 1 ✅
```

## ⚠️ Подводные камни именно этой задачи

1. **Сортировка по концу, а не по началу.** Проверь на `[[1,100], [11,22], [1,11], [2,12]]`:
   сортировка по началу заставит взять `[1,100]`, который съест всё → ответ `3` вместо `2` ❌.
   **Это главное содержание задачи** — уметь объяснить, почему ключ именно такой.
2. **Касание — не пересечение.** Условие «можно взять» — `start >= lastEnd` (нестрого).
   Со строгим `>` ответ на `[[1,2],[2,3]]` будет `1` вместо `0`.
3. **Считаем удалённые, а не оставленные.** Ответ — `intervals.length - kept`. Легко вернуть не
   ту величину.
4. **Компаратор обязателен** и сравнивает **вторые** элементы: `sort((a, b) => a[1] - b[1])`.
5. **`lastEnd` инициализируется `-Infinity`**, чтобы первый интервал точно взялся. Ноль не
   подойдёт — координаты бывают отрицательными.

## 💡 Подсказки (открывай по очереди)

<details>
<summary>Подсказка 1 — переформулируй</summary>

Минимум удалений = всего минус максимум непересекающихся. Считай второе.

</details>

<details>
<summary>Подсказка 2 — ключ сортировки</summary>

По **концу** интервала. Попробуй сначала сам понять почему — подумай, какой интервал
«дешевле» взять первым.

</details>

<details>
<summary>Подсказка 3 — проход</summary>

`lastEnd = -Infinity`, `kept = 0`. Для каждого интервала: если `start >= lastEnd` — берём,
`kept++`, `lastEnd = end`.

</details>

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function eraseOverlapIntervals(intervals) {
  if (intervals.length === 0) return 0;

  intervals.sort((a, b) => a[1] - b[1]);       // по КОНЦУ

  let kept = 0;
  let lastEnd = -Infinity;

  for (const [start, end] of intervals) {
    if (start >= lastEnd) {                    // не пересекается с последним взятым
      kept++;
      lastEnd = end;
    }
  }

  return intervals.length - kept;
}
```

**Трассировка** `[[1,100], [11,22], [1,11], [2,12]]`
после сортировки по концу: `[1,11], [2,12], [11,22], [1,100]`

| интервал | start >= lastEnd? | kept | lastEnd |
|---|:---:|:---:|:---:|
| `[1,11]` | `1 >= -∞` ✓ | 1 | 11 |
| `[2,12]` | `2 >= 11` ✗ | 1 | 11 |
| `[11,22]` | `11 >= 11` ✓ | 2 | 22 |
| `[1,100]` | `1 >= 22` ✗ | 2 | 22 |

Удалить `4 - 2 = 2` ✅

**Что было бы при сортировке по началу:** `[1,11], [1,100], [2,12], [11,22]` — взяли бы `[1,11]`,
потом `[11,22]` — тоже 2. На этом входе совпало, но на `[[1,100], [2,3], [4,5]]` сортировка по
началу даёт `kept = 1` (взяли `[1,100]`, всё остальное отбросили), а по концу — `kept = 2`.
Всегда проверяй жадность на входе с одним «длинным» интервалом.

**Сложность:** время `O(N log N)` — сортировка; проход `O(N)`. Память `O(1)` дополнительно
(не считая расходов самого `sort`).

</details>

<details>
<summary>Почему сортировка по концу корректна (аргумент для интервью)</summary>

> _«Пусть в оптимальном ответе первым идёт интервал X. Заменим его на интервал Y, который
> заканчивается раньше всех. Y не пересекается ни с чем, с чем не пересекался X (его конец
> левее), значит ответ не ухудшится. Повторяя рассуждение, получаем, что жадный выбор
> "самый ранний конец" всегда приводит к оптимуму»._

Это стандартное доказательство **обменом (exchange argument)** — типовой способ обосновывать
жадные алгоритмы. Даже неформальная его версия сильно повышает оценку на интервью.

</details>

<details>
<summary>Семейство интервальных задач и их ключи сортировки</summary>

| Задача | Сортировать по | Почему |
|---|---|---|
| Merge Intervals | **началу** | обрабатываем слева направо, сливая с последним |
| Non-overlapping Intervals | **концу** | оставляем максимум места для будущих |
| Meeting Rooms II | началу (или события отдельно) | считаем одновременность |
| Minimum Arrows to Burst Balloons | **концу** | буквально эта же задача, другой сюжет |
| Insert Interval | вход уже отсортирован | три фазы: до, слияние, после |

Вывод, который стоит запомнить: **«отсортировать» — это ещё не решение; половина работы в
том, ПО КАКОМУ ключу.**

</details>
