# Rotting Oranges (multi-source BFS)

**Тема:** graphs (BFS по уровням, несколько источников) · **Сложность:** medium · **Приоритет:** 🔴 основная

> Эталон приёма **multi-source BFS**: волна идёт от всех источников одновременно. Тот же приём
> решает «расстояние до ближайшего нуля», «до ближайшего выхода» и т.п.

## Условие

Дана сетка `grid`, где:
- `0` — пустая клетка,
- `1` — свежий апельсин,
- `2` — гнилой апельсин.

Каждую минуту любой свежий апельсин, **соседний по горизонтали или вертикали** с гнилым,
становится гнилым.

Верни **минимальное число минут**, за которое сгниют все апельсины. Если это невозможно
(есть свежий апельсин, до которого гниль не дойдёт) — верни `-1`.

## Примеры

```
Вход:  [[2,1,1],
        [1,1,0],
        [0,1,1]]
Выход: 4

Вход:  [[2,1,1],
        [0,1,1],
        [1,0,1]]
Выход: -1        // левый нижний апельсин изолирован

Вход:  [[0,2]]
Выход: 0         // свежих нет — ждать нечего
```

## Ограничения

- `1 <= m, n <= 10`
- `grid[i][j]` ∈ `{0, 1, 2}` (**числа**, в отличие от Number of Islands)

## 🎯 Цель по сложности

- Время **`O(m · n)`**, память `O(m · n)`.

## 🧠 Ментальная модель

Гниение распространяется **волнами**: за одну минуту заражаются все соседи всех текущих гнилых.
Это в точности BFS по уровням — где «уровень» = «минута».

```
минута 0:  [2] 1  1        в очереди все стартовые гнилые
           1  1  0
           0  1  1

минута 1:   2 [2] 1
          [2] 1  0
           0  1  1
...
```

Два отличия от обычного BFS:
1. **Несколько источников** — в очередь до старта кладём **все** гнилые апельсины.
2. Ответ — **число уровней минус один** (стартовый уровень занимает 0 минут).

Проверка на `-1` делается через счётчик свежих: если после обхода остались незаражённые —
до них не дошли.

## ⚠️ Подводные камни именно этой задачи

1. **Все источники кладутся в очередь ДО начала обхода.** Если запускать отдельный BFS от
   каждого гнилого апельсина, получится и медленнее, и неверно (минуты сложатся, а не пойдут
   параллельно). Это ядро задачи.
2. **Считать минуты, а не клетки.** Нужен приём `levelSize` из
   [BFS по уровням](../../05-recursion-trees/02-binary-trees/03-level-order.md): обрабатываем
   ровно один слой за итерацию, потом `minutes++`.
3. **Стартовый уровень не считается.** Если инкрементировать `minutes` на каждом слое, ответ
   будет на 1 больше. Варианты: увеличивать счётчик **только если на слое кто-то заразился**,
   либо в конце вернуть `minutes - 1`. Первый способ надёжнее.
4. **Случай «свежих ноль» → ответ `0`**, а не `-1` и не `minutes`. Проверь на `[[0,2]]` и `[[0]]`.
5. **Уменьшать счётчик свежих в момент заражения**, а не пересчитывать сетку в конце — иначе
   лишний проход и легко забыть.
6. `0` — это пустая клетка, а **не** «уже гнилой». Не перепутай с задачей про острова, где `'0'`
   означало «посещено».

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function orangesRotting(grid) {
  const rows = grid.length;
  const cols = grid[0].length;
  const directions = [[1, 0], [-1, 0], [0, 1], [0, -1]];

  const queue = [];
  let freshCount = 0;

  for (let r = 0; r < rows; r++) {                 // подготовка: все источники сразу
    for (let c = 0; c < cols; c++) {
      if (grid[r][c] === 2) queue.push([r, c]);
      else if (grid[r][c] === 1) freshCount++;
    }
  }

  if (freshCount === 0) return 0;                  // нечего заражать

  let minutes = 0;
  let head = 0;

  while (head < queue.length && freshCount > 0) {
    const levelSize = queue.length - head;         // фиксируем текущий слой

    for (let i = 0; i < levelSize; i++) {
      const [r, c] = queue[head++];

      for (const [dr, dc] of directions) {
        const nr = r + dr;
        const nc = c + dc;
        if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
        if (grid[nr][nc] !== 1) continue;          // пусто или уже гнилой

        grid[nr][nc] = 2;                          // помечаем при добавлении
        freshCount--;
        queue.push([nr, nc]);
      }
    }

    minutes++;                                     // слой обработан = прошла минута
  }

  return freshCount === 0 ? minutes : -1;
}
```

**Почему нет «лишней» минуты.** Цикл прерывается, как только `freshCount` обнулился, поэтому
последний, «пустой» слой (когда заражать уже некого) не обрабатывается и `minutes` не растёт.

**Трассировка** первого примера:
```
[[2,1,1],
 [1,1,0],
 [0,1,1]]
```
| минута | заражаем | freshCount после |
|:---:|---|:---:|
| старт | — | 6 |
| 1 | (0,1), (1,0) | 4 |
| 2 | (0,2), (1,1) | 2 |
| 3 | (2,1) | 1 |
| 4 | (2,2) | 0 → выход |

Ответ **4** ✅

**Проверка `-1`:** во втором примере клетка `(2,0)` отрезана нулями. Волна затухнет, очередь
кончится, а `freshCount` останется `1` → вернём `-1` ✅

**Сложность:** время `O(m · n)` — подготовка плюс обход, каждая клетка обрабатывается один раз.
Память `O(m · n)` — очередь в худшем случае содержит всю сетку.

</details>

```js
queue.push([r, c, 0]);                 // третий элемент — время заражения

maxTime = Math.max(maxTime, time);

```

Так не нужен приём с `levelSize`. Способ короче, но требует больше памяти на элемент и хуже
обобщается на задачи, где нужна именно «пачка» узлов одного уровня. Полезно знать оба:
`levelSize` — когда важен слой целиком, «время в элементе» — когда важно расстояние до каждого
узла по отдельности.

</details>

<details>
<summary>Чем это отличается от обычного BFS (главный вывод)</summary>

Обычный BFS отвечает на вопрос «расстояние от **одной** точки». Multi-source BFS —
«расстояние до **ближайшего** из множества источников», причём за тот же `O(V + E)`, а не за
`O(источников × (V + E))`.

Задачи этого семейства:
- **01 Matrix** — расстояние от каждой клетки до ближайшего нуля;
- **Walls and Gates** — расстояние до ближайших ворот;
- **Shortest Bridge** — BFS от целого острова;
- **Rotting Oranges** — эта задача.

Как только видишь «от нескольких стартов одновременно» — клади в очередь всё сразу.

</details>
