# Kth Largest Element in an Array

**Тема:** sorting / выбор алгоритма · **Сложность:** medium · **Приоритет:** 🔴 основная

> Задача про **осознанный выбор**: сортировка, куча или quickselect. Часто именно обсуждение
> вариантов ценится выше кода.

## Условие

Дан массив `nums` и число `k`. Верни `k`-й **по величине** элемент (k-th largest), считая от
самого большого. Это не «k-й уникальный» — дубликаты учитываются.

## Примеры

```
Вход:  nums = [3, 2, 1, 5, 6, 4], k = 2       Выход: 5
Вход:  nums = [3, 2, 3, 1, 2, 4, 5, 5, 6], k = 4   Выход: 4
Вход:  nums = [1], k = 1                       Выход: 1
```

Разбор второго примера: отсортировано по убыванию — `[6,5,5,4,3,3,2,2,1]`,
четвёртый элемент — `4`. Обрати внимание: `5` встречается дважды и считается дважды.

## Ограничения

- `1 <= k <= nums.length <= 10^5`
- `-10^4 <= nums[i] <= 10^4`

## 🎯 Цель по сложности

Три уровня ответа — **знать все три**:

| Подход | Время | Память | Когда уместен |
|---|:---:|:---:|---|
| Сортировка + индекс | `O(N log N)` | `O(1)`–`O(N)` | базовый, всегда принимается |
| Min-heap размера `k` | `O(N log k)` | `O(k)` | когда `k` мал, поток данных |
| Quickselect | `O(N)` средн., `O(N²)` худш. | `O(1)` | «оптимальный» ответ |

## 🧠 Ментальная модель

**Сортировка.** Отсортировать по убыванию и взять `nums[k - 1]`. Просто и надёжно.
Эквивалентно: отсортировать по возрастанию и взять `nums[n - k]`.

**Куча (heap).** Держать min-heap из `k` наибольших элементов. Каждый новый элемент сравниваем
с минимумом кучи; если больше — заменяем. В конце корень кучи и есть `k`-й по величине.
⚠️ В JS **нет встроенной кучи** — её пришлось бы писать (~30 строк). На интервью достаточно
описать идею словами и назвать сложность.

**Quickselect.** Идея quick sort, но рекурсия идёт **только в одну половину**: после разбиения
мы знаем позицию pivot и понимаем, в какой части лежит искомый индекс. Средняя сложность
`O(N)`, потому что `N + N/2 + N/4 + ... = 2N`.

## ⚠️ Подводные камни именно этой задачи

1. **`nums.sort()` без компаратора** — лексикографическая сортировка. Классика ошибок.
2. **Индекс после сортировки.** По убыванию — `nums[k - 1]`; по возрастанию — `nums[n - k]`.
   Проверь на `k = 1`: должен вернуться максимум. Здесь очень легко ошибиться на единицу.
3. **Дубликаты считаются.** «2-й по величине» в `[5, 5, 4]` — это `5`, а не `4`. Не пытайся
   применять `Set`, если условие не просит уникальности.
4. **Quickselect: худший случай `O(N²)`.** Если назвал `O(N)` — обязательно уточни, что это
   **средняя** сложность, и она достигается при случайном выборе pivot. Интервьюер почти всегда
   спрашивает именно это.
5. Куча в JS не встроена — не говори «возьму приоритетную очередь» так, будто она есть в языке.

<summary>Вариант 1 — сортировка (базовый ответ)</summary>

```js
function findKthLargest(nums, k) {
  nums.sort((a, b) => b - a);      // по убыванию
  return nums[k - 1];
}
```

Проверка индекса: `k = 1` → `nums[0]` = максимум ✅
`nums = [3,2,1,5,6,4]`, `k = 2` → отсортировано `[6,5,4,3,2,1]` → `nums[1] = 5` ✅

**Сложность:** время `O(N log N)`, память — зависит от реализации `sort` (`O(N)` для TimSort в
V8); сам алгоритм дополнительной памяти не требует. Мутирует вход — при необходимости копируй.

</details>

<details>
<summary>Вариант 2 — quickselect (оптимальный)</summary>

```js
function findKthLargest(nums, k) {
  const targetIndex = nums.length - k;      // k-й по величине = (n-k)-й по возрастанию

  let left = 0;
  let right = nums.length - 1;

  while (true) {
    const pivotIndex = partition(nums, left, right);

    if (pivotIndex === targetIndex) return nums[pivotIndex];
    if (pivotIndex < targetIndex) left = pivotIndex + 1;   // ищем правее
    else right = pivotIndex - 1;                            // ищем левее
  }
}

function partition(nums, left, right) {
  // случайный pivot защищает от худшего случая на отсортированных входах
  const randomIndex = left + Math.floor(Math.random() * (right - left + 1));
  [nums[randomIndex], nums[right]] = [nums[right], nums[randomIndex]];

  const pivot = nums[right];
  let boundary = left;                        // граница "меньших или равных"

  for (let i = left; i < right; i++) {
    if (nums[i] <= pivot) {
      [nums[i], nums[boundary]] = [nums[boundary], nums[i]];
      boundary++;
    }
  }

  [nums[boundary], nums[right]] = [nums[right], nums[boundary]];   // pivot на место
  return boundary;
}
```

**Как это работает.** `partition` расставляет элементы так, что слева от pivot — не большие
его, справа — не меньшие. Значит, `pivot` уже стоит на своей **финальной** позиции в
отсортированном массиве. Сравнив эту позицию с `targetIndex`, мы отбрасываем половину.

**Почему в среднем `O(N)`.** Каждый шаг обрабатывает вдвое меньший кусок:
`N + N/2 + N/4 + ... = 2N` → `O(N)`. Худший случай (неудачные pivot подряд) — `O(N²)`,
но случайный выбор делает его практически невероятным.

Память `O(1)` — сортировка на месте, цикл вместо рекурсии.

</details>

<details>
<summary>Вариант 3 — min-heap размера k (идея)</summary>

Псевдокод:
```
heap = min-heap
для каждого num из nums:
    heap.push(num)
    если heap.size > k: heap.pop()   // выбрасываем минимум
вернуть heap.peek()                   // корень = k-й по величине
```

Инвариант: в куче всегда `k` наибольших элементов из просмотренных, и её корень — наименьший
из них, то есть ровно `k`-й по величине.

Время `O(N log k)`, память `O(k)`. **Лучший выбор, когда `k` мал, а `N` огромен** или когда
данные приходят потоком и не помещаются в память целиком — это стоит проговорить.
В JS кучу нужно реализовывать вручную; на интервью обычно достаточно описать идею.
