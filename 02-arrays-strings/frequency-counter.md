# Frequency Counter (Hash Map)

## 🎯 Идея

**Frequency Counter (частотный словарь)** — паттерн, где мы за **один проход** строим
«словарь подсчёта»: ключ → сколько раз он встретился. Затем отвечаем на вопросы о данных,
заглядывая в этот словарь за `O(1)`, вместо того чтобы каждый раз перебирать массив заново.

Это прямое применение того, что ты уже знаешь: **`Map`/`Object` дают доступ по ключу за `O(1)`**,
поэтому вложенный цикл сравнения (`O(N²)`) сворачивается в линейный проход (`O(N)`).

Типичный сценарий: «сравнить две коллекции», «найти дубликат/уникальный», «проверить
анаграмму» — везде, где наивное решение сравнивает элементы попарно.

---

## 🧠 Как распознать (ментальная модель)

Думай про Frequency Counter, когда в условии есть:
- **«анаграмма»**, «те же символы/числа», «переставленные»;
- **«сколько раз встречается»**, «самый частый», «первый уникальный»;
- **«есть ли дубликат»**, «повторяется ли»;
- сравнение **двух массивов/строк** на совпадение состава;
- напрашивается вложенный цикл «для каждого элемента ищу совпадение в другом массиве».

> 💡 Ключевая интуиция: вместо того чтобы для каждого элемента бегать по всему массиву в
> поисках пары (`O(N²)`), я один раз **записываю все частоты в Map** (`O(N)`), а потом
> сверяюсь с ней за `O(1)`.

**Set vs Map здесь** (вспомни decision guide):
- нужен только факт «был/не был», уникальность → **`Set`**;
- нужно **сколько раз** (счётчик) → **`Map`** (или `Object`).

---

## ⏱️ Сложность

- Время: **`O(N)`** — один-два линейных прохода (построить словарь + свериться).
- Память: **`O(K)`**, где `K` — число различных ключей (уникальных символов/чисел). Часто это
  ограничено алфавитом → на практике `O(1)`, если алфавит фиксирован (например, 26 букв).

## 📝 Эталонный разбор

### Задача: Valid Anagram
Даны две строки `s` и `t`. Верни `true`, если `t` — анаграмма `s` (состоит из тех же
символов в том же количестве, порядок не важен).

```
s = "anagram", t = "nagaram"  → true
s = "rat",     t = "car"      → false
```

### Ход мысли (UMPIRE)

**Understand:** две строки. Анаграмма = одинаковый **мультимножественный** состав символов
(каждый символ встречается одинаковое число раз). Edge case: разная длина → сразу `false`.

**Match:** «те же символы в том же количестве» → **Frequency Counter**.

**Наивно (brute force):** для каждого символа `s` искать и вычёркивать его в `t` → `O(N²)`.

**Идея оптимизации:** посчитать частоты символов в `s`, затем «вычитать» их символами `t`.
Если в конце все счётчики нулевые — строки анаграммы.

**Plan:**
1. Если длины разные → `false`.
2. Пройти по `s`, наращивая счётчик каждого символа в `Map`.
3. Пройти по `t`, уменьшая счётчики; если символа нет или счётчик ушёл в минус → `false`.
4. Если дошли до конца → `true`.

### Решение
```js
function isAnagram(s, t) {
  if (s.length !== t.length) return false; // разный размер — точно не анаграмма

  const counts = new Map();

  // 1) считаем символы s
  for (const ch of s) {
    counts.set(ch, (counts.get(ch) || 0) + 1);
  }

  // 2) вычитаем символами t
  for (const ch of t) {
    const current = counts.get(ch) || 0;
    if (current === 0) return false;  // символа из t нет в s (или уже исчерпан)
    counts.set(ch, current - 1);
  }

  return true; // длины равны и все счётчики сошлись
}
```

### Разбор ключевой идиомы
```js
counts.set(ch, (counts.get(ch) || 0) + 1);
```
`counts.get(ch)` вернёт `undefined`, если ключа ещё нет. `undefined || 0` даёт `0` —
безопасный старт счётчика. Затем `+ 1`. Это стандартный способ «инкремент счётчика в Map».

> 📌 Почему проверка длины в начале важна: без неё строки `"aab"` и `"aabb"` могли бы дать
> неверный результат — вторая имеет «лишние» символы, которые первый цикл не увидит. Ранний
> выход по длине закрывает этот случай и экономит работу.

**Сложность:** время `O(N)` (два прохода), память `O(K)` — `K` различных символов (≤ 26 для
латиницы → фактически `O(1)`).

### Альтернатива: через Object
Тот же паттерн часто пишут на объекте:
```js
const counts = {};
for (const ch of s) counts[ch] = (counts[ch] || 0) + 1;
```
Работает так же за `O(1)` на операцию. `Map` предпочтительнее, когда ключи не строки или нужен
`.size`; для строковых символов `Object` тоже уместен.

## ⚠️ Частые ошибки / чек-лист

- ❌ Забыть проверку `s.length !== t.length` в задачах на анаграмму/совпадение состава.
- ❌ Инкремент без дефолта: `counts.set(ch, counts.get(ch) + 1)` даст `NaN` для нового ключа
  (`undefined + 1`). Всегда `(counts.get(ch) || 0) + 1`.
- ❌ Брать `Set` там, где нужен счётчик (сколько **раз**) — `Set` не считает кратность.
- ❌ Для `Object`-счётчика помнить: ключи приводятся к строке (`1` и `'1'` — один ключ).
- ✅ Часто хватает **одного** прохода на построение + одного на сверку — оба `O(N)`.
- ✅ Edge cases: пустые строки/массивы, разная длина, один элемент, все одинаковые.
