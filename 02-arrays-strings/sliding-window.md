# Sliding Window

## 🎯 Идея

**Sliding Window (скользящее окно)** — это подмножество Two Pointers. Мы держим «окно» —
непрерывный участок массива/строки между двумя указателями `left` и `right` — и **скользим**
им по данным, вместо того чтобы каждый раз пересчитывать всё заново.

Главная выгода: задачи вида «найти лучший подотрезок» наивно решаются вложенным циклом
(перебрать все начала × все концы) — это `O(N²)`. Скользящее окно решает их за **один проход
`O(N)`**, потому что при сдвиге окна мы **до-считываем** изменение, а не пересчитываем сумму/счётчик с нуля.

Две разновидности:

1. **Fixed window (окно фиксированного размера `k`).** Размер окна задан. Скользим:
   добавляем новый элемент справа, убираем старый слева. Классика: «максимальная сумма
   подмассива длины k», «среднее по окну».
2. **Dynamic window (окно переменного размера).** Окно растёт/сжимается по условию. Обычно:
   `right` расширяет окно, а когда нарушено условие — `left` сжимает. Классика: «самая длинная
   подстрока без повторов», «минимальный подмассив с суммой ≥ target».

---

## 🧠 Как распознать (ментальная модель)

Думай про Sliding Window, когда в условии есть:
- слова **«подстрока» / «подмассив» / «непрерывный участок»** (contiguous!);
- «самый длинный / самый короткий / максимальный / минимальный» участок при каком-то условии;
- «окно размера `k`», «ровно/не более K различных символов», «сумма ≥ / = target».

> ⚠️ Ключевое слово — **непрерывный (contiguous)**. Если можно брать элементы вразброс
> (подпоследовательность), скользящее окно **не** подходит.

Ментальная картинка dynamic window:
> _«`right` жадно расширяет окно вправо. Как только окно стало "плохим" (нарушило условие) —
> двигаю `left` вправо, сжимая окно, пока оно снова не станет "хорошим". На каждом шаге
> обновляю ответ»._

---

## ⏱️ Сложность

- Время: **`O(N)`**. Хотя есть вложенный `while` для сжатия, каждый элемент **входит в окно
  один раз и выходит один раз** → суммарно не больше `2N` движений указателей.
- Память: обычно **`O(1)`** (fixed window, счётчик суммы) или **`O(K)`** (dynamic window с
  Map/Set для хранения содержимого окна, где K — размер алфавита/окна).

> 📌 Частая ошибка новичков — увидеть вложенный `while` и сказать «это `O(N²)`». Нет!
> Указатель `left` **не откатывается назад**, он только движется вперёд. Поэтому линейно.

## 📝 Эталонный разбор

### Задача: Maximum Sum Subarray of Size K (fixed window)
Дан массив чисел `nums` и число `k`. Найди максимальную сумму среди всех непрерывных
подмассивов длины ровно `k`.

```
nums = [2, 1, 5, 1, 3, 2], k = 3
Ответ: 9   // подмассив [5, 1, 3]
```

### Ход мысли (UMPIRE)

**Understand:** вход — массив + `k`. Выход — число (макс. сумма окна длины `k`).

**Match:** «непрерывный подмассив фиксированной длины k» → **fixed sliding window**.

**Наивно (brute force):** для каждого старта считать сумму `k` элементов → `O(N·k)` ≈ `O(N²)`.
Проблема: мы пересчитываем перекрывающиеся суммы заново.

**Идея оптимизации (суть окна!):** соседние окна отличаются всего на 2 элемента — один ушёл
слева, один пришёл справа. Значит новую сумму можно получить из старой:
`sum = sum - nums[left] + nums[right]`. Пересчёт за `O(1)` вместо `O(k)`.

**Plan:**
1. Посчитать сумму первых `k` элементов — стартовое окно.
2. Скользить: прибавлять новый правый, вычитать ушедший левый, обновлять максимум.

### Решение
```js
function maxSumSubarray(nums, k) {
  if (nums.length < k) return null; // окно не помещается

  // 1) сумма первого окна [0 .. k-1]
  let windowSum = 0;
  for (let i = 0; i < k; i++) {
    windowSum += nums[i];
  }
  let maxSum = windowSum;

  // 2) скользим окном вправо
  for (let right = k; right < nums.length; right++) {
    windowSum += nums[right];         // вошёл новый правый
    windowSum -= nums[right - k];     // вышел старый левый
    maxSum = Math.max(maxSum, windowSum);
  }

  return maxSum;
}
```

**Почему `nums[right - k]`?** Когда правый край на индексе `right`, левый край окна длины `k`
стоит на `right - k`. Именно этот элемент «выпадает» из окна.

**Сложность:** время `O(N)` (один проход), память `O(1)`.

### Мини-набросок dynamic window (для интуиции)
Задача «самая длинная подстрока без повторяющихся символов» — окно растёт, а при повторе
символа `left` сдвигается, пока дубликат не уйдёт:
```js
function longestUnique(s) {
  const seen = new Set();
  let left = 0, best = 0;
  for (let right = 0; right < s.length; right++) {
    while (seen.has(s[right])) {   // окно "плохое" — сжимаем слева
      seen.delete(s[left]);
      left++;
    }
    seen.add(s[right]);            // теперь окно "хорошее"
    best = Math.max(best, right - left + 1); // длина окна
  }
  return best;
}
```
Это будет твоя практическая задача — здесь только для ощущения формы.

### Тот же алгоритм через Map (символ → последний индекс) с «прыжком»
Вместо пошагового сжатия `left` можно хранить в `Map` **последний индекс каждого символа**
и при повторе **перепрыгнуть** `left` сразу за прошлую позицию дубликата — за одно действие,
без вложенного цикла:
```js
function longestUnique(s) {
  const lastIndex = new Map();   // символ -> его последний встреченный индекс
  let left = 0, best = 0;

  for (let right = 0; right < s.length; right++) {
    const ch = s[right];
    // если символ уже видели И его позиция ВНУТРИ текущего окна — прыгаем
    if (lastIndex.has(ch) && lastIndex.get(ch) >= left) {
      left = lastIndex.get(ch) + 1;
    }
    lastIndex.set(ch, right);    // обновляем последний индекс символа
    best = Math.max(best, right - left + 1);
  }
  return best;
}
```
> ⚠️ Условие `lastIndex.get(ch) >= left` обязательно: без него `left` может «прыгнуть назад»
> на индекс символа, который уже вне окна. Проверь на `"abba"` — там это критично.

Обе версии — `O(N)` по времени. Map-версия делает меньше операций (нет пошаговых `delete`),
но обе принимаются на интервью.

## ⚠️ Частые ошибки / чек-лист

- ❌ Считать вложенный `while` за `O(N²)`. `left` только вперёд → суммарно `O(N)`.
- ❌ Путать длину окна: длина = `right - left + 1` (не `right - left`).
- ❌ В fixed window забыть вычесть ушедший левый элемент (`nums[right - k]`).
- ❌ Применять окно к **непрерывному** участку, когда в задаче на самом деле подпоследовательность.
- ❌ Обновлять ответ не в тот момент (для dynamic — **после** восстановления «хорошего» окна).
- ✅ Всегда проверяй edge cases: `k > length`, пустой вход, все элементы одинаковые.
