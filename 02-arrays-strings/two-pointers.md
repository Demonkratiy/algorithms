# Two Pointers

## 🎯 Идея

**Two Pointers (два указателя)** — вместо одного бегунка по массиву мы держим **два индекса**
и двигаем их по определённым правилам. Это позволяет заменить вложенный цикл (`O(N²)`) на
один проход (`O(N)`).

Две основные разновидности:

1. **Навстречу друг другу (opposite ends).** Один указатель `left` в начале, другой `right`
   в конце. Двигаем их навстречу. Классика: разворот массива, поиск пары с заданной суммой в
   **отсортированном** массиве, проверка палиндрома.
2. **В одном направлении, с разной скоростью (fast / slow).** Оба идут слева направо, но по
   разным правилам. Классика: удаление дубликатов на месте, разделение массива, поиск цикла
   в связном списке (об этом позже).

---

## 🧠 Как распознать (ментальная модель)

Думай про Two Pointers, когда видишь:
- Массив/строка **отсортирован**, и нужно найти пару/тройку по сумме или разнице.
- Нужно что-то делать **с двух концов** (палиндром, разворот).
- Нужно **на месте (in-place)** переставить/отфильтровать элементы без доп. памяти.
- «В лоб» напрашивается вложенный цикл, но данные упорядочены — почти всегда его можно
  свернуть в два указателя.

> 💡 Ключевая интуиция варианта «навстречу»: в **отсортированном** массиве, если сумма пары
> слишком мала — двигаем `left` вправо (увеличиваем сумму); если слишком велика — двигаем
> `right` влево (уменьшаем сумму). Сортировка даёт нам это «направление подсказки».

---

## ⏱️ Сложность

- Время: **`O(N)`** — каждый указатель проходит массив максимум один раз.
- Память: **`O(1)`** — храним только пару индексов, ничего не аллоцируем.

Это огромный плюс: Two Pointers часто даёт `O(1)` памяти там, где хэш-подход требует `O(N)`.

## 📝 Эталонный разбор

Разберём **два указателя навстречу** на классической задаче.

### Задача: Two Sum II (отсортированный массив)
Дан **отсортированный по возрастанию** массив `numbers` и число `target`. Верни индексы
(1-based) двух чисел, дающих в сумме `target`. Гарантируется ровно одно решение.

```
numbers = [2, 7, 11, 15], target = 9
Ответ: [1, 2]   // 2 + 7 = 9
```

### Ход мысли (проговариваем UMPIRE)

**Understand:** вход — отсортированный массив + target. Выход — два индекса. Решение точно есть.

**Match:** «отсортированный массив + пара с суммой» → это флаг **Two Pointers навстречу**.
(Наивно можно двойным циклом `O(N²)`, но отсортированность подсказывает лучше.)

**Plan:**
- Ставлю `left = 0`, `right = последний индекс`.
- Считаю `sum = numbers[left] + numbers[right]`.
- Если `sum === target` → нашли, возвращаю индексы.
- Если `sum < target` → сумма мала, нужно **больше** → двигаю `left++` (слева числа больше).
- Если `sum > target` → сумма велика, нужно **меньше** → двигаю `right--`.
- Повторяю, пока `left < right`.

### Решение
```js
function twoSum(numbers, target) {
  let left = 0;
  let right = numbers.length - 1;

  while (left < right) {
    const sum = numbers[left] + numbers[right];

    if (sum === target) {
      return [left + 1, right + 1]; // 1-based индексы
    } else if (sum < target) {
      left++;   // нужно увеличить сумму
    } else {
      right--;  // нужно уменьшить сумму
    }
  }

  return []; // по условию не достигается
}
```

### Почему это работает (важно понять, не заучить!)
Мы **никогда не пропустим** правильную пару. На каждом шаге мы гарантированно отбрасываем
элемент, который не может участвовать в ответе:
- если `sum < target`, то `numbers[left]` слишком мал даже с самым большим правым — значит
  `left` в паре ни с кем не сработает, двигаем его;
- симметрично для `right`.

Это и есть сила отсортированности: одно сравнение говорит, в какую сторону идти.

**Сложность:** по времени `O(N)` (указатели вместе проходят массив один раз), по памяти `O(1)`.

### Бонус: разворот массива на месте (два указателя навстречу)
```js
function reverse(arr) {
  let left = 0;
  let right = arr.length - 1;
  while (left < right) {
    [arr[left], arr[right]] = [arr[right], arr[left]]; // swap
    left++;
    right--;
  }
  return arr;
}
```
Тот же приём: меняем концы местами и сходимся к центру. Время `O(N)`, память `O(1)`.

## ⚠️ Частые ошибки / чек-лист

- ❌ **Забыть, что вариант «навстречу» требует ОТСОРТИРОВАННЫХ данных.** На неотсортированном
  массиве поиск пары так не работает (там нужен `Set`/Map — см. frequency counter).
- ❌ Условие цикла: используй `while (left < right)`. `left <= right` может привести к тому,
  что элемент образует пару сам с собой.
- ❌ Off-by-one: `right` начинается с `length - 1`, а не с `length`.
- ❌ Забыть сдвинуть указатель в какой-то ветке → бесконечный цикл.
- ✅ Проверь edge cases: пустой массив, 1 элемент, нет решения.
- ✅ Если условие говорит «на месте / O(1) памяти» — это сильный намёк на Two Pointers.
