# Greedy (жадные алгоритмы)

## 🎯 Идея

**Жадный алгоритм** на каждом шаге делает локально лучший выбор и **никогда не пересматривает
его**. Никакого перебора, никакой таблицы — один проход.

Это самый простой и самый быстрый класс алгоритмов… и самый опасный: жадность корректна
**не всегда**, и на интервью главный вопрос будет не «как написать», а **«почему это работает»**.

```js
// весь жадный алгоритм часто выглядит так
let best = ...;
for (const item of items) {
  best = обновить(best, item);      // решение принимается сразу и навсегда
}
return best;
```

---

## 🧠 Как распознать

Маркеры:
- «максимальная прибыль», «минимальное количество шагов», «можно ли дойти»;
- **интервалы**: «максимум непересекающихся встреч», «минимум удалений»;
- задача про **последовательность цен / прыжков / сдачи**;
- ощущение «тут очевидно, что надо брать самое большое/маленькое».

> ⚠️ Последний пункт — ловушка. «Очевидно» ≠ «верно». Прежде чем писать жадность, **попытайся
> сломать её контрпримером** (см. ниже).

### Обязательный тест: контрпример

Coin Change, монеты `[1, 3, 4]`, сумма `6`:
- жадно: берём `4`, остаток `2` → `1 + 1` → итого **3 монеты**;
- оптимально: `3 + 3` → **2 монеты**.

Жадность сломана → нужен DP. А вот для монет `[1, 5, 10, 25]` (реальные номиналы) жадность
корректна — но это **свойство конкретного набора**, а не общее правило.

**Правило:** если локально лучший выбор **закрывает** будущие возможности — жадность под
подозрением. Если выбор ничего не «портит» — скорее всего работает.

## 📝 Эталонный разбор: Best Time to Buy and Sell Stock

Дан массив `prices`, где `prices[i]` — цена акции в день `i`. Можно совершить **одну** покупку
и одну продажу (продать строго позже, чем купил). Найти максимальную прибыль; если заработать
нельзя — вернуть `0`.

```
[7, 1, 5, 3, 6, 4] → 5    (купить за 1 в день 1, продать за 6 в день 4)
[7, 6, 4, 3, 1]    → 0    (цены только падают)
```

### Ход мысли

**Наивно:** перебрать все пары `(купить, продать)` → `O(N²)`.

**Наблюдение.** Идя слева направо, для каждого дня-продажи нам нужен только **минимум цены
слева от него**. А минимум можно поддерживать на лету одной переменной.

**Почему жадность корректна.** Продавая в день `i`, выгоднее всего было купить по самой низкой
цене среди дней `0..i-1`. Это утверждение верно **независимо** от будущих дней — значит выбор
ничего не портит, и пересматривать его не придётся.

### Решение
```js
function maxProfit(prices) {
  let minPrice = Infinity;
  let maxProfit = 0;

  for (const price of prices) {
    if (price < minPrice) {
      minPrice = price;                 // нашли более выгодный день покупки
    } else {
      maxProfit = Math.max(maxProfit, price - minPrice);
    }
  }

  return maxProfit;
}
```

**Трассировка** `[7, 1, 5, 3, 6, 4]`:

| price | minPrice | прибыль сегодня | maxProfit |
|:---:|:---:|:---:|:---:|
| 7 | 7 | — | 0 |
| 1 | 1 | — | 0 |
| 5 | 1 | 4 | 4 |
| 3 | 1 | 2 | 4 |
| 6 | 1 | 5 | **5** |
| 4 | 1 | 3 | 5 |

Ответ `5` ✅

**Сложность:** время `O(N)`, память `O(1)`.

> 💡 Эту же задачу можно рассматривать как sliding window (окно между покупкой и продажей) или
> как DP (`dp[i]` = максимальная прибыль до дня `i`). Все три взгляда дают один код — хороший
> повод сказать интервьюеру: _«здесь жадность совпадает с DP, потому что состояние сводится к
> одному числу»_.

## 🔁 Второй сюжет: Best Time to Buy and Sell Stock II

То же самое, но сделок можно совершать **сколько угодно** (покупать и продавать хоть каждый
день, но держать не больше одной акции).

```js
function maxProfitMultiple(prices) {
  let profit = 0;
  for (let i = 1; i < prices.length; i++) {
    if (prices[i] > prices[i - 1]) profit += prices[i] - prices[i - 1];
  }
  return profit;
}
```

**Почему это верно.** Любой выгодный отрезок роста `a → b` можно разбить на сумму соседних
приростов, и наоборот. Значит суммирование **всех положительных разностей соседей** и есть
максимум.

Контринтуитивно, но проверь на `[1, 2, 3]`: `(2-1) + (3-2) = 2`, столько же, сколько при
покупке за 1 и продаже за 3 ✅

Смена одного слова в условии («одна сделка» → «много сделок») полностью меняет решение —
поэтому **читай условие до конца** и уточняй ограничения вслух.

## ⏱️ Сложность

Жадные решения обычно:
- **`O(N)`** — один проход (акции, jump game);
- **`O(N log N)`** — если требуется предварительная сортировка (интервалы, activity selection);
- память **`O(1)`**.

Это и есть их главный плюс — они дешевле DP. Минус один: их надо **обосновывать**.

## ⚠️ Частые ошибки / чек-лист

- ❌ **Применить жадность без проверки.** Всегда пробуй контрпример на 3-4 элементах.
- ❌ **Продать раньше, чем купил.** В задаче про акции прибыль всегда `price - minPrice`, где
  `minPrice` встретился **раньше**. Порядок обхода это гарантирует автоматически.
- ❌ **Инициализировать `maxProfit` значением `-Infinity`.** Если заработать нельзя, ответ `0`,
  а не отрицательное число. А вот `minPrice` начинается с `Infinity` — это верно.
- ❌ **Сортировать интервалы не по тому ключу.** Для «максимум непересекающихся» сортируют по
  **концу**, для «слить пересекающиеся» — по **началу** (см.
  [Merge Intervals](../practice/04-search-sort/02-sorting/02-merge-intervals.md)).
- ❌ Путать «жадность работает» и «жадность проще» — на интервью нужно **доказательство**, хотя
  бы неформальное: _«выбор X не ухудшает будущие варианты, потому что…»_.
- ✅ Пустой массив и массив из одного элемента — обязательные проверки.

## ✅ Мини-опрос для самопроверки

1. Чем жадный алгоритм отличается от DP по способу принятия решения?
2. Как проверить, что жадность в конкретной задаче корректна?
3. Приведи контрпример, показывающий, что жадность не работает в Coin Change.
4. Почему в «много сделок» достаточно сложить все положительные разности соседей?
5. Почему `maxProfit` инициализируется нулём, а `minPrice` — бесконечностью?
6. По какому ключу сортировать интервалы для «максимума непересекающихся» и почему?

<details>
<summary>Ответы</summary>

1. Жадный делает выбор **один раз и навсегда**, исходя из текущего шага. DP рассматривает
   **все** варианты выбора, запоминая результаты подзадач, и поэтому гарантированно находит
   оптимум.
2. Попытаться построить контрпример на маленьком входе; если не выходит — сформулировать, почему
   локальный выбор не ухудшает будущие возможности («свойство жадного выбора»).
3. Монеты `[1, 3, 4]`, сумма `6`: жадно `4 + 1 + 1 = 3` монеты, оптимально `3 + 3 = 2` монеты.
4. Потому что любой отрезок роста равен сумме приростов соседних дней, а отрицательные разности
   мы просто не берём (в эти дни не держим акцию). Ограничений на число сделок нет, значит можно
   «нарезать» рост как угодно мелко.
5. Ответ по условию не может быть отрицательным: если прибыльной сделки нет, возвращаем `0` —
   поэтому старт `0`. А `minPrice` должен быть заведомо больше любой реальной цены, чтобы первый
   же день его перебил — поэтому `Infinity`.
6. По **концу** интервала. Взяв встречу, которая заканчивается раньше всех, мы оставляем
   максимум свободного времени для остальных — то есть локальный выбор не закрывает будущие
   варианты. Сортировка по началу здесь даёт неверный ответ (длинная ранняя встреча съест всё).

</details>
