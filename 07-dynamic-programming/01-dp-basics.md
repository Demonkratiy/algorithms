# Dynamic Programming (динамическое программирование)

## 🎯 Идея

**DP = рекурсия + запоминание результатов подзадач.**

Ты уже применял его, сам того не называя: мемоизация в
[Фибоначчи](../practice/05-recursion-trees/01-recursion/01-fibonacci-memo.md) превратила `O(2^N)` в
`O(N)`. Всё динамическое программирование — развитие этой мысли.

DP применим, когда выполняются два условия:

1. **Оптимальная подструктура** — ответ на задачу выражается через ответы на подзадачи
   («чтобы узнать `f(n)`, достаточно знать `f(n-1)` и `f(n-2)`»).
2. **Перекрывающиеся подзадачи** — одни и те же подзадачи встречаются много раз.
   Если бы не встречались, хватило бы обычной рекурсии («разделяй и властвуй»).

> 💡 Второй пункт — это то, что отличает DP от merge sort: там подзадачи **не повторяются**,
> поэтому запоминать нечего.

## 🧠 Как распознать

Маркеры в условии:
- «**сколько способов** сделать X»;
- «**максимальная / минимальная** сумма, длина, стоимость, прибыль»;
- «можно ли **набрать** сумму / разбить на части»;
- есть **выбор на каждом шаге** («взять или не взять», «шагнуть на 1 или на 2»);
- наивное решение — перебор с экспоненциальной сложностью.

### Универсальный процесс из 4 шагов

Не пытайся «увидеть формулу». Иди по шагам — работает почти всегда:

**1. Определи состояние.** Что описывает подзадачу? Обычно это `dp[i]` = ответ для префикса
длины `i` / для суммы `i` / для позиции `i`.
> Спроси себя: _«какой минимальный набор параметров однозначно описывает подзадачу?»_

**2. Найди переход (рекуррентное соотношение).** Как `dp[i]` выражается через предыдущие?
> Спроси: _«какой был последний шаг, и какие у него были варианты?»_

**3. Определи базу.** Чему равны `dp[0]`, `dp[1]` — то, что известно без вычислений.

**4. Определи порядок вычисления.** Обычно слева направо, чтобы нужные значения уже были готовы.

### Три формы записи одного и того же

```js
// 1. TOP-DOWN (рекурсия + мемоизация) — ближе к «как думаешь»
function climb(n, memo = new Map()) {
  if (n <= 2) return n;
  if (memo.has(n)) return memo.get(n);

  const result = climb(n - 1, memo) + climb(n - 2, memo);
  memo.set(n, result);
  return result;
}

// 2. BOTTOM-UP (таблица) — без рекурсии, нет риска переполнить стек
function climbTable(n) {
  if (n <= 2) return n;

  const dp = new Array(n + 1);
  dp[1] = 1;
  dp[2] = 2;
  for (let i = 3; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2];

  return dp[n];
}

// 3. ОПТИМИЗАЦИЯ ПАМЯТИ — если нужны только последние k значений
function climbOptimized(n) {
  if (n <= 2) return n;

  let prev = 1;
  let curr = 2;
  for (let i = 3; i <= n; i++) [prev, curr] = [curr, prev + curr];

  return curr;
}
```

> 💬 **Стратегия на интервью.** Сначала озвучь перебор и его сложность. Потом добавь
> мемоизацию. Потом, если попросят, разверни в таблицу и урежь память. Такая
> последовательность «brute force → memo → table → O(1) space» — сама по себе сильный ответ,
> даже если ты не дойдёшь до последнего шага.

## ⏱️ Сложность

Правило: **время = (число состояний) × (стоимость одного перехода)**.

| Задача | Состояний | Переход | Время | Память |
|---|:---:|:---:|:---:|:---:|
| Climbing Stairs | `N` | `O(1)` | `O(N)` | `O(1)` после оптимизации |
| House Robber | `N` | `O(1)` | `O(N)` | `O(1)` |
| Coin Change | `amount` | `O(монет)` | `O(amount · C)` | `O(amount)` |
| LIS (простое) | `N` | `O(N)` | `O(N²)` | `O(N)` |
| Unique Paths | `m · n` | `O(1)` | `O(m · n)` | `O(n)` |

Память почти всегда можно уменьшить, если переход смотрит только на несколько предыдущих
состояний.

## 📝 Эталонный разбор: House Robber

Дан массив `nums` — деньги в домах, стоящих в ряд. Нельзя грабить **два соседних** дома
(сработает сигнализация). Найти максимальную сумму.

```
[2, 7, 9, 3, 1] → 12   (дома 0, 2, 4: 2 + 9 + 1)
[1, 2, 3, 1]    → 4    (дома 0 и 2)
```

### Шаг 1: состояние
`dp[i]` = максимальная сумма, которую можно взять из **первых `i` домов** (`nums[0..i-1]`).

### Шаг 2: переход — «взять или не взять»
Смотрим на **последний** дом (`i - 1`), у него ровно два варианта:

- **Не грабим его** → результат такой же, как для `i - 1` домов: `dp[i - 1]`.
- **Грабим** → добавляем его деньги, но тогда предыдущий дом трогать нельзя,
  значит берём лучшее для `i - 2` домов: `nums[i - 1] + dp[i - 2]`.

Берём максимум:
```
dp[i] = Math.max(dp[i - 1], nums[i - 1] + dp[i - 2])
```

**Это и есть ключевой шаблон DP — «взять или не взять».** Он же в Coin Change, Knapsack,
Subsets — везде, где на каждом элементе есть бинарный выбор.

### Шаг 3: база
`dp[0] = 0` (нет домов), `dp[1] = nums[0]` (один дом — берём его).

### Шаг 4: порядок
Слева направо, от `i = 2` до `n`.

### Решение
```js
function rob(nums) {
  const n = nums.length;
  if (n === 0) return 0;
  if (n === 1) return nums[0];

  const dp = new Array(n + 1);
  dp[0] = 0;
  dp[1] = nums[0];

  for (let i = 2; i <= n; i++) {
    dp[i] = Math.max(dp[i - 1], nums[i - 1] + dp[i - 2]);
  }

  return dp[n];
}
```

**Трассировка** `[2, 7, 9, 3, 1]`:

| i | дом `nums[i-1]` | не берём: `dp[i-1]` | берём: `nums[i-1] + dp[i-2]` | dp[i] |
|:-:|:---:|:---:|:---:|:---:|
| 1 | 2 | — | — | 2 |
| 2 | 7 | 2 | 7 + 0 = 7 | **7** |
| 3 | 9 | 7 | 9 + 2 = 11 | **11** |
| 4 | 3 | 11 | 3 + 7 = 10 | **11** |
| 5 | 1 | 11 | 1 + 11 = 12 | **12** |

Ответ `12` ✅ Заметь: на шаге 4 выгоднее было **пропустить** дом — жадность («бери, если
можешь») здесь не работает.

### Оптимизация памяти до `O(1)`
```js
function robOptimized(nums) {
  let skip = 0;      // лучший результат БЕЗ предыдущего дома  (dp[i-2])
  let take = 0;      // лучший результат ДО текущего дома      (dp[i-1])

  for (const money of nums) {
    [skip, take] = [take, Math.max(take, skip + money)];
  }

  return take;
}
```
Переход смотрит только на два предыдущих значения — массив не нужен. Время `O(N)`, память `O(1)`.

## ⚠️ Частые ошибки / чек-лист

- ❌ **Пытаться сразу написать формулу.** Иди по 4 шагам: состояние → переход → база → порядок.
  Проговаривай их вслух — интервьюер оценивает именно процесс.
- ❌ **Путаница между индексом массива и индексом `dp`.** Если `dp[i]` — «первые `i` элементов»,
  то текущий элемент это `nums[i - 1]`, а не `nums[i]`. Выбери соглашение и запиши его
  комментарием.
- ❌ **Неверная база.** `dp[0]` для «максимума» обычно `0`, а для «минимума количества» —
  `0`, но остальные ячейки инициализируются `Infinity`. Смешение ломает всё.
- ❌ **Применять жадность там, где нужен DP.** «Бери самое большое» в House Robber или Coin
  Change даёт неверный ответ. Признак: локально лучший выбор закрывает будущие варианты.
- ❌ **Не передавать `memo` в рекурсию** — мемоизация тихо перестаёт работать.
- ❌ **Забыть про `O(1)`-оптимизацию памяти** — её почти всегда спрашивают следующим вопросом.
- ✅ Проверяй на входах длины 0, 1 и 2 — базы ломаются именно там.

## 🧭 DP или Greedy?

| | Greedy | DP |
|---|---|---|
| Как решает | локально лучший выбор на каждом шаге | перебирает варианты, запоминая результаты |
| Когда корректен | когда локальный оптимум ведёт к глобальному | всегда (если состояние задано верно) |
| Сложность | обычно `O(N)` / `O(N log N)` | обычно `O(N)`–`O(N²)` |
| Пример | Best Time to Buy/Sell Stock | House Robber, Coin Change |

Проверка: **придумай контрпример к жадности**. Для Coin Change с монетами `[1, 3, 4]` и суммой
`6` жадность даёт `4 + 1 + 1 = 3 монеты`, а оптимум `3 + 3 = 2 монеты`. Нашёл контрпример —
нужен DP. Не нашёл и можешь обосновать — greedy.

Подробнее — в [greedy.md](02-greedy.md).

## ✅ Мини-опрос для самопроверки

1. Какие два условия должны выполняться, чтобы задача решалась через DP?
2. Назови 4 шага, по которым строится DP-решение.
3. В чём разница между top-down и bottom-up? Когда какой лучше?
4. Почему merge sort — не DP, хотя он тоже рекурсивно решает подзадачи?
5. Как понять, что жадный алгоритм здесь **не** сработает?
6. Как оценить время работы DP-решения, не считая строки кода?

<details>
<summary>Ответы</summary>

1. **Оптимальная подструктура** (ответ выражается через ответы подзадач) и
   **перекрывающиеся подзадачи** (одни и те же подзадачи встречаются многократно).
2. Состояние (что такое `dp[i]`) → переход (как выражается через предыдущие) → база
   (что известно сразу) → порядок вычисления.
3. Top-down — рекурсия с мемоизацией: пишется ближе к ходу мысли, считает только реально нужные
   состояния, но тратит стек. Bottom-up — таблица: без рекурсии, легко оптимизируется по памяти,
   но считает все состояния подряд. На интервью удобно начать с top-down и развернуть в
   bottom-up.
4. Потому что его подзадачи **не перекрываются**: каждая половина массива обрабатывается ровно
   один раз, запоминать нечего. Это «разделяй и властвуй», а не DP.
5. Найти контрпример. Признак опасности: локально лучший выбор **закрывает** будущие
   возможности (взял дом — потерял соседний; взял большую монету — остаток стал неудобным).
6. Время = **число состояний × стоимость одного перехода**. Например, Coin Change: состояний
   `amount`, переход перебирает все монеты → `O(amount · C)`.

</details>
