# Stack & Queue (стек и очередь)

## 🎯 Идея

Две простейшие структуры, отличающиеся **только тем, с какого конца забирают элемент**.

**Stack (стек)** — LIFO, *last in, first out*. Как стопка тарелок: кладёшь и берёшь сверху.
**Queue (очередь)** — FIFO, *first in, first out*. Как очередь в магазине.

```
Stack:  push(1) push(2) push(3) → [1, 2, 3]   pop() → 3
Queue:  enqueue(1,2,3)          → [1, 2, 3]   dequeue() → 1
```

В JS обе делаются на массиве, но **не любым способом** — см. раздел про `shift()` ниже.

```js
// Stack на массиве — идеально
const stack = [];
stack.push(x);        // O(1)
stack.pop();          // O(1)
stack[stack.length - 1];   // заглянуть наверх (peek), O(1)
stack.length === 0;        // пусто?
```

## 🧠 Как распознать (ментальная модель)

### Stack — когда нужен «последний открытый / ближайший слева»
- **скобки, теги, вложенность** — «каждому открывающему нужен парный закрывающий»;
- **undo / история / назад в браузере**;
- **«ближайший больший (меньший) элемент»** — monotonic stack;
- **обход в глубину без рекурсии** (стек заменяет стек вызовов);
- «обработать в обратном порядке».

> 💡 Главная интуиция стека: _«я откладываю элемент, потому что пока не знаю ответ для него.
> Отвечу, когда встречу того, кто его закрывает»._

### Queue — когда важен порядок поступления
- **BFS**, «обход по уровням» дерева/графа;
- «кратчайший путь в невзвешенном графе»;
- планировщики, буферы, «обработать в порядке поступления».

### Monotonic stack (важный подпаттерн)
Стек, в котором значения намеренно держат **монотонными** (только убывают или только растут).
Перед `push` выталкиваем всё, что нарушает порядок — и **в момент выталкивания** даём ответ для
вытолкнутого элемента. Так решаются задачи вида:
- «следующий больший элемент справа»,
- «сколько дней ждать более тёплого дня»,
- «наибольший прямоугольник в гистограмме» (hard).

Сложность такого обхода — `O(N)`, потому что **каждый элемент кладётся и вынимается ровно один
раз** (амортизированный анализ — тот же аргумент, что в sliding window).

## ⏱️ Сложность

| Операция | Стоимость | Комментарий |
|---|:---:|---|
| `push` / `pop` (массив, конец) | `O(1)` амортиз. | правильная реализация стека |
| `peek` (`arr[arr.length - 1]`) | `O(1)` | |
| `unshift` / `shift` (начало массива) | **`O(N)`** | сдвигает все элементы! |
| Очередь на двух указателях | `O(1)` | см. ниже |
| Проход monotonic stack по массиву | `O(N)` | каждый элемент входит/выходит один раз |

### ⚠️ Главная JS-ловушка: `shift()` — это `O(N)`

Наивная очередь `queue.push(x)` + `queue.shift()` выглядит правильно, но `shift()` физически
сдвигает все оставшиеся элементы влево → `O(N)` на операцию, `O(N²)` на весь обход.
На маленьких входах незаметно, на интервью — замечание от интервьюера.

**Правильная очередь на массиве с указателем головы:**

```js
class Queue {
  constructor() {
    this.items = [];
    this.head = 0;              // индекс головы вместо физического удаления
  }
  enqueue(x) { this.items.push(x); }
  dequeue() {
    if (this.isEmpty()) return undefined;
    const item = this.items[this.head];
    this.items[this.head] = undefined;   // помогаем сборщику мусора
    this.head++;
    return item;                          // O(1)
  }
  peek()    { return this.items[this.head]; }
  isEmpty() { return this.head >= this.items.length; }
  get size() { return this.items.length - this.head; }
}
```

> 💬 На интервью говори так: _«для стека беру массив с push/pop — это O(1). Для очереди shift()
> дал бы O(N), поэтому держу указатель на голову»_. Одна эта фраза выделяет тебя из потока.
>
> Если реализация очереди не в фокусе задачи (например, BFS по дереву на 100 узлов) — можно
> использовать `shift()`, но **проговорить**, что знаешь про его стоимость.

## 📝 Эталонный разбор

### Задача: Valid Parentheses
Дана строка `s` из символов `()[]{}`. Определи, правильно ли расставлены скобки.
Правильно = каждая открывающая закрыта скобкой **того же типа** и в **правильном порядке**.

```
"()"       → true
"()[]{}"   → true
"(]"       → false
"([)]"     → false
"{[]}"     → true
```

### Ход мысли (UMPIRE)

**Understand:** вход — строка, выход — boolean. Edge cases: пустая строка (`true`), строка
нечётной длины (всегда `false`), только закрывающие `")))"`.

**Match:** «вложенность, парность, последний открытый» → **Stack**.

**Почему не счётчик?** Для одного типа скобок хватило бы счётчика `+1/-1`. Но с тремя типами
счётчики не ловят `([)]`: по количествам всё сходится, а порядок нарушен. Нужно помнить
**какая именно** скобка была открыта последней — это и есть стек.

**Plan:**
1. Идти по символам.
2. Открывающая → `push` в стек.
3. Закрывающая → стек пуст? `false`. Иначе `pop` и сравнить с ожидаемой парой.
4. В конце стек должен быть **пуст** (иначе остались незакрытые).

### Решение
```js
function isValid(s) {
  const pairs = { ')': '(', ']': '[', '}': '{' };   // закрывающая → её открывающая
  const stack = [];

  for (const char of s) {
    if (char === '(' || char === '[' || char === '{') {
      stack.push(char);
    } else {
      if (stack.pop() !== pairs[char]) return false;   // pop() у пустого стека даёт undefined
    }
  }

  return stack.length === 0;    // остались незакрытые?
}
```

### Трассировка `"{[]}"`

| символ | действие | стек после |
|:---:|---|---|
| `{` | push | `['{']` |
| `[` | push | `['{', '[']` |
| `]` | pop → `'['`, ожидали `'['` ✅ | `['{']` |
| `}` | pop → `'{'`, ожидали `'{'` ✅ | `[]` |

Стек пуст → `true` ✅

Трассировка `"([)]"`: push `(`, push `[`, встречаем `)` → `pop()` даёт `'['`, а ожидали `'('`
→ `false` ✅ — вот где счётчик бы ошибся.

**Почему `stack.pop() !== pairs[char]` покрывает и пустой стек:** `pop()` на пустом массиве
возвращает `undefined`, что не равно ни одной открывающей скобке → корректно вернём `false`
для строки вроде `")("`.

**Сложность:** время `O(N)`, память `O(N)` — в худшем случае (`"((((("`) стек хранит всю строку.

## ⚠️ Частые ошибки / чек-лист

- ❌ **Забыть финальную проверку `stack.length === 0`.** Строка `"((("` пройдёт цикл без ошибок
  и вернёт `true`, если просто `return true` в конце.
- ❌ **`shift()` для очереди** — `O(N)`. Помни про указатель головы.
- ❌ **Сравнивать количество, а не порядок** — ломается на `([)]`.
- ❌ **`pop()` без проверки на пустоту** там, где `undefined` не отличим от валидного значения
  (например, если в стеке лежат числа и `0` — валидное). В скобках это безопасно, в других
  задачах — проверяй `stack.length` явно.
- ❌ **Класть в стек не то.** Часто удобнее хранить **индексы**, а не значения (Daily
  Temperatures, Next Greater Element) — тогда можно вычислить расстояние.
- ❌ Путать `peek` (посмотреть) и `pop` (взять и удалить) — в monotonic stack это разные шаги.
- ✅ Проверяй на пустом входе и на входе только из закрывающих символов.

## ✅ Мини-опрос для самопроверки

1. Почему для трёх типов скобок не хватает счётчиков и нужен именно стек?
2. Чему равна сложность `arr.shift()` и как сделать очередь с `O(1)` извлечением?
3. Что вернёт `[].pop()` и почему это безопасно в задаче Valid Parentheses?
4. Что такое monotonic stack и почему обход остаётся `O(N)`, хотя внутри есть `while`?
5. Зачем в задачах про «следующий больший элемент» в стек кладут **индексы**, а не значения?
6. Какой обход дерева использует стек, а какой — очередь?

<details>
<summary>Ответы</summary>

1. Счётчики хранят только **количество** открытых скобок каждого типа, но не **порядок**
   вложенности. Строка `([)]` имеет верные количества, но неверный порядок. Стек хранит
   последовательность и позволяет проверить, что закрывается именно последняя открытая.
2. `shift()` — `O(N)`: он физически сдвигает все элементы влево. Очередь с `O(1)` — массив плюс
   индекс головы (`this.head++` вместо удаления), либо связный список с указателями на голову и
   хвост.
3. `undefined`. Это безопасно, потому что `undefined` не равен ни одной открывающей скобке,
   значит условие `stack.pop() !== pairs[char]` корректно вернёт `false` для лишней закрывающей.
4. Стек, в котором значения поддерживаются монотонными (только убывают или только растут);
   нарушители выталкиваются, и в момент выталкивания для них известен ответ. Обход `O(N)`, потому
   что каждый элемент кладётся и вынимается **ровно один раз** — суммарно `2N` операций,
   независимо от вложенного `while` (амортизированный анализ).
5. По индексу можно восстановить и значение (`arr[i]`), и **расстояние** (`i - stack.top()`),
   которое обычно и является ответом. Из значения индекс не восстановишь.
6. DFS (в глубину) — стек, явный или через рекурсию. BFS (по уровням) — очередь.

</details>
