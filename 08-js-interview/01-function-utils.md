# JS Function Utils (debounce, throttle, curry, memoize)

## 🎯 Зачем этот раздел

Это **не алгоритмы**, а «живые» JS-задачи, которые на Frontend-секциях спрашивают не реже
классики, а часто вместо неё. Проверяют они другое: понимаешь ли ты **замыкания, `this`,
таймеры и промисы** — то, чем ты пользуешься каждый день, но редко пишешь руками.

Формат вопроса обычно звучит так: _«реализуйте debounce»_, _«напишите функцию, ограничивающую
частоту вызовов»_, _«сделайте мемоизацию произвольной функции»_.

> 💬 Отличие от алгоритмических задач: здесь почти нет «сложности `O(N)`», зато есть **детали
> реализации**, которые отличают junior от senior: сохранение `this`, передача аргументов,
> возврат значения, метод `cancel`, edge cases с таймерами.

---

## 🧠 Три кита, на которых всё держится

### 1. Замыкание (closure)
Функция «помнит» переменные из области, где была создана. Именно так хранится `timeoutId`,
кеш, счётчик — **между** вызовами.

```js
function counter() {
  let count = 0;                 // живёт между вызовами
  return () => ++count;
}
const next = counter();
next(); // 1
next(); // 2
```

### 2. `this` и передача контекста
Если утилиту навесят на метод объекта, `this` обязан сохраниться. Поэтому:

```js
function wrap(fn) {
  return function (...args) {       // ОБЫЧНАЯ функция, не стрелочная!
    return fn.apply(this, args);    // this и аргументы прокидываются насквозь
  };
}
```

> ⚠️ Стрелочная функция **не имеет своего `this`** — она возьмёт его из места объявления.
> Для обёрток это ошибка: `obj.method()` потеряет `obj`. Помни правило: **обёртка — обычная
> функция, внутренние колбэки — стрелочные** (чтобы унаследовать уже захваченный `this`).

### 3. Таймеры
`setTimeout` возвращает идентификатор, `clearTimeout(id)` его отменяет. На этом построены и
debounce, и throttle.

```js
const id = setTimeout(fn, 300);
clearTimeout(id);                 // отменили
```

## 📝 Эталонный разбор: debounce

**Что делает.** Откладывает вызов функции до тех пор, пока не пройдёт `delay` миллисекунд
**без новых вызовов**. Каждый новый вызов «сбрасывает таймер».

**Где применяется.** Поиск при вводе (не дёргать API на каждую букву), автосохранение,
валидация формы, `resize`.

```
вызовы:   | | |     |        |
таймер:   ...сброс...      ▓▓▓▓▓ → выполнение
```

### Решение
```js
function debounce(fn, delay) {
  let timeoutId = null;                    // живёт в замыкании между вызовами

  return function (...args) {              // обычная функция — сохраняем this
    clearTimeout(timeoutId);               // отменяем предыдущий отложенный вызов

    timeoutId = setTimeout(() => {
      fn.apply(this, args);                // стрелочная — берёт this из обёртки
    }, delay);
  };
}
```

**Разбор по строкам:**

| Строка | Зачем |
|---|---|
| `let timeoutId = null` | состояние между вызовами — это и есть замыкание |
| `function (...args)` | обычная функция, чтобы `this` пришёл от места вызова |
| `clearTimeout(timeoutId)` | отменяем прошлый таймер; на `null` работает без ошибок |
| `() => fn.apply(this, args)` | стрелка наследует `this` обёртки; `args` захвачены замыканием |

**Использование:**
```js
const search = debounce((query) => fetchResults(query), 300);
input.addEventListener('input', (e) => search(e.target.value));
```

**Расширения, о которых спросят следом:**
- `cancel()` — отменить запланированный вызов;
- `immediate` / leading edge — выполнить **сразу**, а потом игнорировать `delay`;
- возврат промиса с результатом.

Всё это разобрано в задаче [`01-debounce`](../practice/08-js-interview/01-function-utils/01-debounce.md).

## 🔁 Debounce vs Throttle — главное различие

| | debounce | throttle |
|---|---|---|
| Смысл | «выполнить, когда **перестали** дёргать» | «выполнять **не чаще**, чем раз в N мс» |
| При непрерывном потоке событий | выполнится **один раз в конце** | выполнится **регулярно** |
| Типичное применение | поиск, автосохранение, валидация | scroll, mousemove, resize, отправка аналитики |

```
события:  ● ● ● ● ● ● ● ● ● ●   (непрерывно, 1 сек)
debounce:                     ✔   (один раз, после паузы)
throttle: ✔     ✔     ✔     ✔    (равномерно, раз в N мс)
```

Путать их — самая частая ошибка на интервью. Если тебя просят «не дёргать сервер на каждую
букву» — это **debounce**. Если «обновлять позицию при скролле, но не 60 раз в секунду» —
**throttle**.

## ⚠️ Частые ошибки / чек-лист

- ❌ **Стрелочная функция как обёртка** — теряется `this`. Обёртка всегда `function`.
- ❌ **`fn(...args)` вместо `fn.apply(this, args)`** — работает, пока функцию не используют как
  метод объекта. Интервьюер проверит именно этот случай.
- ❌ **Забыть `clearTimeout`** в debounce — получится не debounce, а «выполнить всё с задержкой».
- ❌ **Хранить состояние вне замыкания** (в глобальной переменной) — две обёртки начнут мешать
  друг другу. Проверка: `const a = debounce(f, 100); const b = debounce(g, 100);` должны быть
  независимы.
- ❌ **Не вернуть значение** из мемоизированной/каррированной функции.
- ❌ **Использовать объект вместо `Map` для кеша** — ключи приводятся к строкам, ломаются
  ключи-объекты и есть риск коллизии с прототипом (`__proto__`, `constructor`).
- ✅ Всегда проговаривай, что обёртка **прозрачна**: принимает любые аргументы, сохраняет `this`,
  возвращает результат.

## ✅ Мини-опрос для самопроверки

1. В чём разница между debounce и throttle? Приведи по одному применению каждого.
2. Почему обёртка объявляется как `function`, а внутренний колбэк — стрелкой?
3. Что произойдёт, если в debounce забыть `clearTimeout`?
4. Где хранится `timeoutId` между вызовами и как это называется?
5. Почему для кеша в `memoize` лучше `Map`, чем обычный объект?
6. Как сделать так, чтобы debounce выполнял функцию **сразу**, а потом молчал `delay` мс?

<details>
<summary>Ответы</summary>

1. Debounce откладывает вызов до паузы в потоке событий и выполняет функцию **один раз** после
   неё (поиск при вводе). Throttle пропускает вызовы **не чаще раза в N мс**, выполняя их
   регулярно во время потока (обработка `scroll`).
2. Обёртка должна получить `this` от места вызова (`obj.method()`), а у стрелочной функции
   своего `this` нет. Внутренний колбэк, наоборот, должен **унаследовать** уже захваченный
   `this` обёртки — для этого стрелка идеальна.
3. Функция выполнится столько раз, сколько было вызовов, просто каждый — с задержкой `delay`.
   Это не debounce, а «отложенное выполнение всего подряд».
4. В **замыкании** возвращаемой функции: переменная объявлена в `debounce`, а используется во
   вложенной функции, поэтому живёт между вызовами и своя у каждой созданной обёртки.
5. `Map` принимает **любые** ключи, включая объекты, не приводит их к строкам и не пересекается
   с прототипом (`__proto__`, `toString`). У объекта ключ `1` и `'1'` схлопнутся, а имена вроде
   `constructor` могут дать ложное попадание в кеш.
6. Это режим **leading edge**: держать флаг «таймер не запущен» — если он не запущен, выполнить
   сразу и запустить таймер; последующие вызовы в течение `delay` игнорировать. Реализация — в
   задаче [`01-debounce`](../practice/08-js-interview/01-function-utils/01-debounce.md).

</details>
