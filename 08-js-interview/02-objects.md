# JS: объекты и структуры (deep clone, EventEmitter)

## 🎯 Зачем эта тема

Здесь проверяют две вещи: понимание **ссылочной модели JS** (что копируется, а что — нет)
и умение **спроектировать небольшую структуру** с осмысленным выбором коллекций.

Типичные формулировки: _«напишите deepClone»_, _«реализуйте EventEmitter»_, _«почему здесь Map,
а не обычный объект?»_.

## 🧠 Ключевые идеи

### 1. Ссылки vs значения
Примитивы копируются по значению, объекты и массивы — **по ссылке**.

```js
const a = { x: { y: 1 } };
const shallow = { ...a };        // ПОВЕРХНОСТНАЯ копия
shallow.x.y = 42;
a.x.y;                            // 42 — вложенный объект общий!
```

Отсюда задача глубокого копирования: обойти структуру рекурсивно и создать новые объекты
на каждом уровне.

### 2. Почему `JSON.parse(JSON.stringify(obj))` — плохой ответ

Это первое, что приходит в голову, и на интервью его ждут — но ждут вместе с перечислением
проблем:

| Теряется / ломается | Что происходит |
|---|---|
| `undefined`, функции, `Symbol` | молча **исчезают** из объекта (в массиве → `null`) |
| `Date` | превращается в **строку** |
| `Map`, `Set`, `RegExp` | становятся пустым объектом `{}` |
| `NaN`, `Infinity` | становятся `null` |
| **Циклические ссылки** | выбрасывает `TypeError: Converting circular structure to JSON` |
| Прототипы, геттеры | теряются |

> 💡 Современная альтернатива — `structuredClone(obj)` (есть в браузерах и Node 17+): умеет
> циклы, `Date`, `Map`, `Set`, но **не копирует функции** и выбрасывает ошибку на них.
> Назвать его — хороший ход, но реализацию всё равно попросят написать руками.

### 3. Циклические ссылки решаются `Map`
Тот же приём, что в [Clone Graph](../practice/06-graphs/01-graph-traversal/03-clone-graph.md):
храним соответствие «оригинал → копия» и при повторной встрече возвращаем готовую копию.

```js
if (seen.has(value)) return seen.get(value);   // обрыв цикла
seen.set(value, copy);                          // ЗАПИСЬ ДО обхода потомков
```

### 4. `Map`/`Set` вместо объекта и массива

Когда проектируешь хранилище, выбор коллекции — это то, что спрашивают в первую очередь:

| | Объект / массив | `Map` / `Set` |
|---|---|---|
| Ключи | только строки и символы | **любые**, включая объекты |
| Коллизии с прототипом | `__proto__`, `constructor` | нет |
| Удаление элемента | у массива `O(N)` | `O(1)` |
| Порядок вставки | частично (числовые ключи вперёд) | гарантирован |
| Слабые ссылки (GC) | нет | `WeakMap` / `WeakSet` |

Отсюда стандартный ответ в задачах на дизайн: хранилище — `Map`, множество подписчиков/
посещённых — `Set`, кеш с объектными ключами — `WeakMap`.

## 📝 Эталонный разбор: EventEmitter

Классическая задача «спроектируйте структуру». Нужен объект с методами `on`, `off`, `emit`,
`once`.

```js
class EventEmitter {
  constructor() {
    this.listeners = new Map();          // событие → Set обработчиков
  }

  on(event, handler) {
    if (!this.listeners.has(event)) this.listeners.set(event, new Set());
    this.listeners.get(event).add(handler);

    return () => this.off(event, handler);     // удобство: функция отписки
  }

  off(event, handler) {
    this.listeners.get(event)?.delete(handler);
  }

  once(event, handler) {
    const wrapper = (...args) => {
      this.off(event, wrapper);          // сначала отписываемся
      handler(...args);                   // потом вызываем
    };
    return this.on(event, wrapper);
  }

  emit(event, ...args) {
    const handlers = this.listeners.get(event);
    if (!handlers) return false;

    for (const handler of [...handlers]) {     // КОПИЯ: обработчик может отписаться
      handler(...args);
    }

    return true;
  }
}
```

**Три решения, которые нужно уметь объяснить:**

1. **`Map` + `Set`, а не объект + массив.** `Set` даёт `O(1)` удаление и автоматически
   защищает от двойной подписки одним и тем же обработчиком. `Map` разрешает любые ключи и не
   конфликтует с прототипом.
2. **`[...handlers]` в `emit`.** Обработчик может отписаться (или подписаться) прямо во время
   вызова — итерация по живой коллекции даст непредсказуемый результат. Копия делает обход
   безопасным. **Это главный подводный камень задачи**, и его специально проверяют через
   `once`.
3. **`once` через обёртку**: отписка **до** вызова `handler`, иначе рекурсивный `emit` внутри
   обработчика вызовет его повторно.

**Возврат функции отписки** из `on` — не требование, но приятная деталь: так делают
современные библиотеки (и React-хуки), и это показывает насмотренность.

**Сложность:** `on` / `off` / `emit`(на один обработчик) — `O(1)`; `emit` целиком — `O(K)`, где
`K` — число подписчиков.

## ⚠️ Частые ошибки / чек-лист

- ❌ **Отвечать `JSON.parse(JSON.stringify())` без оговорок** — назови ограничения сам, не
  дожидаясь вопроса.
- ❌ **Не обработать циклические ссылки** в deep clone → бесконечная рекурсия.
- ❌ **Записывать копию в `Map` после обхода потомков** — цикл не разорвётся.
- ❌ **Забыть, что `typeof null === 'object'`** → `null` уйдёт в ветку копирования объекта и
  упадёт. Проверка: `if (value === null || typeof value !== 'object') return value;`
- ❌ **Итерировать живой `Set` в `emit`**, пока обработчики отписываются.
- ❌ **Брать обычный объект под хранилище с произвольными ключами** — ключи приведутся к строкам,
  а `constructor` и `__proto__` дадут ложные попадания.
- ❌ **Забыть о чистке подписок** — подписки держат ссылки на замыкания и DOM → утечка памяти.
- ✅ Всегда уточняй: «нужно ли копировать функции / `Date` / `Map`?», «можно ли мутировать
  входной объект?».

## ✅ Мини-опрос для самопроверки

1. Назови пять вещей, которые ломает `JSON.parse(JSON.stringify(obj))`.
2. Как deep clone обрабатывает циклические ссылки и почему порядок записи в `Map` важен?
3. Почему `typeof null === 'object'` опасен в рекурсивном копировании?
4. Зачем в `emit` итерировать по копии коллекции обработчиков?
5. Почему для хранилища подписчиков выбраны `Map` и `Set`, а не объект и массив?
6. Когда нужен `WeakMap` вместо `Map`?

<details>
<summary>Ответы</summary>

1. `undefined`/функции/`Symbol` (исчезают), `Date` (становится строкой), `Map`/`Set`/`RegExp`
   (становятся `{}`), `NaN`/`Infinity` (становятся `null`), циклические ссылки (выбрасывает
   `TypeError`). Плюс теряются прототипы и геттеры.
2. Через `Map` «оригинал → копия»: при повторной встрече объекта возвращаем уже созданную копию.
   Записывать копию нужно **до** рекурсивного обхода полей — иначе рекурсия вернётся в текущий
   объект, не найдёт его в `Map` и уйдёт в бесконечный цикл.
3. Потому что проверка `typeof value === 'object'` пропустит `null` в ветку «копируем объект»,
   и `Object.entries(null)` выбросит ошибку. Нужно явно проверять `value === null` первым.
4. Обработчик во время вызова может отписаться или подписать новый (например, так работает
   `once`). Изменение коллекции во время итерации даёт непредсказуемое поведение; копия
   фиксирует список подписчиков на момент события.
5. `Set` даёт `O(1)` удаление (у массива — `O(N)`) и защищает от двойной подписки одного и того
   же обработчика. `Map` принимает любые ключи и не конфликтует с прототипом: у объекта
   событие с именем `constructor` или `__proto__` дало бы ложное попадание.
6. Когда ключи — **объекты** и кеш не должен мешать сборщику мусора. `WeakMap` держит ключи
   слабо: как только на объект больше никто не ссылается, запись удаляется автоматически.
   Цена — нельзя перебрать содержимое и узнать размер.

</details>
