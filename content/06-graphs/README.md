# Графы

Графы обобщают знакомые списки, деревья и сетки: теперь у объекта может быть несколько соседей, а пути могут сходиться и возвращаться назад. Выдели 5–10 минут на обзор. Главная подготовительная работа — правильно определить вершины, рёбра и смысл перехода, а не сразу писать обход.

## Общая идея

**Graph** состоит из vertices — вершин, и edges — связей между ними. Вершинами могут быть города, задачи, клетки поля или состояния программы. Ребро означает конкретное допустимое отношение: переход, зависимость, соседство. Значение этого отношения определяет алгоритм.

У **directed graph** ребро `A → B` разрешает направление от `A` к `B`; обратное ребро не появляется автоматически. У **undirected graph** связь двусторонняя. **Cycle** — путь, возвращающийся в исходную вершину; для directed graph при этом нужно соблюдать направления рёбер.

Граф не обязан быть связным: из выбранной стартовой вершины может быть достижима только часть данных. Для обхода всего графа приходится учитывать остальные вершины. В directed graph достижимость также несимметрична: возможность попасть из `A` в `B` не доказывает возможность вернуться.

Обычное неориентированное Tree — частный случай графа: связный и без циклов. Выбор root добавляет удобную иерархию parent/children. У произвольного графа естественного root может не быть, но старт обхода выбрать можно. Даже в undirected tree при хранении двусторонних рёбер нужно не ходить бесконечно между parent и child.

Два базовых порядка обхода уже знакомы:

- **DFS** исследует одну ветку через Stack или рекурсию.
- **BFS** расширяет область поиска по слоям через Queue.

В графе дополнительно важно хранить факт посещения: одна вершина может встречаться по нескольким путям. Однако «вершина уже посещалась» само по себе не доказывает цикл в directed graph: две независимые ветки могут просто прийти в одну вершину. Для проверки циклов нужно более точное состояние или другой алгоритм.

**Topological Sort** решает не задачу «кого посетить дальше», а задачу «в каком порядке выполнить зависимости». При соглашении `A → B` означает «A должно быть раньше B» нужен порядок, соблюдающий все такие рёбра. Он существует только для directed acyclic graph — DAG; правильных порядков может быть несколько.

## Где это встречается

Зависимости задач, переходы между состояниями и связи объектов естественно задаются графами. Для зависимостей модулей важно уточнить модель: наличие связи между файлами ещё не значит, что любой цикл в реальной системе запрещён. В задаче на Topological Sort требуется именно порядок «сначала все prerequisites».

Grid — **implicit graph**: вершина задаётся координатами, а соседей можно вычислять, не создавая отдельный список всех рёбер. Условие должно определить четыре или восемь направлений, препятствия и допустимые переходы. Геометрическая близость клеток сама по себе не делает переход разрешённым.

BFS находит минимальное число рёбер от старта в невзвешенном графе, а также минимальную стоимость при одинаковом положительном весе всех рёбер. При разных весах это обещание пропадает. DFS подходит для исследования достижимости, но первый найденный им путь не обязан быть кратчайшим.

С adjacency list полный обход требует `O(V + E)` времени и `O(V)` дополнительной памяти, где `V` — число вершин, `E` — число рёбер. Сам adjacency list занимает `O(V + E)` памяти. Эти оценки предполагают, что вершины не обрабатываются повторно и перечисление соседей соответствует числу рёбер. Для adjacency matrix просмотр всех потенциальных соседей даёт `O(V²)` времени, `O(V)` дополнительной памяти обхода и `O(V²)` памяти представления.

## Маршрут изучения

1. [Graph Traversal (BFS / DFS)](01-graph-traversal.md). Научись задавать соседей, учитывать повторные пути, обходить компоненты и видеть implicit graph в сетке.
2. [Topological Sort](02-topological-sort.md). Перейди от достижимости к зависимостям: разбери входящие рёбра, доступные к обработке вершины и обнаружение невозможного порядка.

Queue в алгоритме Kahn не делает Topological Sort обычным BFS кратчайших путей. Здесь вершина становится доступной после выполнения prerequisites, а не просто после посещения одного соседа.

## Что получится после раздела

Ты сможешь превратить условие в графовую модель и объяснить назначение обхода.

Проверь себя:

- Что обозначают вершина и ребро именно в этой задаче?
- Направлены ли рёбра и возможны ли недостижимые из старта вершины?
- Почему для кратчайшего пути допустим BFS?
- Нужна достижимость или порядок зависимостей?
- Учитываются ли представление графа, `visited`, Stack или Queue в памяти?
