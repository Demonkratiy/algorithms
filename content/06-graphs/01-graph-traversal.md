# Graph Traversal (обход графов: BFS / DFS)

## 🎯 Идея

**Граф** — узлы (вершины) и связи между ними (рёбра). В отличие от дерева, у графа **нет корня**,
связи могут идти в любую сторону и образовывать **циклы**. Поэтому появляется одна новая
сущность, которой не было в деревьях:

> **`visited`** — множество уже посещённых узлов. Без него обход зациклится навсегда.

Это единственное принципиальное отличие обхода графа от обхода дерева. Всё остальное — тот же
DFS (рекурсия/стек) и BFS (очередь), которые ты уже знаешь.

---

## 🧠 Как распознать (ментальная модель)

Признаки в условии:
- «связи», «соседи», «сеть», «зависимости», «маршрут», «компоненты»;
- **двумерная сетка** (`grid`) — это тоже граф! Каждая клетка — узел, соседи — 4 (или 8) клеток;
- «сколько островов / регионов / групп» → подсчёт **компонент связности**;
- «минимальное число шагов / кратчайший путь» в невзвешенном графе → **BFS**;
- «есть ли путь», «обойти всё» → **DFS** (проще писать).

### Три способа задать граф

```js
// 1. Список смежности (adjacency list) — самый частый на интервью
const graph = { a: ['b', 'c'], b: ['d'], c: [], d: [] };
const graphMap = new Map([[0, [1, 2]], [1, [3]], [2, []], [3, []]]);

// 2. Матрица смежности — редко, O(V²) памяти
const matrix = [[0, 1, 1], [0, 0, 1], [0, 0, 0]];

// 3. Неявный граф — сетка, где соседи вычисляются по координатам
const grid = [['1', '1', '0'], ['0', '1', '0']];
```

### Список рёбер → список смежности

Часто на вход дают `edges = [[0,1], [1,2]]`, и первое, что нужно сделать, — построить смежность:

```js
function buildGraph(n, edges, directed = false) {
  const graph = Array.from({ length: n }, () => []);   // НЕ new Array(n).fill([]) !
  for (const [from, to] of edges) {
    graph[from].push(to);
    if (!directed) graph[to].push(from);               // неориентированный — обе стороны
  }
  return graph;
}
```

> ⚠️ `new Array(n).fill([])` создаст `n` ссылок на **один и тот же** массив — классическая
> ошибка. Нужен `Array.from({ length: n }, () => [])`.

## ⏱️ Сложность

| | Время | Память |
|---|:---:|:---:|
| DFS / BFS по списку смежности | `O(V + E)` | `O(V)` |
| DFS / BFS по сетке `m × n` | `O(m · n)` | `O(m · n)` |
| DFS рекурсивно | | + `O(V)` на стек в худшем случае |

`V` — число вершин, `E` — число рёбер. Каждая вершина посещается один раз, каждое ребро
рассматривается один (для ориентированного) или два раза.

> ⚠️ Не говори «`O(N)`» — в графах два измерения. Правильный ответ: **`O(V + E)`**.
> Для сетки — `O(m · n)`, где каждая клетка обрабатывается один раз.

## 📝 Эталонный разбор

### Задача: Number of Islands
Дана сетка `grid` из `'1'` (земля) и `'0'` (вода). Остров — группа соседних по горизонтали и
вертикали клеток земли. Посчитать количество островов.

```
[['1','1','0','0'],
 ['1','1','0','0'],      → 3 острова
 ['0','0','1','0'],
 ['0','0','0','1']]
```

### Ход мысли (UMPIRE)

**Understand:** вход — матрица символов, выход — число. Соседство только по 4 направлениям
(не по диагонали — уточни на интервью!).

**Match:** «сколько групп связанных клеток» → **подсчёт компонент связности** → обход графа.

**Plan:**
1. Идём по всем клеткам.
2. Встретили непосещённую землю → это **новый остров**, `count++`.
3. Запускаем обход (DFS или BFS), который «топит» весь остров целиком, помечая клетки
   посещёнными.
4. Продолжаем перебор — уже помеченные клетки пропускаются.

**Ключевая мысль:** внешний цикл ищет **новые компоненты**, внутренний обход **поглощает**
компоненту целиком. Это универсальный каркас для всех задач «сколько групп».

### Решение (DFS)
```js
function numIslands(grid) {
  if (grid.length === 0) return 0;

  const rows = grid.length;
  const cols = grid[0].length;
  let count = 0;

  function sink(r, c) {
    // одна проверка границ и «стоп-условий» на входе — вместо четырёх перед вызовами
    if (r < 0 || r >= rows || c < 0 || c >= cols) return;
    if (grid[r][c] !== '1') return;                 // вода или уже посещено

    grid[r][c] = '0';                               // помечаем как посещённое

    sink(r + 1, c);
    sink(r - 1, c);
    sink(r, c + 1);
    sink(r, c - 1);
  }

  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (grid[r][c] === '1') {
        count++;                                    // нашли новый остров
        sink(r, c);                                 // и целиком его погасили
      }
    }
  }

  return count;
}
```

**Приём «проверка на входе».** Границы и условие «уже посещено» проверяются **внутри** функции,
а не перед каждым из четырёх вызовов. Кода в 4 раза меньше, ошибиться негде.

**Про `visited`.** Здесь мы модифицируем сам `grid` — это `O(1)` дополнительной памяти вместо
отдельного `Set`. Если вход портить нельзя, заводим `visited`:
```js
const visited = new Set();
const key = `${r},${c}`;              // строковый ключ: Set сравнивает объекты по ссылке
```

**Сложность:** время `O(m · n)` — каждая клетка посещается не более одного раза
(после пометки она больше не пройдёт проверку). Память `O(m · n)` в худшем случае — глубина
рекурсии на сетке, целиком состоящей из земли.

### То же самое через BFS
```js
function numIslandsBFS(grid) {
  const rows = grid.length;
  const cols = grid[0].length;
  const directions = [[1, 0], [-1, 0], [0, 1], [0, -1]];
  let count = 0;

  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (grid[r][c] !== '1') continue;

      count++;
      const queue = [[r, c]];
      grid[r][c] = '0';                    // помечаем СРАЗУ при добавлении в очередь

      for (let head = 0; head < queue.length; head++) {
        const [cr, cc] = queue[head];
        for (const [dr, dc] of directions) {
          const nr = cr + dr;
          const nc = cc + dc;
          if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
          if (grid[nr][nc] !== '1') continue;

          grid[nr][nc] = '0';
          queue.push([nr, nc]);
        }
      }
    }
  }

  return count;
}
```

**Массив `directions`** — стандартный приём: вместо четырёх одинаковых блоков кода один цикл.
Для 8 направлений (с диагоналями) достаточно дописать четыре пары.

> ⚠️ **Помечать узел нужно в момент добавления в очередь**, а не когда достаём. Иначе одна и та
> же клетка попадёт в очередь несколько раз (её добавят разные соседи) — и алгоритм из `O(V+E)`
> может выродиться. Это самая частая ошибка в BFS по графам.

## ⚠️ Частые ошибки / чек-лист

- ❌ **Забыть `visited`** → бесконечный цикл (в графе с циклами) или экспоненциальный обход.
- ❌ **Помечать при извлечении из очереди, а не при добавлении** — дубликаты в очереди.
- ❌ **`new Array(n).fill([])`** — все элементы ссылаются на один массив.
- ❌ **Проверять границы перед вызовом**, а не внутри функции — вчетверо больше кода и ошибок.
- ❌ **`Set` с координатами-массивами**: `set.has([r, c])` всегда `false`, объекты сравниваются
  по ссылке. Используй строковый ключ `` `${r},${c}` `` или `r * cols + c`.
- ❌ **Считать сложность как `O(N)`** — правильно `O(V + E)` или `O(m · n)`.
- ❌ **Использовать DFS для кратчайшего пути** — он найдёт какой-то путь, но не обязательно
  минимальный. Для кратчайшего в невзвешенном графе нужен **BFS**.
- ✅ Уточняй у интервьюера: соседство по 4 или по 8? Граф ориентированный? Связный?

## 🧭 DFS или BFS: как выбрать

| Нужно | Берём | Почему |
|---|---|---|
| «Есть ли путь», «обойти всё», «сколько компонент» | **DFS** | короче код, рекурсия |
| «Минимальное число шагов», «кратчайший путь» | **BFS** | обходит по слоям — первый найденный путь минимален |
| «За сколько минут всё заразится/распространится» | **BFS multi-source** | стартуем со всех источников сразу |
| Глубокий граф, риск переполнения стека | **BFS** или DFS со стеком | нет рекурсии |

**Multi-source BFS** — важный приём: в очередь кладут **сразу все** стартовые узлы, и волна идёт
от них одновременно. Так решается «Rotting Oranges» и «расстояние до ближайшего нуля».

## ✅ Мини-опрос для самопроверки

1. Чем обход графа принципиально отличается от обхода дерева?
2. Почему в BFS узел помечают посещённым при добавлении в очередь, а не при извлечении?
3. Какая сложность у обхода графа и почему её нельзя записать как `O(N)`?
4. Почему `visited.has([r, c])` не работает и как правильно?
5. Когда обязателен BFS и DFS не подойдёт?
6. Что такое multi-source BFS и какую задачу он решает?

<details>
<summary>Ответы</summary>

1. В графе есть **циклы** и несколько путей к одному узлу, поэтому нужен `visited`. В дереве
   каждый узел достижим ровно одним путём, и множество посещённых не требуется.
2. Иначе один и тот же узел успеет попасть в очередь несколько раз (его добавят разные соседи,
   пока он ждёт извлечения). Появятся дубликаты работы, а на плотном графе — заметная деградация.
3. `O(V + E)`: каждая вершина обрабатывается один раз, каждое ребро просматривается один-два
   раза. Одно число `N` не описывает граф — вершин и рёбер может быть очень разное количество
   (у разреженного `E ≈ V`, у плотного `E ≈ V²`). Для сетки — `O(m · n)`.
4. `Set` и `Map` сравнивают объекты **по ссылке**, а `[r, c]` каждый раз новый массив. Нужен
   примитивный ключ: строка `` `${r},${c}` `` или число `r * cols + c`.
5. Когда нужен **кратчайший** путь / минимальное число шагов в невзвешенном графе. BFS
   гарантирует, что первый раз узел достигается по кратчайшему пути; DFS может прийти к нему
   длинной дорогой.
6. Это BFS, в очередь которого до начала обхода кладут **все** стартовые узлы. Волна идёт от
   всех источников одновременно, поэтому каждый узел получает расстояние до **ближайшего** из
   них. Решает задачи вида «за сколько минут сгниют все апельсины», «расстояние до ближайшего
   нуля/выхода».

</details>
