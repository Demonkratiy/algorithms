# Topological Sort (топологическая сортировка)

## 🎯 Идея

**Топологическая сортировка** — упорядочивание вершин ориентированного графа так, что каждое
ребро `a → b` идёт «слева направо»: `a` встречается в порядке **раньше**, чем `b`.

Практический смысл — **порядок выполнения задач с зависимостями**:

```
"чтобы пройти курс C, нужно сначала пройти A и B"
A → C
B → C
C → D

валидный порядок: A, B, C, D
```

Существует топологический порядок **тогда и только тогда, когда в графе нет циклов**. Поэтому
одна и та же техника решает две задачи: «в каком порядке» и **«есть ли цикл»**.

> 💡 Для фронтендера это не абстракция: разрешение зависимостей модулей (`import`), порядок
> сборки в бандлере, очередь миграций, вычисление зависимых значений — всё это топологическая
> сортировка.

---

## 🧠 Как распознать

Маркеры в условии:
- «**зависимости**», «сначала нужно…», «prerequisites», «порядок выполнения»;
- «можно ли завершить все задачи/курсы» → на самом деле вопрос **«нет ли цикла»**;
- «порядок сборки», «расписание», «последовательность установки».

Граф **обязательно ориентированный**. Если он неориентированный — это не про топологическую
сортировку.

## 📝 Алгоритм Кана (BFS) — рекомендуемый

Идея: считаем для каждой вершины **in-degree** — количество входящих рёбер (сколько
зависимостей ещё не выполнено). Вершины с `in-degree === 0` можно брать прямо сейчас.

```
1. Построить список смежности и посчитать in-degree всех вершин.
2. Положить в очередь все вершины с in-degree === 0.
3. Пока очередь не пуста:
     взять вершину, добавить в результат;
     у каждого её соседа уменьшить in-degree на 1;
     если стал 0 — положить соседа в очередь.
4. Если в результате оказались НЕ все вершины — в графе цикл.
```

```js
function topologicalSort(numNodes, edges) {
  const graph = Array.from({ length: numNodes }, () => []);
  const inDegree = new Array(numNodes).fill(0);

  for (const [from, to] of edges) {          // ребро from → to
    graph[from].push(to);
    inDegree[to]++;
  }

  const queue = [];
  for (let node = 0; node < numNodes; node++) {
    if (inDegree[node] === 0) queue.push(node);      // ничего не ждут — можно сразу
  }

  const order = [];
  for (let head = 0; head < queue.length; head++) {  // указатель головы вместо shift()
    const node = queue[head];
    order.push(node);

    for (const next of graph[node]) {
      inDegree[next]--;                              // одна зависимость закрыта
      if (inDegree[next] === 0) queue.push(next);    // все зависимости закрыты
    }
  }

  return order.length === numNodes ? order : [];     // неполный порядок ⇒ цикл
}
```

### Трассировка

```
курсы: 0 → 1, 0 → 2, 1 → 3, 2 → 3
inDegree: [0, 1, 1, 2]
```

| шаг | очередь | берём | inDegree после | order |
|:---:|---|:---:|---|---|
| 1 | `[0]` | 0 | `[0,0,0,2]` | `[0]` |
| 2 | `[0,1,2]` | 1 | `[0,0,0,1]` | `[0,1]` |
| 3 | `[0,1,2]` | 2 | `[0,0,0,0]` | `[0,1,2]` |
| 4 | `[0,1,2,3]` | 3 | — | `[0,1,2,3]` ✅ |

Длина `order` равна числу вершин → цикла нет, порядок валиден.

**Почему «не все вершины ⇒ цикл».** Вершина попадает в очередь только когда её `in-degree`
обнулился. Если вершины лежат в цикле, они взаимно держат друг у друга `in-degree > 0`, и ни
одна никогда не освободится.

## 🔁 Вариант через DFS (для полноты)

```js
function topoSortDFS(numNodes, graph) {
  const state = new Array(numNodes).fill(0);   // 0 = не был, 1 = в обработке, 2 = завершён
  const order = [];
  let hasCycle = false;

  function dfs(node) {
    if (state[node] === 1) { hasCycle = true; return; }   // вернулись в "серую" вершину — цикл!
    if (state[node] === 2) return;                        // уже полностью обработана

    state[node] = 1;                                      // красим в серый
    for (const next of graph[node]) dfs(next);
    state[node] = 2;                                      // чёрный: все потомки готовы

    order.push(node);                                     // POST-order!
  }

  for (let node = 0; node < numNodes; node++) dfs(node);

  return hasCycle ? [] : order.reverse();                 // обратный post-order
}
```

**Три цвета — ключевая идея.** Обычного `visited` (два состояния) **недостаточно**: он не
отличает «уже обработана в другой ветке» от «мы прямо сейчас внутри неё». Цикл — это возврат в
**серую** вершину, то есть в ту, что находится в текущем пути рекурсии.

**Почему `reverse()`.** Вершина добавляется в `order` **после** всех своих потомков (post-order),
значит в массиве она оказывается раньше них. Разворот ставит зависимости на правильные места.

## ⏱️ Сложность

- Время **`O(V + E)`** — каждая вершина и каждое ребро обрабатываются один раз.
- Память **`O(V + E)`** — список смежности плюс очередь/стек.

---

## ⚠️ Частые ошибки / чек-лист

- ❌ **Перепутать направление ребра.** В задачах вида «чтобы пройти `a`, нужен `b`» вход часто
  даётся как `[a, b]`, а ребро при этом идёт **`b → a`**. Всегда проговаривай направление вслух
  и проверяй на примере из двух элементов.
- ❌ **Проверять цикл через обычный `visited`** в DFS-версии — нужны три состояния.
- ❌ **Забыть финальную проверку `order.length === numNodes`** — без неё при цикле вернётся
  неполный, но внешне «валидный» ответ.
- ❌ **Уменьшать `in-degree` не тем вершинам** — уменьшается у **соседей** (тех, куда ведут
  рёбра), а не у текущей.
- ❌ **`shift()` в очереди** — `O(N)`; используй указатель головы.
- ❌ Считать, что порядок **единственный.** Обычно валидных порядков много — задачи это
  допускают («верните любой»).
- ✅ Вершины без рёбер тоже входят в ответ — не потеряй их.

## ✅ Мини-опрос для самопроверки

1. Когда топологический порядок **не существует**?
2. Что такое in-degree и почему вершины с `in-degree === 0` можно брать первыми?
3. Как алгоритм Кана обнаруживает цикл?
4. Почему в DFS-версии нужны три состояния, а не обычный `visited`?
5. Почему результат DFS-версии нужно разворачивать?
6. Дано «чтобы пройти курс `a`, надо сначала `b`», вход `[a, b]`. Какое ребро строить?

<details>
<summary>Ответы</summary>

1. Когда в графе есть **цикл**: вершины цикла взаимно зависят друг от друга, и ни одну нельзя
   поставить раньше остальных.
2. In-degree — количество входящих рёбер, то есть невыполненных зависимостей. Если он равен
   нулю, вершина ни от кого не зависит и может идти в порядок прямо сейчас.
3. По длине результата: если после работы алгоритма в `order` попали не все вершины, значит
   у оставшихся `in-degree` так и не обнулился — они держат друг друга в цикле.
4. Двух состояний мало: `visited` не различает «эта вершина уже полностью обработана в другой
   ветке» (нормально) и «мы сейчас находимся внутри её обхода» (цикл). Серый цвет помечает
   именно текущий путь рекурсии.
5. Потому что вершина добавляется в `order` **после** всех потомков (post-order), то есть
   зависимости оказываются позже зависимых. Разворот восстанавливает нужный порядок.
6. Ребро **`b → a`**: сначала `b`, потом `a`. Соответственно `graph[b].push(a)` и `inDegree[a]++`.
   Перепутанное направление даёт «работающий» код с неверным ответом — проверяй на минимальном
   примере.

</details>
