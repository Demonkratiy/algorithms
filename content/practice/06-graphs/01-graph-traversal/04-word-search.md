# Word Search (DFS + backtracking на сетке)

**Тема:** graphs / backtracking · **Сложность:** medium · **Приоритет:** ⚪ дополнительная

> Соединяет два паттерна: обход сетки и **backtracking** из
> [Subsets](../../05-recursion-trees/01-recursion/03-subsets.md). Показывает, зачем в графах
> иногда нужно **снимать** пометку посещения.

## Условие

Дана сетка `board` из символов и строка `word`. Верни `true`, если слово можно составить,
двигаясь по **соседним** клеткам (горизонталь/вертикаль).

Одну и ту же клетку **нельзя использовать дважды в одном слове**.

## Примеры

```
board = [['A','B','C','E'],
         ['S','F','C','S'],
         ['A','D','E','E']]

word = "ABCCED"  → true
word = "SEE"     → true
word = "ABCB"    → false    // 'B' пришлось бы использовать дважды
```

## Ограничения

- `1 <= m, n <= 6`, `1 <= word.length <= 15`
- буквы — латиница в верхнем/нижнем регистре.

## 🎯 Цель по сложности

- Время **`O(m · n · 3^L)`**, где `L` — длина слова: из каждой клетки есть 3 продолжения
  (назад идти нельзя), и стартовать можно из любой из `m · n` клеток.
- Память `O(L)` — глубина рекурсии.

Экспонента здесь нормальна: это перебор. Важно уметь **назвать** её и объяснить отсечения.

## 🧠 Ментальная модель

Из каждой клетки, совпавшей с текущей буквой, пробуем продолжить во все 4 стороны. Если ветка
не привела к успеху — **откатываем пометку** и пробуем другую.

```
выбрали клетку → пометили → рекурсия в 4 стороны → ОТКАТИЛИ пометку
```

Отличие от Number of Islands принципиальное: там пометка ставилась **навсегда** (клетка больше
не нужна), здесь — только **на время текущего пути**, потому что другой путь может пройти через
эту же клетку.

## ⚠️ Подводные камни именно этой задачи

1. **Обязательный откат пометки** (`board[r][c] = saved` после рекурсии). Без него клетка
   останется «занятой» для всех последующих попыток, и часть слов не найдётся. Это
   **главное отличие** backtracking от обычного обхода — если понял его здесь, понял везде.
2. **База успеха — до проверки границ.** Порядок в функции: сначала `if (index === word.length)
   return true`, потом проверки границ и совпадения буквы.
3. **Возврат `true` наверх немедленно.** Как только какая-то ветка вернула `true`, надо
   прекратить перебор и не забыть при этом **восстановить** клетку.
4. **Пометка «занято» не должна совпадать с буквой алфавита.** Обычно ставят `'#'` или `null`.
5. Стартовать нужно из **каждой** клетки — слово может начинаться где угодно.
6. Отсечение по количеству букв (см. разбор) превращает безнадёжные входы в мгновенные.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function exist(board, word) {
  const rows = board.length;
  const cols = board[0].length;

  function dfs(r, c, index) {
    if (index === word.length) return true;                  // всё слово собрано
    if (r < 0 || r >= rows || c < 0 || c >= cols) return false;
    if (board[r][c] !== word[index]) return false;

    const saved = board[r][c];
    board[r][c] = '#';                                       // помечаем занятой

    const found =
      dfs(r + 1, c, index + 1) ||
      dfs(r - 1, c, index + 1) ||
      dfs(r, c + 1, index + 1) ||
      dfs(r, c - 1, index + 1);

    board[r][c] = saved;                                     // ОТКАТ — ключевая строка

    return found;
  }

  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (dfs(r, c, 0)) return true;
    }
  }

  return false;
}
```

**Почему откат обязателен.** Проверь `word = "SEE"` на примере: путь идёт `(1,3)S → (2,3)E →
(2,2)E`. Если бы клетки, использованные при неудачной попытке начать с `(1,0)S`, остались
помечены, этот путь не нашёлся бы.

**Короткое замыкание `||`** даёт бесплатное отсечение: как только одно направление вернуло
`true`, остальные даже не вызываются.

**Сложность:** время `O(m · n · 3^L)` — стартов `m · n`, из каждой клетки не более 3 новых
направлений (в четвёртом мы только что были), глубина `L`. Память `O(L)` на стек.

</details>

<details>
<summary>Полезное отсечение (pruning)</summary>

```js
function exist(board, word) {
  const counts = new Map();
  for (const row of board) {
    for (const ch of row) counts.set(ch, (counts.get(ch) || 0) + 1);
  }

  const needed = new Map();
  for (const ch of word) needed.set(ch, (needed.get(ch) || 0) + 1);

  for (const [ch, need] of needed) {
    if ((counts.get(ch) || 0) < need) return false;    // букв физически не хватает
  }

  // ...дальше обычный перебор
}
```

Это **Frequency Counter** (тема из раздела 02) в роли отсечения: если в сетке всего две буквы
`'C'`, а в слове их три — перебор запускать бессмысленно.

Второе классическое отсечение: если последняя буква слова встречается в сетке реже первой —
искать слово **с конца** (`word.split('').reverse().join('')`). Стартов будет меньше.

Упоминание отсечений на интервью ценится: оно показывает, что ты думаешь о реальной
производительности, а не только об асимптотике.

</details>

<details>
<summary>Backtracking vs обычный обход — итог</summary>

| | Number of Islands | Word Search |
|---|---|---|
| Пометка | навсегда | только на текущем пути |
| Откат | не нужен | **обязателен** |
| Цель | посетить всё | найти **один** подходящий путь |
| Сложность | `O(m·n)` | `O(m·n·3^L)` |

Правило: если клетка может понадобиться **другому** варианту решения — пометку надо снимать.
Если она отработана окончательно — оставлять.

</details>
