# Fibonacci с мемоизацией

**Тема:** recursion (мемоизация) · **Сложность:** easy · **Приоритет:** 🔴 основная

> ⚠️ Разобрана в теории ([recursion.md](../../../05-recursion-trees/01-recursion.md)).
> Пиши **по памяти** все три версии. Это фундамент понимания «почему рекурсия бывает медленной».

## Условие

Числа Фибоначчи: `F(0) = 0`, `F(1) = 1`, `F(n) = F(n-1) + F(n-2)` при `n >= 2`.

Напиши **три** версии:
- **A.** Наивная рекурсия. Назови её сложность.
- **B.** Рекурсия с мемоизацией. Сложность?
- **C.** Итеративная с `O(1)` памяти.

## Примеры

```
fib(0) = 0
fib(1) = 1
fib(2) = 1
fib(5) = 5        // 0, 1, 1, 2, 3, 5
fib(10) = 55
fib(50) = 12586269025
```

## Ограничения

- `0 <= n <= 50` для версий B и C.
- Версию A не запускай на `n > 40` — будет считаться очень долго (в этом и смысл упражнения).

## 🎯 Цель по сложности

| Версия | Время | Память |
|---|:---:|:---:|
| A наивная | `O(2^N)` | `O(N)` стек |
| B мемоизация | `O(N)` | `O(N)` |
| C итеративная | `O(N)` | `O(1)` |

## 🧠 Ментальная модель

Дерево вызовов наивной версии ветвится надвое на каждом уровне — отсюда экспонента.
Мемоизация «срезает» повторяющиеся ветки: каждое значение считается один раз.
Итеративная версия замечает, что нужны только **два последних** значения.

## ⚠️ Подводные камни именно этой задачи

1. **База — `n < 2`, а не `n === 0`.** Нужны **два** базовых случая (`0` и `1`), иначе
   `fib(1)` уйдёт в `fib(0) + fib(-1)` → бесконечная рекурсия.
2. **Мемо нужно передавать во вложенные вызовы.** `fib(n - 1)` без второго аргумента создаст
   новый пустой `Map` на каждом уровне — код будет работать, но останется `O(2^N)`.
   Ошибка **тихая**: результат верный, тормоза необъяснимые.
3. **Записывать в кеш до возврата.** `memo.set(n, result)` должно стоять перед `return`.
4. **В итеративной версии обмен переменных.** `prev = curr; curr = prev + curr;` — ошибка
   (`prev` уже перезаписан). Нужна деструктуризация `[prev, curr] = [curr, prev + curr]`
   или временная переменная.
5. `fib(0)` и `fib(1)` — обязательные проверки во всех трёх версиях.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Все три версии + объяснение</summary>

```js
// A — наивная: O(2^N) время, O(N) память (стек)
function fibNaive(n) {
  if (n < 2) return n;                      // покрывает и 0, и 1
  return fibNaive(n - 1) + fibNaive(n - 2);
}

// B — мемоизация: O(N) / O(N)
function fibMemo(n, memo = new Map()) {
  if (n < 2) return n;
  if (memo.has(n)) return memo.get(n);      // уже считали

  const result = fibMemo(n - 1, memo) + fibMemo(n - 2, memo);   // memo передаём!
  memo.set(n, result);
  return result;
}

// C — итеративная: O(N) / O(1)
function fibIterative(n) {
  if (n < 2) return n;

  let prev = 0;                             // F(0)
  let curr = 1;                             // F(1)

  for (let i = 2; i <= n; i++) {
    [prev, curr] = [curr, prev + curr];     // сдвигаем окно вправо
  }

  return curr;
}
```

**Трассировка версии C** для `n = 5`:

| i | prev (до) | curr (до) | prev (после) | curr (после) |
|:-:|:---------:|:---------:|:------------:|:------------:|
| 2 | 0 | 1 | 1 | 1 |
| 3 | 1 | 1 | 1 | 2 |
| 4 | 1 | 2 | 2 | 3 |
| 5 | 2 | 3 | 3 | 5 |

Возвращаем `curr = 5` ✅ (`F(5) = 5`)

Проверь **последнюю итерацию** отдельно — это твоя слабая точка по прошлым задачам:
цикл идёт `i <= n` (нестрого), иначе для `n = 2` тело не выполнится и вернётся `1` вместо `1`…
здесь совпало бы случайно, а для `n = 3` вернулось бы `1` вместо `2` ❌

</details>

<details>
<summary>Почему мемоизация даёт именно O(N)</summary>

С кешем каждое значение `F(k)` вычисляется **ровно один раз**: первый вызов считает и
записывает, все последующие сразу читают из `Map` за `O(1)`. Разных значений `k` от `0` до `n`
всего `n + 1` → `O(N)` вызовов, в каждом константная работа.

Память `O(N)`: кеш на `n` записей + до `n` фреймов в стеке (спуск идёт по цепочке
`n → n-1 → n-2 → ... → 1`).

Это ровно тот же приём, что ты применял в Frequency Counter и Prefix Sum:
**«сохранить уже вычисленное, чтобы не считать заново»**. Здесь он называется мемоизацией и
формально является top-down динамическим программированием.

</details>

<summary>Эксперимент, который стоит провести</summary>
