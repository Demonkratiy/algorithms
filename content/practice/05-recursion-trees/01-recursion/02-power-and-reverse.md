# Power — рекурсивное возведение в степень

**Тема:** recursion (база + шаг) · **Сложность:** easy · **Приоритет:** 🔴 основная

Короткая разминка на рекурсивный контракт: **доверяй вложенному вызову**. Вторая разминка — [Reverse String](02-b-reverse-string.md).

## Условие

Возведи `base` в неотрицательную целую степень `exponent` **рекурсивно**.
`**` и `Math.pow` использовать нельзя.

```
power(2, 0) = 1
power(2, 5) = 32
power(3, 3) = 27
```

**Бонус (важный!):** сделай за `O(log N)` вместо `O(N)` — быстрое возведение в степень.

`exponent` — неотрицательное целое число; результат помещается в конечный `Number`. Для степени `0`, включая `power(0, 0)`, договоримся возвращать `1`.

## 🎯 Цель по сложности

`N = exponent`. Наивная версия: время `O(N)`, память стека `O(N)`. Быстрая версия: время и стек `O(log N)` для `N > 0`; при `N = 0` — `O(1)`.

## 🧠 Ментальная модель

**Рекурсивный контракт.** Не раскручивай стек в голове. Спроси себя:

1. Какой вход **тривиален** и ответ известен сразу? → база.
2. Если вложенный вызов **уже вернул правильный ответ** для меньшего входа, что мне сделать,
   чтобы получить ответ для текущего? → шаг.

Для `power`: если `power(2, 4)` уже равно `16`, то `power(2, 5) = 2 * 16`. База: любое число в
степени `0` равно `1`.

## ⚠️ Подводные камни именно этой задачи

1. **База `exponent === 0` возвращает `1`, а не `0`.** Классическая ошибка.
2. **Забыть `return`** перед рекурсивным вызовом → `undefined`. Проверь глазами.
3. **Быстрое возведение: `exponent` нечётный.** Формула `power(b, e) = power(b, e/2)²` работает
   только для чётных. Для нечётных — `b * power(b, e - 1)`. Пропустить эту ветку = получить
   неверный ответ на нечётных степенях.
4. **Вычислять `power(b, e/2)` ОДИН раз.** Если написать
   `power(b, e/2) * power(b, e/2)` — будет два вызова, и сложность вернётся к `O(N)`.
   Сохраняй в переменную. Это та же идея, что мемоизация в Фибоначчи.

## 💡 Подсказки (открывай по очереди)

<details>
<summary>Подсказка 1 — power, наивно</summary>

База: `exponent === 0` → `1`. Шаг: `base * power(base, exponent - 1)`.

</details>

<details>
<summary>Подсказка 2 — power, быстро</summary>

Если `exponent` чётный: `half = power(base, exponent / 2)`, вернуть `half * half`.
Если нечётный: вернуть `base * power(base, exponent - 1)`.

</details>

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>power — наивная и быстрая</summary>

```js
function power(base, exponent) {
  if (exponent === 0) return 1;                 // база: b^0 = 1
  return base * power(base, exponent - 1);      // шаг
}
```
Время `O(N)`, память `O(N)` (глубина стека = `exponent`).

```js
function fastPower(base, exponent) {
  if (exponent === 0) return 1;

  if (exponent % 2 === 0) {
    const half = fastPower(base, exponent / 2);   // ОДИН вызов, результат переиспользуем
    return half * half;
  }

  return base * fastPower(base, exponent - 1);    // нечётный: сводим к чётному
}
```

**Трассировка** `fastPower(2, 10)`:

```
fastPower(2, 10) → чётный → half = fastPower(2, 5)
  fastPower(2, 5) → нечётный → 2 * fastPower(2, 4)
    fastPower(2, 4) → чётный → half = fastPower(2, 2)
      fastPower(2, 2) → чётный → half = fastPower(2, 1)
        fastPower(2, 1) → нечётный → 2 * fastPower(2, 0) = 2 * 1 = 2
      → 2 * 2 = 4
    → 4 * 4 = 16
  → 2 * 16 = 32
→ 32 * 32 = 1024 ✅
```

Всего 6 вызовов вместо 10 — а при `exponent = 1 000 000` разница катастрофическая:
`log₂(10^6) ≈ 20` вызовов против миллиона.

**Сложность:** время `O(log N)` — экспонента уменьшается вдвое (или на 1, но следующий шаг
обязательно делит пополам). Память `O(log N)` — глубина стека.

⚠️ Если бы мы написали `return fastPower(base, exponent/2) * fastPower(base, exponent/2)`,
то делали бы **два** одинаковых вызова, и суммарно получилось бы `O(N)` — вся оптимизация
пропала бы. Точно та же ловушка, что в наивном Фибоначчи.

</details>

<details>
<summary>Что здесь тренируется (не пропусти)</summary>

Эта задача и [Reverse String](02-b-reverse-string.md) — про **формулировку контракта**. Прежде чем писать код, произнеси вслух:

> «Если вложенный вызов правильно решает задачу для входа поменьше, то я делаю _вот это_,
> чтобы получить ответ для своего входа. А самый маленький вход — _вот такой_, и ответ на него
> — _вот такой_».

Если ты можешь произнести эти две фразы — код напишется сам. Если не можешь — код не поможет.
Именно этот навык понадобится в задачах на деревья, где рекурсия становится основным
инструментом.

</details>
