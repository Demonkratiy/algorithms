# Validate Binary Search Tree

**Тема:** binary-trees / BST · **Сложность:** medium · **Приоритет:** 🔴 основная

> Задача с **ловушкой**, на которой спотыкается большинство. Проверяет, понимаешь ли ты, что
> свойство BST — **глобальное**, а не локальное.

## Условие

Дан корень бинарного дерева. Определи, является ли оно **корректным BST** (binary search tree).

Правила BST:
- все значения в **левом** поддереве узла **строго меньше** значения узла;
- все значения в **правом** поддереве **строго больше**;
- оба поддерева тоже являются BST.

## Примеры

```
Вход:   2          Выход: true
       / \
      1   3

Вход:   5          Выход: false
       / \
      1   4        // 4 < 5, но находится в ПРАВОМ поддереве
         / \
        3   6

Вход:   5          Выход: false  ← ГЛАВНАЯ ЛОВУШКА
       / \
      1   6
         / \
        3   7      // локально всё верно (3 < 6, 7 > 6),
                   // но 3 < 5 и лежит в ПРАВОМ поддереве корня

Вход:  [1]         Выход: true
Вход:  []          Выход: true
```

## Ограничения

- `1 <= число узлов <= 10^4`
- `-2^31 <= Node.val <= 2^31 - 1`

## 🎯 Цель по сложности

- Время `O(N)`, память `O(h)`.

## 🧠 Ментальная модель

**Свойство BST глобально.** Проверять «`node.left.val < node.val`» недостаточно — узел должен
укладываться в **диапазон**, заданный всеми предками.

Идея: спускаясь вниз, передаём каждому узлу допустимый интервал `(min, max)`:

```
                5           (-∞, +∞)
              /   \
    (-∞, 5)  1     6        (5, +∞)
                  / \
        (5, 6)   3   7      (6, +∞)
                 ↑
        3 не входит в (5, 6) → false ✅
```

Правила сужения:
- идём **влево** → верхняя граница становится `node.val`: `(min, node.val)`;
- идём **вправо** → нижняя граница становится `node.val`: `(node.val, max)`.

Альтернативный подход — **in-order обход**: у корректного BST он даёт строго возрастающую
последовательность. Достаточно сравнивать текущее значение с предыдущим.

## ⚠️ Подводные камни именно этой задачи

1. **Локальная проверка недостаточна.** Пример с `3` под `6` из условия — обязательно
   проверь на нём своё решение. Если оно вернуло `true` — ты попал в главную ловушку.
2. **Строгие неравенства.** Дубликаты в BST по этому определению **запрещены**:
   `node.val <= min` → `false`. Уточняй у интервьюера, разрешены ли равные значения.
3. **Границы `-Infinity` / `Infinity`.** Не используй `Number.MIN_SAFE_INTEGER` — значения узлов
   доходят до `-2^31`, и при жёстких границах корректное дерево может быть отвергнуто.
   `null` в качестве «нет границы» тоже работает, но требует лишних проверок.
4. **In-order способ: сравнение с предыдущим, а не с родителем.** Нужно хранить `prev` между
   вызовами (замыкание или поле объекта), а не передавать вниз.
5. Пустое дерево и один узел — валидные BST.

Влево: `validate(node.left, min, node.val)`.
Вправо: `validate(node.right, node.val, max)`.

</details>

<details>
<summary>Подсказка 3 — альтернатива</summary>

In-order обход должен давать строго возрастающую последовательность. Храни `prev` и проверяй

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение через диапазоны (рекомендуемое)</summary>

```js
function isValidBST(root) {
  function validate(node, min, max) {
    if (node === null) return true;                       // пустое поддерево валидно

    if (node.val <= min || node.val >= max) return false; // вышли за допустимый диапазон

    return (
      validate(node.left, min, node.val) &&               // влево: сужаем ВЕРХНЮЮ границу
      validate(node.right, node.val, max)                 // вправо: сужаем НИЖНЮЮ
    );
  }

  return validate(root, -Infinity, Infinity);
}
```

**Трассировка «ловушки»:**
```
        5
       / \
      1   6
         / \
        3   7
```

| узел | диапазон | проверка | итог |
|:---:|---|---|---|
| 5 | `(-∞, +∞)` | ок | идём дальше |
| 1 | `(-∞, 5)` | `1` в диапазоне | ок |
| 6 | `(5, +∞)` | ок | идём дальше |
| 3 | `(5, 6)` | `3 <= 5` | **false** ✅ |

Именно передача диапазона от корня `5` вниз через `6` ловит ошибку, которую локальная проверка
пропустила бы.

**Сложность:** время `O(N)` — каждый узел один раз.
Память `O(h)` — стек рекурсии; `O(log N)` для сбалансированного, `O(N)` для вырожденного.

Короткое замыкание `&&` даёт бонус: при `false` в левом поддереве правое даже не обходится.

</details>

<details>
<summary>Решение через in-order обход</summary>

```js
function isValidBSTInorder(root) {
  let prev = -Infinity;
  let valid = true;

  function inorder(node) {
    if (node === null || !valid) return;

    inorder(node.left);                       // 1. левое поддерево

    if (node.val <= prev) valid = false;      // 2. сам узел: должен расти строго
    prev = node.val;

    inorder(node.right);                      // 3. правое поддерево
  }

  inorder(root);
  return valid;
}
```

**Почему работает.** In-order обход BST выдаёт значения по возрастанию — это определяющее
свойство. Значит, достаточно проверить, что каждое следующее строго больше предыдущего.

Для дерева-ловушки последовательность получится `1, 5, 3, 6, 7` — на шаге `3` после `5`
условие нарушено ✅

Тот же `O(N)` / `O(h)`. Способ короче, но требует аккуратности с внешней переменной `prev`
(её нельзя передавать как параметр — она общая для всего обхода).

</details>

<details>
<summary>Полезные факты про BST для интервью</summary>

- **In-order = отсортированный порядок** — используется в задачах «k-й наименьший элемент в BST»
  (обход с досрочным выходом на `k`-м узле, `O(h + k)`).
- **Поиск в BST — `O(h)`**, а не `O(log N)`: логарифм только для **сбалансированного** дерева.
  Вырожденное BST (вставка отсортированных данных) деградирует в связный список.
  Отсюда самобалансирующиеся деревья: AVL, красно-чёрные. Знать названия достаточно.
- **Вставка/удаление** — `O(h)`. Удаление узла с двумя потомками требует замены на «преемника»
  (минимум правого поддерева) — популярный уточняющий вопрос.
- Проверять BST «локально» — самая известная ошибка на этой теме. Теперь ты её знаешь.

</details>
