# Diameter of Binary Tree

**Тема:** binary-trees (DFS, «ответ в узле ≠ возвращаемое значение») · **Сложность:** easy → medium · **Приоритет:** ⚪ дополнительная

> Задача учит важнейшему приёму: **функция возвращает одно, а попутно вычисляет другое**.
> Он нужен в куче задач (max path sum, longest univalue path, balanced tree).

## Условие

Дан корень бинарного дерева. Верни его **диаметр** — длину самого длинного пути между любыми
двумя узлами дерева. Длина измеряется в **рёбрах**.

Путь **не обязан** проходить через корень.

## Примеры

```
Вход:      1            Выход: 3
         /   \                 // путь 4 → 2 → 1 → 3 (или 5 → 2 → 1 → 3): 3 ребра
        2     3
       / \
      4   5

Вход:  [1, 2]           Выход: 1
Вход:  [1]              Выход: 0
Вход:  []               Выход: 0
```

## Ограничения

- `1 <= число узлов <= 10^4`

## 🎯 Цель по сложности

- Время **`O(N)`** — один обход.
- Память `O(h)`.
- ⚠️ Наивно: для каждого узла считать `depth(left) + depth(right)`, вызывая `depth` заново →
  `O(N²)` (в вырожденном дереве). Задача как раз про то, чтобы этого избежать.

## 🧠 Ментальная модель

Для **каждого** узла есть путь, проходящий через него: `depth(left) + depth(right)` рёбер.
Диаметр — максимум таких значений по всем узлам.

```
        1
      /   \
     2     3        через узел 2: depth(4)=1 + depth(5)=1 = 2
    / \              через узел 1: depth(2)=2 + depth(3)=1 = 3 ← максимум
   4   5
```

**Ключевой приём.** Рекурсивная функция возвращает **глубину** (это нужно родителю), но по пути
обновляет **внешнюю переменную** `maxDiameter` (это нужно нам). Одно другому не мешает —
и всё считается за один проход.

> 💡 Формулируй так: _«возвращаю то, что нужно родителю; попутно обновляю ответ»_.
> Как только увидишь задачу, где «ответ в узле не совпадает с тем, что надо вернуть наверх», —
> вспоминай этот приём.

## ⚠️ Подводные камни именно этой задачи

1. **Диаметр измеряется в РЁБРАХ, а не в узлах.** Для дерева из двух узлов ответ `1`, не `2`.
   Отсюда формула `leftDepth + rightDepth` без `+1`.
2. **Возвращать глубину, а не диаметр.** Родителю нужна глубина поддерева; если вернуть
   диаметр, вычисления сломаются. Это суть задачи.
3. **Не пересчитывать глубину для каждого узла заново** — иначе `O(N²)`.
4. **`maxDiameter` — внешняя переменная (замыкание)**, обновляется через `Math.max`.
   Инициализация `0`, а не `-Infinity`: диаметр не может быть отрицательным.
5. **База возвращает `0`** — глубина пустого поддерева. Не `-1` (это была бы «высота в рёбрах»),
   иначе арифметика поедет на единицу.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function diameterOfBinaryTree(root) {
  let maxDiameter = 0;

  function depth(node) {
    if (node === null) return 0;                              // глубина пустого поддерева

    const leftDepth = depth(node.left);
    const rightDepth = depth(node.right);

    // путь, проходящий ЧЕРЕЗ текущий узел (в рёбрах)
    maxDiameter = Math.max(maxDiameter, leftDepth + rightDepth);

    // а наверх возвращаем ГЛУБИНУ — это нужно родителю
    return 1 + Math.max(leftDepth, rightDepth);
  }

  depth(root);
  return maxDiameter;
}
```

**Трассировка** (снизу вверх):

```
        1
      /   \
     2     3
    / \
   4   5
```

| узел | leftDepth | rightDepth | путь через узел | maxDiameter | возврат |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 4 | 0 | 0 | 0 | 0 | 1 |
| 5 | 0 | 0 | 0 | 0 | 1 |
| 2 | 1 | 1 | **2** | 2 | 2 |
| 3 | 0 | 0 | 0 | 2 | 1 |
| 1 | 2 | 1 | **3** | **3** | 3 |

Ответ `3` ✅ — путь `4 → 2 → 1 → 3`.

**Сложность:** время `O(N)` — каждый узел ровно один вызов `depth`.
Память `O(h)` — стек рекурсии.

</details>

<details>
<summary>Почему наивный подход даёт O(N²)</summary>

```js
// НЕ ДЕЛАЙ ТАК
function diameterNaive(root) {
  if (root === null) return 0;

  const throughRoot = depth(root.left) + depth(root.right);   // depth считается заново
  return Math.max(
    throughRoot,
    diameterNaive(root.left),
    diameterNaive(root.right),
  );
}
```

Здесь `depth` вызывается для каждого узла независимо, и одни и те же поддеревья обходятся
многократно. В вырожденном дереве («палка» из `N` узлов) это `O(N²)`.

Это та же болезнь, что у наивного Фибоначчи — **повторный пересчёт подзадач**. Лечение то же:
считать один раз и переиспользовать (здесь — вернуть глубину наверх, а не запрашивать её снова).

</details>

<details>
<summary>Другие задачи с этим приёмом</summary>

Один и тот же шаблон — «возвращаю одно, обновляю другое»:

- **Balanced Binary Tree** — возвращаем высоту, попутно проверяем `|left - right| <= 1`;
- **Binary Tree Maximum Path Sum** (hard) — возвращаем максимальную сумму «ветки вниз»,
  обновляем максимум пути через узел; дополнительная тонкость — отрицательные ветки
  отбрасываются через `Math.max(0, ...)`;
- **Longest Univalue Path** — возвращаем длину одинаковой ветки, обновляем максимум;
- **Count Good Nodes** — передаём максимум по пути вниз, копим счётчик.

Как только видишь «самый длинный/большой путь **где-то в дереве**» (не обязательно от корня) —
это он.

</details>
