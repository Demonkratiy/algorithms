# Find Pivot Index

**Тема:** prefix-sum (без массива префиксов) · **Сложность:** easy · **Приоритет:** 🔴 основная

## Условие

Дан массив целых чисел `nums`. Найди **pivot index** — такой индекс `i`, что сумма элементов
**строго слева** от него равна сумме элементов **строго справа**. Сам элемент `nums[i]`
не входит ни в одну из сумм.

Верни **самый левый** подходящий индекс. Если такого нет — верни `-1`.

Если pivot — это индекс `0`, то левая сумма считается равной `0` (слева ничего нет).
Аналогично для последнего индекса — правая сумма `0`.

## Примеры

```
Вход:  nums = [1, 7, 3, 6, 5, 6]
Выход: 3            // слева 1+7+3 = 11, справа 5+6 = 11

Вход:  nums = [1, 2, 3]
Выход: -1

Вход:  nums = [2, 1, -1]
Выход: 0            // слева пусто = 0, справа 1 + (-1) = 0

Вход:  nums = [0]
Выход: 0            // слева 0, справа 0
```

## Ограничения

- `1 <= nums.length <= 10^4`
- `-1000 <= nums[i] <= 1000`

## 🎯 Цель по сложности

- Время **`O(N)`**, память **`O(1)`**.
- Наивно: для каждого `i` считать обе суммы циклами → `O(N²)`.

## 🧠 Ментальная модель

Это Prefix Sum, но **массив префиксов не нужен** — хватит двух чисел.

Заметь связь: `total = left + nums[i] + right`, значит `right = total - left - nums[i]`.
Условие «left === right» превращается в:

```
left === total - left - nums[i]
```

Алгоритм: посчитать `total` одним проходом, затем идти вторым проходом, держа бегущую `left`
(сумма строго слева от текущего `i`), и на каждом шаге проверять равенство.

> 💡 Это важный приём: «две суммы» почти всегда сводятся к **одной бегущей + общей**.
> Он же экономит память с `O(N)` до `O(1)`.

## ⚠️ Подводные камни именно этой задачи

1. **`left` — сумма СТРОГО слева.** Проверять надо **до** того, как прибавил `nums[i]` к `left`.
   Классическая ошибка — прибавить сначала, тогда `nums[i]` попадёт в левую сумму.
2. **Отрицательные числа есть.** Нельзя останавливаться, когда «left уже больше половины» —
   дальше сумма может снова упасть. Идём до конца массива.
3. **Нужен самый левый индекс** → возвращаем сразу при первом совпадении, а не собираем все.
4. **Границы включены:** `i = 0` и `i = nums.length - 1` — валидные ответы, не пропусти их
   (не начинай цикл с `1` и не заканчивай на `length - 1` исключительно).
5. Массив из одного элемента — ответ всегда `0` (обе суммы пустые). Хороший edge case для
   самопроверки.

<details>
<summary>Подсказка 1 — общая сумма</summary>

`const total = nums.reduce((acc, n) => acc + n, 0);` — или обычным циклом.

</details>

<details>
<summary>Подсказка 2 — выразить правую сумму</summary>

Не считай правую сумму отдельно. Она равна `total - left - nums[i]`.

</details>

<details>
<summary>Подсказка 3 — порядок внутри цикла</summary>

Внутри цикла: **сначала** сравнение, **потом** `left += nums[i]`. Если сделаешь наоборот,
`nums[i]` окажется в левой части.

</details>

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function pivotIndex(nums) {
  let total = 0;
  for (const num of nums) total += num;

  let left = 0;                                  // сумма СТРОГО слева от i
  for (let i = 0; i < nums.length; i++) {
    const right = total - left - nums[i];
    if (left === right) return i;                // самый левый подходит — выходим сразу
    left += nums[i];                             // только теперь nums[i] уходит "налево"
  }

  return -1;
}
```

**Трассировка** `nums = [1, 7, 3, 6, 5, 6]`, `total = 28`:

| i | nums[i] | left (до сравнения) | right = 28 - left - nums[i] | равны? |
|:-:|:-------:|:-------------------:|:---------------------------:|:------:|
| 0 | 1 | 0 | 27 | нет |
| 1 | 7 | 1 | 20 | нет |
| 2 | 3 | 8 | 17 | нет |
| 3 | 6 | 11 | 11 | **да → 3** ✅ |

**Сложность:** время `O(N)` (два линейных прохода = `O(2N)` = `O(N)`),
память `O(1)` — только два числа, массив префиксов не строим.

</details>

<details>
<summary>Вариант через массив префиксов (для сравнения)</summary>

```js
function pivotIndexPrefix(nums) {
  const prefix = [0];
  for (let i = 0; i < nums.length; i++) prefix.push(prefix[i] + nums[i]);

  const total = prefix[nums.length];
  for (let i = 0; i < nums.length; i++) {
    if (prefix[i] === total - prefix[i + 1]) return i;   // слева от i / справа от i
  }
  return -1;
}
```

Тоже `O(N)` по времени, но `O(N)` по памяти. На интервью стоит назвать оба и объяснить, почему
первый лучше: **массив префиксов нужен, только если к нему будет много запросов**; для одного
прохода достаточно бегущей суммы.

Разбери индексы: `prefix[i]` — сумма элементов `0..i-1` (строго слева), `prefix[i + 1]` — сумма
`0..i` (включая сам элемент), значит справа остаётся `total - prefix[i + 1]`.

</details>
