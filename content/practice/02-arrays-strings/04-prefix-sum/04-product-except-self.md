# Product of Array Except Self

**Тема:** prefix-sum (префикс/суффикс, но произведение) · **Сложность:** medium · **Приоритет:** ⚪ дополнительная

> Классика собеседований в BigTech. Показывает, что идея «префикс» работает не только для сумм,
> и учит приёму **префикс слева + суффикс справа**.

## Условие

Дан массив чисел `nums`. Верни массив `answer`, где `answer[i]` — произведение **всех**
элементов `nums`, **кроме** `nums[i]`.

**Нельзя использовать деление.** Требуется `O(N)` по времени.

## Примеры

```
Вход:  nums = [1, 2, 3, 4]
Выход: [24, 12, 8, 6]

Вход:  nums = [-1, 1, 0, -3, 3]
Выход: [0, 0, 9, 0, 0]
```

## Ограничения

- `2 <= nums.length <= 10^5`
- Гарантируется, что произведение любого префикса/суффикса помещается в 32-битное целое.

## 🎯 Цель по сложности

- Время **`O(N)`**, память **`O(N)`** под ответ.
- Продвинуто: **`O(1)` дополнительной памяти** (выходной массив не считается) — второй проход
  идёт справа налево и домножает то, что уже лежит в ответе.

## 🧠 Ментальная модель

`answer[i]` = (произведение всего слева от `i`) × (произведение всего справа от `i`).

```
nums:    [ 1 ,  2 ,  3 ,  4 ]
prefix:  [ 1 ,  1 ,  2 ,  6 ]   // произведение элементов строго слева
suffix:  [24 , 12 ,  4 ,  1 ]   // произведение элементов строго справа
answer:  [24 , 12 ,  8 ,  6 ]   // поэлементное произведение
```

Это ровно та же идея, что и prefix sum, только операция — умножение, и нужен ещё «префикс с
другой стороны» (суффикс).

## ⚠️ Подводные камни именно этой задачи

1. **Нули.** Соблазн: посчитать произведение всего и делить на `nums[i]`. Во-первых, деление
   запрещено; во-вторых, при нуле оно ломается (деление на 0), а при двух нулях — ломается ещё
   и логика. Префикс/суффикс обрабатывает нули сам собой — специальные ветки не нужны.
2. **«Строго слева/справа».** `prefix[0] = 1` и `suffix[n-1] = 1` — нейтральный элемент
   умножения, аналог нуля для сумм. Частая ошибка — начать с `nums[0]`.
3. **Направление второго цикла.** Суффиксы считаются **справа налево** (`for (let i = n - 1; i >= 0; i--)`);
   лёгкое место для off-by-one — проверь последнюю итерацию (`i = 0`).
4. Начинать аккумулятор с `0` вместо `1` — весь ответ обнулится. Нейтральный элемент для
   умножения — единица.

## 💡 Подсказки (открывай по очереди)

<details>
<summary>Подсказка 1 — два массива</summary>

Сначала сделай «наглядную» версию: отдельный массив `prefix` и отдельный `suffix`, потом
перемножь поэлементно. Оптимизацию памяти сделаешь вторым шагом.

</details>

<details>
<summary>Подсказка 2 — как экономится память</summary>

Заполни `answer` префиксами. Затем иди справа налево с переменной `suffix = 1`:
`answer[i] *= suffix; suffix *= nums[i];` — порядок важен, как и в pivot index.

</details>

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Наглядная версия (два массива)</summary>

```js
function productExceptSelf(nums) {
  const n = nums.length;
  const prefix = new Array(n).fill(1);
  const suffix = new Array(n).fill(1);

  for (let i = 1; i < n; i++) {
    prefix[i] = prefix[i - 1] * nums[i - 1];       // всё строго слева от i
  }
  for (let i = n - 2; i >= 0; i--) {
    suffix[i] = suffix[i + 1] * nums[i + 1];       // всё строго справа от i
  }

  const answer = new Array(n);
  for (let i = 0; i < n; i++) answer[i] = prefix[i] * suffix[i];
  return answer;
}
```

Время `O(N)`, память `O(N)` дополнительно (два вспомогательных массива).

</details>

<details>
<summary>Оптимальная версия — O(1) доп. памяти</summary>

```js
function productExceptSelf(nums) {
  const n = nums.length;
  const answer = new Array(n).fill(1);

  let prefix = 1;
  for (let i = 0; i < n; i++) {
    answer[i] = prefix;        // сначала кладём "всё слева"
    prefix *= nums[i];         // потом включаем текущий элемент
  }

  let suffix = 1;
  for (let i = n - 1; i >= 0; i--) {
    answer[i] *= suffix;       // домножаем на "всё справа"
    suffix *= nums[i];
  }

  return answer;
}
```

**Трассировка** `nums = [1, 2, 3, 4]`:

| проход | i | что кладём | answer после шага | аккумулятор после |
|:------:|:-:|------------|-------------------|-------------------|
| слева | 0 | prefix=1 | `[1, _, _, _]` | prefix=1 |
| слева | 1 | prefix=1 | `[1, 1, _, _]` | prefix=2 |
| слева | 2 | prefix=2 | `[1, 1, 2, _]` | prefix=6 |
| слева | 3 | prefix=6 | `[1, 1, 2, 6]` | prefix=24 |
| справа | 3 | ×1 | `[1, 1, 2, 6]` | suffix=4 |
| справа | 2 | ×4 | `[1, 1, 8, 6]` | suffix=12 |
| справа | 1 | ×12 | `[1, 12, 8, 6]` | suffix=24 |
| справа | 0 | ×24 | `[24, 12, 8, 6]` | suffix=24 |

✅ Совпало.

**Сложность:** время `O(N)` (два прохода), память `O(1)` дополнительно — выходной массив по
условию не считается. Именно эту оговорку («не считая выходного массива») нужно проговорить
вслух на интервью, иначе формально это `O(N)`.

</details>

<details>
<summary>Почему подход с делением плох (для устного ответа)</summary>

```js
// НЕ ДЕЛАЙ ТАК
const total = nums.reduce((a, b) => a * b, 1);
return nums.map(n => total / n);          // падает на n === 0
```

Даже если разрешить деление, нужны спецслучаи: один ноль в массиве (все ответы `0`, кроме
позиции самого нуля) и два и более нулей (все ответы `0`). Префикс/суффикс покрывает всё
единообразно — это и есть аргумент «почему мой способ лучше».

</details>
