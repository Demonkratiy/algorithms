# Valid Palindrome

**Тема:** two-pointers · **Сложность:** easy

## Условие

Дана строка `s`. Определи, является ли она **палиндромом**, учитывая только
буквы и цифры и игнорируя регистр.

Палиндром — строка, которая читается одинаково слева направо и справа налево.

Правила очистки:

- Все НЕ буквенно-цифровые символы (пробелы, запятые, двоеточия и т.п.) игнорируются.
- Регистр не важен: `A` и `a` считаются одинаковыми.

Верни `true`, если строка — палиндром, иначе `false`.

## Примеры

```
Вход:  "A man, a plan, a canal: Panama"
Выход: true
Пояснение: после очистки → "amanaplanacanalpanama" — палиндром.

Вход:  "race a car"
Выход: false
Пояснение: после очистки → "raceacar" — не палиндром.

Вход:  " "
Выход: true
Пояснение: после очистки → "" (пустая строка) считается палиндромом.
```

## Ограничения

- `1 <= s.length <= 2 * 10^5`
- `s` состоит из печатаемых ASCII-символов.

## 🎯 Цель по сложности (к чему стремиться)

- Время: `O(N)`
- Память: `O(1)` — постарайся решить **без создания новой очищенной строки**,
  двигая два указателя прямо по исходной строке. (Сначала можно решить как угодно,
  потом оптимизируем до O(1) памяти.)

<summary>Решение и объяснение</summary>

### Идея и инвариант

Two Pointers идут навстречу по исходной строке. Каждый указатель пропускает
небуквенно-цифровые ASCII-символы. Затем сравниваем пару с учётом регистра:
несовпадение сразу доказывает, что палиндрома нет.
Все значимые символы вне текущего отрезка уже образуют совпавшие пары.
Когда указатели встретились или пересеклись, непроверенных пар больше нет.

### Эталонный код

```js
function isPalindrome(s) {
  let left = 0;
  let right = s.length - 1;
  const alphanumeric = /[a-z0-9]/i;

  while (left < right) {
    while (left < right && !alphanumeric.test(s[left])) {
      left++;
    }
    while (left < right && !alphanumeric.test(s[right])) {
      right--;
    }
    if (left >= right) break;
    if (s[left].toLowerCase() !== s[right].toLowerCase()) {
      return false;
    }
    left++;
    right--;
  }

  return true;
}
```

### Трассировка руками

Для `s = "A, b,a"` индексы идут от `0` до `5`.

| Шаг | Указатели и действие |
| --- | --- |
| 1 | `left = 0`, `right = 5`: `A` и `a` совпали после приведения регистра; получаем `1` и `4`. |
| 2 — последняя итерация | Слева пропускаем запятую и пробел до `3`, справа запятую до `3`. Указатели встретились на `b`; сравнивать пару уже не нужно. |
| Выход | Возвращаем `true`: центральный символ не мешает палиндрому. |

### Сложность

- Время: `O(N)`, где `N` — длина **исходной** строки. Каждый указатель движется
  только в одну сторону; вложенные пропуски суммарно линейны. Проверка одного
  ASCII-символа и изменение его регистра занимают `O(1)`.
- Дополнительная память: `O(1)` — индексы, фиксированная регулярка и текущие
  односимвольные значения. Очищенная строка и копия всего входа не создаются.
  Результат — одно логическое значение, `O(1)`.

### Границы и типичные ошибки

- Один символ и строка только из знаков/пробелов дают `true`. Пустая строка,
  хотя она вне заданного диапазона длины, тоже корректно даёт `true`.
- Цифры нужно учитывать: `"0P"` даёт `false`. Проверка только букв неверна.
- Границы проверяются **внутри** циклов пропуска: указатели могут встретиться,
  пока мы пропускаем знаки. Последний индекс равен `s.length - 1`.
- Флаг `g` регулярке не нужен: с ним последовательные вызовы `.test()`
  зависят от `lastIndex`, а здесь каждая проверка должна быть независимой.
- Приведение регистра всей строки или её очистка заранее потребуют `O(N)`
  дополнительной памяти. Здесь используется именно ASCII-контракт, не
  универсальная обработка букв всех языков.
