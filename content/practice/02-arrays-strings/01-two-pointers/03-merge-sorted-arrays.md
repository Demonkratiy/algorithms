# Merge Two Sorted Arrays

**Тема:** two-pointers (два массива) · **Сложность:** easy → medium

## Условие

Даны два массива `a` и `b`, **каждый отсортирован по возрастанию**.
Верни **новый** массив, содержащий все элементы из обоих, тоже отсортированный по возрастанию.

Дубликаты сохраняются (если число есть в обоих массивах — оно встретится дважды в результате).

## Примеры

```
Вход:  a = [1, 3, 5],   b = [2, 4, 6]
Выход: [1, 2, 3, 4, 5, 6]

Вход:  a = [1, 2, 2],   b = [2, 3]
Выход: [1, 2, 2, 2, 3]

Вход:  a = [],          b = [1, 2]
Выход: [1, 2]

Вход:  a = [1, 5, 9],   b = [2, 3]
Выход: [1, 2, 3, 5, 9]
```

## Ограничения

- `0 <= a.length, b.length <= 10^4`
- Оба массива уже отсортированы по возрастанию.

## 🎯 Цель по сложности

- Время: `O(N + M)`, где N и M — длины массивов.
- Память: `O(N + M)` для нового массива (это допустимо — результат обязан где-то жить).

> ⚠️ Наивный путь «склеить `a.concat(b)` и вызвать `.sort()`» даёт `O((N+M) log(N+M))` —
> хуже, чем нужно. Задача проверяет, умеешь ли ты воспользоваться тем, что массивы
> **уже отсортированы**, и слить их за линейное время.

## 🧠 Ментальная модель (НОВАЯ разновидность — прочитай)

Заведи **два указателя**: `i` по массиву `a`, `j` по массиву `b`. Оба стартуют с 0.
На каждом шаге сравниваешь `a[i]` и `b[j]`:

- меньший (или равный) элемент кладёшь в результат и сдвигаешь **его** указатель;
- так «молнией» (zipper) сливаешь оба массива в один отсортированный.

Когда один массив закончился — просто дозаписываешь **хвост** второго (он уже отсортирован).

Это фундамент шага **merge** в сортировке слиянием (Merge Sort) — увидишь его снова.

<details>
<summary>Подсказка 2 — хвосты</summary>

После основного цикла один из массивов может быть не дочитан. Добавь два отдельных
`while` (или `push` остатка), чтобы дописать оставшийся хвост `a` или `b`.

</details>

<details>
<summary>Подсказка 3 — про равные элементы</summary>

Если `a[i] <= b[j]` — бери из `a`. Знак `<=` (а не `<`) сохранит стабильный порядок
и корректно обработает дубликаты. По факту для чисел разница не критична.

</details>

<summary>Решение и объяснение</summary>

### Идея и инвариант

`i` и `j` указывают на первые ещё не перенесённые элементы `a` и `b`.
Результат уже отсортирован и содержит ровно элементы префиксов `[0, i)` и `[0, j)`.
Так как входы отсортированы, следующий минимальный элемент находится в одной
из этих двух позиций. Переносим меньший, сдвигая только его указатель.
После исчерпания одного входа оставшийся хвост второго можно дописать без сравнений.

### Эталонный код

```js
function mergeSorted(a, b) {
  const result = [];
  let i = 0;
  let j = 0;

  while (i < a.length && j < b.length) {
    if (a[i] <= b[j]) {
      result.push(a[i]);
      i++;
    } else {
      result.push(b[j]);
      j++;
    }
  }

  while (i < a.length) {
    result.push(a[i]);
    i++;
  }
  while (j < b.length) {
    result.push(b[j]);
    j++;
  }

  return result;
}
```

`a` и `b` не изменяются. Даже при пустом входе возвращается **новый** массив,
а не ссылка на один из аргументов.

### Трассировка руками

Вход: `a = [1, 2, 2]`, `b = [2, 3]`.

| Шаг | Сравнение и действие | `i`, `j` после шага | Результат |
| --- | --- | --- | --- |
| 1 | `1 <= 2`: берём из `a` | `1`, `0` | `[1]` |
| 2 | `2 <= 2`: берём из `a` | `2`, `0` | `[1, 2]` |
| 3 — последнее сравнение | `2 <= 2`: берём из `a` | `3`, `0` | `[1, 2, 2]` |
| 4 | `a` закончился; дописываем `b[0]` | `3`, `1` | `[1, 2, 2, 2]` |
| 5 — последняя итерация хвоста | Дописываем `b[1]`, затем `j = b.length` | `3`, `2` | `[1, 2, 2, 2, 3]` |

Равные элементы не исчезли: каждый переносится отдельно.

### Сложность

- Время: `O(N + M)`, где `N = a.length`, `M = b.length`. Каждый элемент
  переносится один раз. Для `push` используется стандартная амортизированная
  оценка `O(1)` на добавление.
- **Дополнительная память без результата: `O(1)`** — только индексы.
- **Память результата: `O(N + M)`**. Общая выделенная память с учётом нового
  массива — `O(N + M)`. Поэтому цель в условии и ответ `O(1)` в поле
  «Дополнительная память» тренажёра описывают разные способы учёта, а не противоречат.

### Границы и типичные ошибки

- Оба входа пусты: получаем новый `[]`. Один пуст: второй копируется поэлементно,
  без изменения входа и без возврата его ссылки.
- Дубликаты, отрицательные числа и сильно различающиеся длины не требуют особых веток.
- Основной цикл работает, пока доступны **оба** элемента: нужен `&&`, не `||`.
  При `||` один указатель может выйти за границу массива.
- В циклах используются `< length`, не `<= length`. Оставшиеся хвосты обязательны:
  завершение сравнений ещё не означает, что все элементы перенесены.
- На равенстве нельзя сдвигать оба указателя, записав лишь один элемент:
  так потеряется дубликат. Выбор из `a` первым сохраняет стабильность слияния.
- `shift()` изменяет входы и может сделать время квадратичным; здесь читаем по индексам.
