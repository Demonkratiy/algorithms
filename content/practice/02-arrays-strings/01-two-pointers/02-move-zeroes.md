# Move Zeroes

**Тема:** two-pointers (fast / slow) · **Сложность:** easy

## Условие
Дан массив чисел `nums`. Перемести все нули `0` в **конец** массива, сохранив
**относительный порядок** ненулевых элементов.

Важно: сделать это нужно **на месте (in-place)**, без создания копии массива.
Функция ничего не возвращает — она изменяет сам массив.

## Примеры
```
Вход:  [0, 1, 0, 3, 12]
Итог:  [1, 3, 12, 0, 0]

Вход:  [0]
Итог:  [0]

Вход:  [1, 2, 3]
Итог:  [1, 2, 3]   // нулей нет — ничего не меняется
```

## Ограничения
- `1 <= nums.length <= 10^4`
- `-2^31 <= nums[i] <= 2^31 - 1`

## 🎯 Цель по сложности
- Время: `O(N)`
- Память: `O(1)` — без нового массива.

## 🧠 Ментальная модель (это НОВАЯ разновидность — прочитай)
Здесь оба указателя идут в **одну сторону** (слева направо), но с разным смыслом:
- **`slow` (указатель записи, write)** — позиция, куда мы кладём следующий ненулевой элемент.
- **`fast` (указатель чтения, read)** — просматривает каждый элемент подряд.

Идея: `fast` бежит по массиву; как только встречает ненулевой элемент — «записывает»
его на позицию `slow` и сдвигает `slow` вперёд. В конце все ненулевые окажутся в начале
в правильном порядке, а «хвост» нужно добить нулями.

Это шаблон **read/write pointers** — он повторяется во многих in-place задачах
(Remove Duplicates, Remove Element и т.д.).

</details>

<summary>Решение и объяснение</summary>

### Идея и инвариант

Используем read/write pointers. `fast` читает массив слева направо, `slow`
показывает место следующей записи. Перед каждым чтением диапазон `[0, slow)`
содержит все ненулевые элементы из уже просмотренного префикса в исходном порядке.
Всегда `slow <= fast`, поэтому запись не портит ещё не прочитанные элементы.
После прохода заполняем нулями весь оставшийся хвост.

### Эталонный код

```js
function moveZeroes(nums) {
  let slow = 0;

  for (let fast = 0; fast < nums.length; fast++) {
    if (nums[fast] !== 0) {
      nums[slow] = nums[fast];
      slow++;
    }
  }

  while (slow < nums.length) {
    nums[slow] = 0;
    slow++;
  }
}
```

Функция меняет переданный массив и не возвращает результат: её возвращаемое
значение — `undefined`. Проверять нужно содержимое исходного `nums`.

### Трассировка руками

Вход: `[0, 1, 0, 3, 12]`.

| `fast` | Действие | `slow` после шага | Массив после шага |
| --- | --- | --- | --- |
| 0 | Пропускаем ноль | 0 | `[0, 1, 0, 3, 12]` |
| 1 | Записываем `1` в индекс `0` | 1 | `[1, 1, 0, 3, 12]` |
| 2 | Пропускаем ноль | 1 | `[1, 1, 0, 3, 12]` |
| 3 | Записываем `3` в индекс `1` | 2 | `[1, 3, 0, 3, 12]` |
| 4 — последнее чтение | Записываем `12` в индекс `2` | 3 | `[1, 3, 12, 3, 12]` |

Теперь в хвосте лежат устаревшие значения, а не готовый ответ!
При `slow = 3` записываем ноль в индекс `3`. Последняя итерация заполнения:
при `slow = 4` обнуляем индекс `4`, увеличиваем `slow` до `5` и выходим.
Итог: `[1, 3, 12, 0, 0]`.

### Сложность

- Время: `O(N)` — `N` чтений и не более `N` записей во втором проходе.
  Два последовательных линейных прохода не дают `O(N²)`.
- Дополнительная память: `O(1)` — два индекса. Входной массив занимает `O(N)`,
  но не считается дополнительной памятью; отдельного массива результата нет.

### Границы и типичные ошибки

- Все нули: `slow` остаётся равным `0`, второй проход обнуляет весь массив.
- Нулей нет: каждый элемент записывается на своё место, второй проход пуст.
- `[0]` и один ненулевой элемент обрабатываются теми же циклами. Пустой массив,
  хотя вне ограничений, останется пустым.
- Отрицательные числа тоже ненулевые: условие `nums[fast] > 0` неверно.
- Не двигай `slow` при нуле и не забывай обнулить хвост. Временные дубликаты
  после первого прохода нормальны.
- Условие обоих проходов — `< nums.length`, не `<=`: иначе появится лишняя ячейка.
- Присваивание нового массива локальной переменной `nums` не меняет исходный
  массив у вызывающего кода. Здесь нужны записи в его элементы.
