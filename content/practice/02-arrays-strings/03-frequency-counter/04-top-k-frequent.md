# Top K Frequent Elements

**Тема:** frequency-counter (+ сортировка / bucket) · **Сложность:** medium

## Условие

Дан массив чисел `nums` и число `k`. Верни `k` **самых часто встречающихся** элементов.
Порядок в ответе — любой.

Гарантируется, что ответ единственный (частоты позволяют однозначно выбрать top-k).

## Примеры

```
Вход:  nums = [1, 1, 1, 2, 2, 3], k = 2
Выход: [1, 2]

Вход:  nums = [1], k = 1
Выход: [1]

Вход:  nums = [4, 4, 4, 6, 6, 7, 7, 7, 7], k = 1
Выход: [7]
```

## Ограничения

- `1 <= nums.length <= 10^5`
- `k` в диапазоне `[1, число различных элементов]`

## 🎯 Цель по сложности

- Приемлемо: `O(N log N)` (счётчик + сортировка по частоте).
- Продвинуто: `O(N)` через **bucket sort** (корзины по частоте). Про этот способ можно
  рассказать вслух как оптимизацию.

## 🧠 Ментальная модель

Шаг 1 (Frequency Counter) — посчитай частоты: `Map` `число → сколько раз`.
Шаг 2 — выбери `k` ключей с наибольшими частотами.

Два способа шага 2:

1. **Сортировка** (проще): взять пары `[число, частота]`, отсортировать по частоте убыв.,
   взять первые `k` чисел. Это `O(M log M)`, где M — число различных элементов.
2. **Bucket sort** (`O(N)`): завести массив `buckets`, где индекс = частота, значение =
   список чисел с такой частотой. Частота не превышает `N`, поэтому индексов достаточно.
   Пройти корзины с конца (от высокой частоты к низкой) и набрать `k` чисел.

Начни со способа 1 (сортировка). Способ 2 — назови как оптимизацию до `O(N)`.

<summary>Решение и объяснение</summary>

### Идея и инвариант

Разделим задачу на подсчёт частот и выбор наиболее частых **различных** значений.
Во время первого прохода `counts` хранит точные частоты в обработанном префиксе `nums`.
После прохода каждой паре `[значение, частота]` соответствует одно различное значение.

Сортируем эти пары по убыванию **частоты**, не самого значения.
После сортировки частота каждой пары не меньше частот всех пар правее.
Поэтому первые `k` пар содержат нужные элементы; из них извлекаем только значения.
Гарантия единственного ответа исключает неоднозначный выбор на границе top-k.
Равные частоты внутри выбранной части не мешают: порядок ответа произвольный.

### Код

```js
function topKFrequent(nums, k) {
  const counts = new Map();

  for (const num of nums) {
    counts.set(num, (counts.get(num) ?? 0) + 1);
  }

  const entries = [...counts];
  entries.sort((a, b) => b[1] - a[1]);

  return entries.slice(0, k).map(pair => pair[0]);
}
```

### Трассировка руками

`nums = [4, 4, 4, 6, 6, 7, 7, 7, 7]`, `k = 2`.
После подсчёта: `4 → 3`, `6 → 2`, `7 → 4` — последняя `7` поднимает её частоту до `4`.
Пары до сортировки: `[[4, 3], [6, 2], [7, 4]]`.
После сортировки: `[[7, 4], [4, 3], [6, 2]]`.
`slice(0, 2)` берёт две пары, `map` извлекает значения → `[7, 4]`.

### Сложность

- `N` — длина `nums`, `M` — число различных значений, `k` — размер ответа;
  `1 ≤ k ≤ M ≤ N`. Здесь параметр размера ответа — строчная `k`.
- Время: `O(N + M log M)` — подсчёт за `O(N)`, создание пар за `O(M)`,
  сортировка за `O(M log M)`, извлечение ответа за `O(k)`. Последние два линейных
  слагаемых поглощаются общей оценкой; при `M = 1` работу учитывает `O(N)`.
  В худшем случае `M = N`, получаем `O(N log N)`.
- Дополнительная память **без ответа:** `O(M)` для `Map` и массива пар.
  Временный массив от `slice` занимает `O(k)`, что не больше `O(M)`;
  рабочая память сортировки до `O(M)` не меняет итог.
- **Ответ отдельно:** массив из `k` чисел занимает `O(k)`. Вход `nums` не копируется
  и не сортируется; изменяется только локальный массив `entries`.

Оценка предполагает операции `Map` за `O(1)` в среднем и стандартную сортировку
сравнениями за `O(M log M)` с до `O(M)` рабочей памяти. Спецификация JavaScript
не гарантирует конкретную реализацию `sort`.

**Оптимизация без сортировки:** bucket sort раскладывает значения по корзинам,
индекс которых равен частоте (от `1` до `N`). Обход корзин от `N` вниз собирает
ровно `k` значений. Получаем время `O(N)` и дополнительную память `O(N)`
без `O(k)` ответа. Это возможное улучшение, но частоты с сортировкой здесь принимаются.

### Границы и типичные ошибки

- Один элемент при `k = 1` → этот элемент; все значения одинаковы → одно значение.
- При `k = M` нужно вернуть все различные значения, каждое ровно один раз.
  Ноль и отрицательные числа нормально работают как числовые ключи `Map`.
- Пустой `nums`, `k = 0` и `k > M` вне ограничений; отдельную валидацию не добавляем.
- `counts.get(num)` может вернуть `undefined`, поэтому перед сложением нужен `?? 0`.
  `counts[num]` не обращается к записи `Map`.
- `[...counts]` содержит пары: индекс `0` — значение, индекс `1` — частота.
  Сортировка по `b[0] - a[0]` решала бы другую задачу.
- Без компаратора `sort()` сравнивает строковые представления; нужен именно
  `(a, b) => b[1] - a[1]`. При стрелочной функции с `{}` не забудь `return`.
- `slice(0, k)` не включает индекс `k`, поэтому возвращает ровно `k` пар.
  Финальный `map` нужен, чтобы вернуть числа, а не пары или частоты.
