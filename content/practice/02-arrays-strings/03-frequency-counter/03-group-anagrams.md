# Group Anagrams

**Тема:** frequency-counter (Map + составной ключ) · **Сложность:** medium

## Условие
Дан массив строк `strs`. Сгруппируй строки, которые являются **анаграммами** друг друга
(состоят из одних и тех же символов в одинаковом количестве). Верни массив групп.

Порядок групп и порядок строк внутри группы — **любой** (не важен для проверки).

## Примеры
```
Вход:  strs = ["eat", "tea", "tan", "ate", "nat", "bat"]
Выход: [["eat","tea","ate"], ["tan","nat"], ["bat"]]

Вход:  strs = [""]
Выход: [[""]]

Вход:  strs = ["a"]
Выход: [["a"]]
```

## Ограничения
- `1 <= strs.length <= 10^4`
- `0 <= strs[i].length <= 100`
- `strs[i]` состоит из строчных латинских букв.

## 🎯 Цель по сложности
- Время: `O(N * K)` или `O(N * K log K)` (N — число строк, K — макс. длина строки) — зависит
  от того, как строишь ключ (частотная подпись vs сортировка).
- Память: `O(N * K)` — храним все строки в группах.

## 🧠 Ментальная модель (Map с «ключом-подписью»)
Ключевая идея: у всех анаграмм должна быть **одинаковая "подпись" (canonical key)**. Строим
`Map`, где **ключ — подпись**, а **значение — массив строк** с этой подписью.

Два способа получить подпись строки:

1. **Сортировка символов** (проще): `"eat"` → `"aet"`, `"tea"` → `"aet"`. Одинаковая
   отсортированная строка = анаграммы. Ключ = `word.split('').sort().join('')`.
   Стоимость подписи одной строки — `O(K log K)`.

2. **Частотная подпись** (быстрее): посчитать частоты 26 букв и сделать из них строку, напр.
   `"a1e1t1..."` или массив из 26 чисел. Стоимость — `O(K)`, без `log`.

Начни со способа 1 (нагляднее), про способ 2 упомяни вслух как оптимизацию.

Алгоритм:
- для каждой строки посчитай её подпись;
- если подписи ещё нет в Map — заведи пустой массив;
- добавь строку в массив по этой подписи;
- в конце верни все значения Map.

<summary>Решение и объяснение</summary>

### Идея и инвариант

Для каждой строки строим **canonical key** — строку из её отсортированных букв.
У анаграмм такие ключи совпадают: одинаковые буквы в одинаковых количествах после сортировки
дают одну последовательность. Обратно, равные отсортированные строки означают равные
частоты букв, то есть исходные слова — анаграммы.

Инвариант: после обработки первых `i` слов `groups` содержит каждое из этих слов ровно
столько раз, сколько оно встретилось; слова лежат в группе своего ключа. Новое слово
добавляется в существующую группу или создаёт новую. Поэтому после последнего слова
все вхождения распределены правильно, включая дубликаты.

### Код

```js
function groupAnagrams(strs) {
  const groups = new Map();

  for (const word of strs) {
    const key = word.split('').sort().join('');
    if (!groups.has(key)) {
      groups.set(key, []);
    }
    groups.get(key).push(word);
  }

  return [...groups.values()];
}
```

### Трассировка руками

Для `["eat", "", "tea", "eat", ""]`:

1. `"eat"` → ключ `"aet"` → группа `["eat"]`.
2. `""` → ключ `""` → отдельная группа `[""]`.
3. `"tea"` → `"aet"` → `["eat", "tea"]`.
4. Второе `"eat"` → `"aet"` → `["eat", "tea", "eat"]`: дубликат не удаляется.
5. Последнее `""` → `""` → `["", ""]`.

Результат: `[["eat", "tea", "eat"], ["", ""]]`; порядок групп не важен.

### Сложность

- `N` — число слов, `K` — максимальная длина слова, `M` — число групп (`M ≤ N`).
- Обычно время записывают как `O(N * K log K)`: сортируем каждое слово, а `split`,
  `join` и обработка строкового ключа требуют ещё `O(K)`.
  Для пустых и односимвольных слов эта запись скрывает обязательную обработку каждого
  слова. Универсальная оценка — `O(N * (1 + K log(K + 1)))`: при `K = 0` или `K = 1`
  она даёт `O(N)`, а не ноль.
- Дополнительная память **без результата**: до `O(M * (K + 1) + K)` для ключей,
  записей `Map` и временного массива букв. Более простая верхняя граница —
  `O(N * (K + 1))`; `+1` учитывает записи даже для пустых слов.
- **Результат отдельно:** `O(N)` ссылок на исходные строки и `O(M)` массивов групп
  и ссылок внешнего массива, итого `O(N)`. Исходные строки в группах не копируются;
  новые строки создаются для ключей. Массивы групп в `Map` — те же массивы,
  которые попадут в ответ: не считаем их дважды.

Это стандартная модель: доступ к `Map` в среднем константный после обработки ключа,
сортировка слова длины `L` — `O(L log L)` с до `O(L)` рабочей памяти.
Спецификация JavaScript не фиксирует алгоритм и сложность `sort`.
Алфавит из 26 букв не ограничивает длину слова или отсортированного ключа числом 26.
Частотная подпись из 26 счётчиков, сериализованная в строку с разделителями, позволяет
убрать сортировку и получить время `O(N * (K + 1))`.

### Границы и типичные ошибки

- `[""]` → `[[""]]`; `["", ""]` → `[["", ""]]`; одинаковые слова сохраняются все.
  При отсутствии анаграмм каждое слово образует отдельную группу.
- Пустой входной массив не входит в ограничения; этот код вернёт для него `[]`.
- Ключ должен быть **строкой**: без `join('')` получатся разные объекты-массивы.
  `Map` сравнивает массивы по ссылке, а не по содержимому.
- `groups.values()` возвращает итератор, не массив. Spread `[...groups.values()]`
  материализует результат; скобки вызова `()` обязательны.
- `[...groups]` вернул бы пары `[ключ, группа]`, а не нужные группы.
- `push` возвращает длину массива: нельзя записывать её обратно вместо группы.
  `set(key, [])` вызывается только для нового ключа, иначе уже собранные слова потеряются.
- У строки нет метода `sort`: сортируем массив после `split`. Для одиночных строчных
  латинских букв стандартный порядок `sort()` подходит. Исходный `strs` не изменяется.
