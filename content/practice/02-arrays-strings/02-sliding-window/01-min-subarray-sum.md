# Minimum Size Subarray Sum

**Тема:** sliding-window (dynamic) · **Сложность:** medium

## Условие

Дан массив **положительных** чисел `nums` и число `target`.
Найди **длину самого короткого** непрерывного подмассива, сумма которого **≥ `target`**.

Если такого подмассива нет — верни `0`.

## Примеры

```
Вход:  target = 7, nums = [2, 3, 1, 2, 4, 3]
Выход: 2
Пояснение: подмассив [4, 3] даёт сумму 7 и он самый короткий.

Вход:  target = 4, nums = [1, 4, 4]
Выход: 1
Пояснение: [4] уже даёт сумму ≥ 4.

Вход:  target = 11, nums = [1, 1, 1, 1, 1, 1, 1, 1]
Выход: 0
Пояснение: вся сумма = 8 < 11, ответа нет.
```

## Ограничения

- `1 <= nums.length <= 10^5`
- `1 <= nums[i]` (все числа положительные — это важно для окна!)
- `1 <= target`

## 🎯 Цель по сложности

- Время: `O(N)`
- Память: `O(1)`

> ⚠️ Наивно: перебрать все пары (start, end) и суммировать → `O(N²)`. Скользящее окно решает
> за `O(N)`.

## 🧠 Ментальная модель (dynamic window)

Это **окно переменного размера**:

- `right` расширяет окно вправо, добавляя `nums[right]` к текущей сумме окна;
- как только сумма окна **≥ target** — окно «достаточно большое»: пробуем его **сжать**
  слева (`left++`), обновляя минимальную длину, пока сумма не станет `< target`;
- так на каждом шаге ищем минимально возможную длину.

Длина окна = `right - left + 1`.

Почему это работает именно с положительными числами: добавление элемента только увеличивает
сумму, удаление — только уменьшает. Значит сжатие/расширение ведут себя предсказуемо.

### Идея и инвариант

`sum` всегда равна сумме текущего окна `[left, right]`.
После добавления правого элемента сжимаем окно, **пока** его сумма не меньше
`target`: сначала учитываем допустимую длину, затем убираем левый элемент.
`best` хранит минимальную длину среди уже рассмотренных допустимых окон.

Ключевая предпосылка — **все числа положительные и `target > 0`**.
Расширение увеличивает сумму, сжатие уменьшает её. Когда сумма стала меньше
`target`, дальнейшее сжатие не поможет. Отброшенное допустимое окно тоже
не понадобится: его будущие расширения будут только длиннее уже учтённого.
Это позволяет двигать обе границы только вперёд.

### Эталонный код

```js
function minSubArrayLen(target, nums) {
  let left = 0;
  let sum = 0;
  let best = Infinity;

  for (let right = 0; right < nums.length; right++) {
    sum += nums[right];

    while (sum >= target) {
      best = Math.min(best, right - left + 1);
      sum -= nums[left];
      left++;
    }
  }

  return best === Infinity ? 0 : best;
}
```

### Трассировка руками

Вход: `target = 7`, `nums = [2, 3, 1, 2, 4, 3]`.

| `right` | Сумма после добавления | Сжатие и результат шага |
| --- | --- | --- |
| 0 | 2 | Не сжимаем; `left = 0`, ответа ещё нет. |
| 1 | 5 | Не сжимаем. |
| 2 | 6 | Не сжимаем. |
| 3 | 8 | Длина `4`, `best = 4`; убираем `2`, получаем `sum = 6`, `left = 1`. |
| 4 | 10 | Длина `4`; убираем `3` → сумма `7`, длина `3`, `best = 3`; убираем `1` → сумма `6`, `left = 3`. |
| 5 — последняя итерация | 9 | Длина `3`; убираем `2` → сумма `7`, окно `[4, 3]`, длина `2`, `best = 2`; убираем `4` → сумма `3`, `left = 5`. |

После последнего сжатия текущее окно уже **не** удовлетворяет условию, но
`best` сохранил допустимый ответ `2`. Возвращать длину текущего окна нельзя.

### Сложность

- Время: `O(N)` — `right` проходит `N` элементов, а `left` за **все**
  выполнения `while` сдвигается не более `N` раз. Вложенность циклов здесь
  не означает `O(N²)`.
- Дополнительная память: `O(1)` — индексы, сумма и лучшая длина.
  Подмассивы не копируются; числовой результат занимает `O(1)`.
- Используется обычная для этих задач модель числовых операций JavaScript
  за `O(1)`; точность сумм предполагается в пределах безопасных целых `Number`.

### Границы и типичные ошибки

- Если один элемент достигает `target`, ответ `1`; если вся сумма меньше —
  `0`. Пустой массив, хотя вне ограничений, тоже даёт `0`.
- Равенство суммы допустимо: условие `>= target`, не `> target`.
- Длина включительного окна — `right - left + 1`; без `+ 1` потеряется элемент.
- Обновляем `best` **до** удаления левого элемента, пока окно допустимо.
  Нужен `while`, не `if`: один правый элемент может позволить несколько сжатий.
- С отрицательными числами этот алгоритм применять нельзя. Например,
  `target = 3`, `[1, -1, 3]`: после удаления `1` сумма станет `2`, сжатие
  остановится, и окно `[3]` будет пропущено. Это другой контракт и другой алгоритм.
- Если наивный перебор пар каждый раз заново суммирует подмассив, он занимает
  `O(N³)` в худшем случае; `O(N²)` получается при накоплении суммы для каждого старта.
