# Best Time to Buy and Sell Stock (I и II)

**Тема:** greedy · **Сложность:** easy · **Приоритет:** 🔴 основная

> ⚠️ Разобрана в теории ([greedy.md](../../../07-dynamic-programming/02-greedy.md)).
> Пиши **по памяти**. Одна из самых частых задач на FE-интервью — и отличный пример того, как
> одно слово в условии меняет решение.

## Условие

**Часть I.** Дан массив `prices`, `prices[i]` — цена акции в день `i`. Разрешена **одна**
покупка и **одна** продажа (продать можно только в день после покупки). Верни максимальную
прибыль; если заработать нельзя — `0`.

**Часть II.** То же, но сделок можно совершать **сколько угодно**. Одновременно можно держать
не более одной акции (перед новой покупкой предыдущую нужно продать).

## Примеры

```
Часть I:
  [7, 1, 5, 3, 6, 4] → 5     // купить за 1, продать за 6
  [7, 6, 4, 3, 1]    → 0     // цены только падают
  [1]                → 0

Часть II:
  [7, 1, 5, 3, 6, 4] → 7     // (5-1) + (6-3)
  [1, 2, 3, 4, 5]    → 4     // (2-1)+(3-2)+(4-3)+(5-4) = 4
  [7, 6, 4, 3, 1]    → 0
```

## Ограничения

- `1 <= prices.length <= 10^5`
- `0 <= prices[i] <= 10^4`

## 🎯 Цель по сложности

- Обе части: время **`O(N)`**, память `O(1)`.
- Наивно (часть I): перебор всех пар `(i, j)` с `i < j` → `O(N²)`, при `10^5` не пройдёт.

## 🧠 Ментальная модель

**Часть I.** Для каждого дня-продажи нужен только **минимум слева от него**. Минимум
поддерживаем одной переменной по ходу прохода.

```
цены:      7    1    5    3    6    4
minPrice:  7    1    1    1    1    1
прибыль:   -    -    4    2    5    3   → max = 5
```

**Часть II.** Раз сделок сколько угодно, любой рост можно «нарезать» на соседние дни. Значит
ответ — **сумма всех положительных разностей соседей**.

```
цены:     7   1   5   3   6   4
разность:  -6  +4  -2  +3  -2
берём:         4       3        → 7
```

## ⚠️ Подводные камни этих задач

1. **Продать нельзя раньше, чем купил.** Проход слева направо гарантирует это автоматически:
   `minPrice` всегда из уже просмотренных дней. Но проговорить надо.
2. **Инициализация.** `maxProfit = 0` (ответ не может быть отрицательным — сделку можно просто
   не совершать), `minPrice = Infinity`. Перепутать эти два старта — типичная ошибка.
3. **Часть II ≠ «купить на минимуме, продать на максимуме».** Проверь `[1, 5, 3, 6]`: ответ
   `4 + 3 = 7`, а не `6 - 1 = 5`.
4. **В части II не нужно искать пары.** Соблазн отслеживать «точку покупки» и «точку продажи»
   приводит к громоздкому коду с багами на плато. Сумма положительных разностей — короче и
   надёжнее.
5. **Массив из одного элемента** → `0` в обеих частях.
6. Задачу иногда просят решить как DP (`dp[i]` = максимальная прибыль до дня `i`) — стоит уметь
   сказать, что жадное решение эквивалентно, но проще.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Часть I — решение</summary>

```js
function maxProfit(prices) {
  let minPrice = Infinity;
  let maxProfit = 0;

  for (const price of prices) {
    if (price < minPrice) {
      minPrice = price;                                    // новый лучший день покупки
    } else {
      maxProfit = Math.max(maxProfit, price - minPrice);   // пробуем продать сегодня
    }
  }

  return maxProfit;
}
```

`else` здесь не обязателен (если `price < minPrice`, то разность отрицательна и `Math.max` её
не возьмёт), но с ним намерение читается яснее: «либо обновляем минимум, либо считаем прибыль».

**Трассировка** `[7, 1, 5, 3, 6, 4]`:

| price | minPrice | price - minPrice | maxProfit |
|:---:|:---:|:---:|:---:|
| 7 | 7 | — | 0 |
| 1 | 1 | — | 0 |
| 5 | 1 | 4 | 4 |
| 3 | 1 | 2 | 4 |
| 6 | 1 | 5 | **5** |
| 4 | 1 | 3 | 5 |

Ответ `5` ✅

**Почему жадность корректна.** Решение «купить по минимальной цене слева» не зависит от будущих
дней — оно не может стать хуже от того, что случится дальше. Значит пересматривать выбор не
придётся, и одного прохода достаточно.

**Сложность:** время `O(N)`, память `O(1)`.

</details>

<details>
<summary>Часть II — решение</summary>

```js
function maxProfitMultiple(prices) {
  let profit = 0;

  for (let i = 1; i < prices.length; i++) {
    if (prices[i] > prices[i - 1]) {
      profit += prices[i] - prices[i - 1];      // забираем каждый рост
    }
  }

  return profit;
}
```

**Почему сумма приростов = максимум.** Любая выгодная сделка «купил в день `a`, продал в день
`b`» даёт прибыль `prices[b] - prices[a]`, что равно **сумме разностей соседних дней** на
отрезке `[a, b]`. Разбив сделку на ежедневные, мы получим ту же прибыль. При этом ежедневный
подход дополнительно позволяет **пропустить** падения, чего одна большая сделка не умеет.
Значит сумма положительных разностей не меньше любой другой стратегии.

**Трассировка** `[7, 1, 5, 3, 6, 4]`: разности `-6, +4, -2, +3, -2` → берём `4 + 3 = 7` ✅

**Сложность:** время `O(N)`, память `O(1)`.

</details>

<details>
<summary>Как это связано с другими темами</summary>

- **Sliding window:** часть I можно описать как окно `[покупка, продажа]`, где левая граница
  двигается на новый минимум. Тот же код.
- **DP:** `dp[i] = max(dp[i-1], prices[i] - minPrice)` — буквально та же формула, просто без
  массива. Полезно назвать: _«жадное решение здесь совпадает с DP, потому что состояние
  сворачивается в одно число»_.
- **Kadane's algorithm** (максимальная сумма подмассива) — родственная задача: если построить
  массив разностей соседних цен, часть I превращается в «максимальную сумму подмассива». Это
  красивое наблюдение, которое стоит уметь озвучить.

**Follow-up, которые могут спросить:**
- «не более `k` сделок» → полноценное 2D-DP;
- «после продажи день обязательного простоя» (Cooldown) → DP с тремя состояниями;
- «с комиссией за сделку» → та же жадность с поправкой на комиссию.

Все они уже DP, а не greedy — граница проходит ровно там, где выбор начинает влиять на будущее.

</details>
