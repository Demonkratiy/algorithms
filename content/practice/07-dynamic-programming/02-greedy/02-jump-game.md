# Jump Game

**Тема:** greedy (достижимость) · **Сложность:** medium · **Приоритет:** 🔴 основная

## Условие

Дан массив неотрицательных чисел `nums`. Ты стоишь на индексе `0`. Значение `nums[i]` — это
**максимальная** длина прыжка из позиции `i` (прыгнуть можно и на меньшее расстояние).

**Часть A.** Верни `true`, если можно достичь последнего индекса.
**Часть B (Jump Game II).** Верни **минимальное число прыжков** до последнего индекса
(гарантируется, что дойти можно).

## Примеры

```
Часть A:
  [2, 3, 1, 1, 4] → true     // 0→1→4
  [3, 2, 1, 0, 4] → false    // застреваем на индексе 3 (значение 0)
  [0]             → true     // уже на месте

Часть B:
  [2, 3, 1, 1, 4] → 2        // прыжок 0→1, затем 1→4
  [2, 3, 0, 1, 4] → 2
```

## Ограничения

- `1 <= nums.length <= 10^4`
- `0 <= nums[i] <= 10^5`

## 🎯 Цель по сложности

- Обе части: время **`O(N)`**, память `O(1)`.
- DP-решение `O(N²)` («для каждой позиции проверить все прыжки») тоже верное, но жадность лучше.

## 🧠 Ментальная модель

**Часть A — отслеживай максимальную достижимую позицию.**

Идём слева направо и храним `maxReach` — самый дальний индекс, куда мы **вообще способны**
допрыгнуть. На позиции `i`:
- если `i > maxReach` — мы сюда не дойдём, дальше идти бессмысленно → `false`;
- иначе обновляем `maxReach = Math.max(maxReach, i + nums[i])`.

```
[2, 3, 1, 1, 4]
 i=0: maxReach = 0+2 = 2
 i=1: 1 <= 2 ✓, maxReach = max(2, 1+3) = 4  → уже покрывает конец
```

**Часть B — «уровни», как в BFS.** Прыжки образуют слои: за 1 прыжок достижим один диапазон
индексов, за 2 — следующий и т.д. Держим границу текущего слоя (`currentEnd`) и максимальную
достижимость из него (`farthest`). Дойдя до границы, увеличиваем счётчик прыжков.

## ⚠️ Подводные камни этих задач

1. **Часть A: нули — не всегда тупик.** `[2, 0, 1]` проходима: прыжок из `0` перелетает через
   ноль. Нельзя просто «искать нули» — нужна именно `maxReach`.
2. **Ранний выход.** Проверка `i > maxReach` должна стоять **в начале** итерации, до обновления
   `maxReach`. Иначе учтёшь недостижимую позицию и получишь `true` там, где `false`
   (проверь на `[3,2,1,0,4]`).
3. **Часть B: не увеличивать счётчик на каждом шаге.** Прыжок засчитывается только при
   **достижении границы текущего слоя**, а не на каждой позиции.
4. **Часть B: цикл идёт до `n - 1` (не включая последний индекс).** Если дойти до последнего
   элемента и там пересечь границу, посчитаешь лишний прыжок.
5. **Массив из одного элемента** → `true` / `0` прыжков. Не забудь этот случай.
6. Значения могут быть большими (`i + nums[i]` вылетает далеко за массив) — это нормально,
   сравнения всё равно работают.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Часть A — решение</summary>

```js
function canJump(nums) {
  let maxReach = 0;

  for (let i = 0; i < nums.length; i++) {
    if (i > maxReach) return false;                    // сюда не допрыгнуть
    maxReach = Math.max(maxReach, i + nums[i]);
    if (maxReach >= nums.length - 1) return true;      // конец уже покрыт
  }

  return true;
}
```

**Трассировка** `[3, 2, 1, 0, 4]` (ответ `false`):

| i | nums[i] | i > maxReach? | maxReach после |
|:-:|:---:|:---:|:---:|
| 0 | 3 | нет | 3 |
| 1 | 2 | нет | 3 |
| 2 | 1 | нет | 3 |
| 3 | 0 | нет | 3 |
| 4 | 4 | **4 > 3 → false** ✅ | |

**Трассировка** `[2, 0, 1]` (ответ `true`, несмотря на ноль):
`i=0` → `maxReach = 2` → сразу `2 >= 2` → **true** ✅ Ноль перепрыгнут.

**Почему жадность корректна.** Если позиция `i` достижима, то достижимы и все позиции до неё
(можно прыгать короче). Поэтому достаточно знать одну величину — самый дальний достижимый
индекс. Локальный выбор «прыгать максимально далеко» ничего не портит.

**Сложность:** время `O(N)`, память `O(1)`.

</details>

<details>
<summary>Часть B — минимальное число прыжков</summary>

```js
function jump(nums) {
  let jumps = 0;
  let currentEnd = 0;      // граница зоны, достижимой за `jumps` прыжков
  let farthest = 0;        // самая дальняя точка, достижимая из текущей зоны

  for (let i = 0; i < nums.length - 1; i++) {      // до предпоследнего!
    farthest = Math.max(farthest, i + nums[i]);

    if (i === currentEnd) {                        // исчерпали текущий слой
      jumps++;
      currentEnd = farthest;                       // переходим на следующий
    }
  }

  return jumps;
}
```

**Трассировка** `[2, 3, 1, 1, 4]`:

| i | nums[i] | farthest | i === currentEnd? | jumps | currentEnd |
|:-:|:---:|:---:|:---:|:---:|:---:|
| 0 | 2 | 2 | да (0 === 0) | 1 | 2 |
| 1 | 3 | 4 | нет | 1 | 2 |
| 2 | 1 | 4 | да (2 === 2) | 2 | 4 |
| 3 | 1 | 4 | нет | 2 | 4 |

Цикл закончился (`i < 4`), ответ **2** ✅

**Почему цикл до `n - 1`.** Если бы он дошёл до последнего индекса и там сработало
`i === currentEnd`, мы бы засчитали ещё один прыжок — уже находясь на финише. Проверь на
`[1, 1]`: с правильным циклом ответ `1`, с неправильным `2`.

**Аналогия с BFS.** `currentEnd` — граница уровня, `jumps` — номер уровня. Это тот же приём
`levelSize` из [обхода дерева по уровням](../../05-recursion-trees/02-binary-trees/03-level-order.md),
только границы заданы числами, а не размером очереди.

**Сложность:** время `O(N)`, память `O(1)`.

</details>

<details>
<summary>DP-решение для сравнения (O(N²))</summary>

```js
function canJumpDP(nums) {
  const n = nums.length;
  const reachable = new Array(n).fill(false);
  reachable[0] = true;

  for (let i = 0; i < n; i++) {
    if (!reachable[i]) continue;
    for (let step = 1; step <= nums[i] && i + step < n; step++) {
      reachable[i + step] = true;
    }
  }

  return reachable[n - 1];
}
```

Верно, но `O(N²)` по времени и `O(N)` по памяти. Полезно как первый ответ на интервью
(«вижу DP-решение за O(N²)»), после которого ты предлагаешь жадность за `O(N)`/`O(1)`.
Такое сравнение — сильный ход: показывает, что ты **осознанно** выбрал жадный подход.

</details>
