# Unique Paths (двумерное DP)

**Тема:** dp на сетке · **Сложность:** medium · **Приоритет:** ⚪ дополнительная

> Первое **двумерное** DP. Показывает, что состояние может иметь два параметра, и знакомит с
> оптимизацией «двумерная таблица → одна строка».

## Условие

Робот стоит в левом верхнем углу сетки `m × n`. Он может двигаться только **вправо** или
**вниз**. Сколько существует различных путей до правого нижнего угла?

**Часть B (обязательно попробуй):** то же, но некоторые клетки — препятствия (`1` в сетке
`obstacleGrid`), через них проходить нельзя.

## Примеры

```
m = 3, n = 7   → 28
m = 3, n = 2   → 3
   □ □          пути: ↓↓→, ↓→↓, →↓↓
   □ □
   □ □
m = 1, n = 1   → 1

Часть B:
[[0,0,0],
 [0,1,0],     → 2
 [0,0,0]]
```

## Ограничения

- `1 <= m, n <= 100`
- ответ гарантированно помещается в 32-битное целое.

## 🎯 Цель по сложности

- Время `O(m · n)`, память `O(m · n)` таблицей и **`O(n)`** после оптимизации.
- Есть и `O(1)`-решение через комбинаторику (см. последний спойлер).

## 🧠 Ментальная модель

**Состояние.** `dp[r][c]` = число путей от старта до клетки `(r, c)`.

**Переход.** В клетку `(r, c)` можно попасть только сверху или слева, и эти множества путей не
пересекаются:

```
dp[r][c] = dp[r-1][c] + dp[r][c-1]
```

**База.** Вся верхняя строка и весь левый столбец — по `1` пути (идти можно только прямо).

```
1  1  1  1
1  2  3  4
1  3  6  10
```

Знакомая картинка? Это треугольник Паскаля, развёрнутый в сетку.

## ⚠️ Подводные камни именно этой задачи

1. **Создание двумерного массива.** `new Array(m).fill(new Array(n).fill(0))` создаст `m` ссылок
   на **одну** строку — изменение в одной строке отразится во всех.
   Правильно: `Array.from({ length: m }, () => new Array(n).fill(0))`.
2. **База — вся первая строка и первый столбец**, а не только `dp[0][0]`. Пропустишь — получишь
   нули.
3. **Складываем, а не берём максимум** — вопрос «сколько путей».
4. **Часть B:** препятствие обнуляет клетку (`dp[r][c] = 0`), и это правильно — через неё
   не проходит ни один путь. Отдельный подводный камень: **препятствие в стартовой или финишной
   клетке** → ответ `0`.
5. **Часть B, первая строка/столбец:** после препятствия все клетки строки становятся
   недостижимыми — нельзя слепо заполнять их единицами.
6. `m = 1` или `n = 1` → ровно `1` путь.

<summary>Подсказка 1 — состояние и база</summary>

`dp[r][c]` — число путей до клетки. Первая строка и первый столбец заполняются единицами.

</details>

<details>
<summary>Подсказка 2 — оптимизация памяти</summary>

Переход смотрит только на клетку сверху и слева. Значит достаточно **одной строки**, которую
обновляем на месте: `row[c] += row[c - 1]` (где `row[c]` до присваивания — это «сверху», а
`row[c-1]` — «слева»).

</details>

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Часть A — таблица + оптимизация</summary>

```js
function uniquePaths(m, n) {
  const dp = Array.from({ length: m }, () => new Array(n).fill(1));   // база сразу единицами

  for (let r = 1; r < m; r++) {
    for (let c = 1; c < n; c++) {
      dp[r][c] = dp[r - 1][c] + dp[r][c - 1];
    }
  }

  return dp[m - 1][n - 1];
}
```

Инициализация единицами удобно закрывает базу: первая строка и первый столбец остаются
нетронутыми, а циклы начинаются с `1`.

**Оптимизация до `O(n)` памяти:**

```js
function uniquePathsOptimized(m, n) {
  const row = new Array(n).fill(1);       // первая строка

  for (let r = 1; r < m; r++) {
    for (let c = 1; c < n; c++) {
      row[c] += row[c - 1];               // row[c] — "сверху", row[c-1] — "слева"
    }
  }

  return row[n - 1];
}
```

**Почему это работает.** В момент вычисления `row[c]` в нём ещё лежит значение из
**предыдущей строки** (то есть «сверху»), а `row[c - 1]` уже обновлён в этой строке
(«слева»). Одна строка играет обе роли — приём «прокатки» (rolling array), он применяется во
многих 2D-DP.

**Трассировка** `m = 3, n = 3`:
```
старт:      [1, 1, 1]
после r=1:  [1, 2, 3]
после r=2:  [1, 3, 6]   → ответ 6
```

**Сложность:** время `O(m · n)`, память `O(n)`.

</details>

<details>
<summary>Часть B — с препятствиями</summary>

```js
function uniquePathsWithObstacles(obstacleGrid) {
  const m = obstacleGrid.length;
  const n = obstacleGrid[0].length;

  if (obstacleGrid[0][0] === 1) return 0;          // старт заблокирован

  const row = new Array(n).fill(0);
  row[0] = 1;                                       // единственная стартовая клетка

  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) {
      if (obstacleGrid[r][c] === 1) {
        row[c] = 0;                                 // сюда не дойти
      } else if (c > 0) {
        row[c] += row[c - 1];
      }
      // при c === 0 и без препятствия row[0] остаётся прежним — это путь "только вниз"
    }
  }

  return row[n - 1];
}
```

**Трассировка** для
```
[[0,0,0],
 [0,1,0],
 [0,0,0]]
```
```
r=0: [1, 1, 1]
r=1: [1, 0, 1]     ← препятствие обнулило середину
r=2: [1, 1, 2]     → ответ 2 ✅
```

Обрати внимание на строку `r=1`: обнулённая клетка «отрезала» часть путей, и это распространилось
дальше автоматически — никаких особых веток не потребовалось.

**Сложность:** время `O(m · n)`, память `O(n)`.

</details>

<details>
<summary>Бонус: решение за O(1) через комбинаторику</summary>

Любой путь — это последовательность из `(m - 1)` шагов вниз и `(n - 1)` шагов вправо, всего
`m + n - 2` шагов. Ответ — число способов выбрать, какие из них будут «вниз»:

$$C(m+n-2,\ m-1) = \frac{(m+n-2)!}{(m-1)!\,(n-1)!}$$

```js
function uniquePathsMath(m, n) {
  let result = 1;
  for (let i = 1; i <= m - 1; i++) {
    result = result * (n - 1 + i) / i;     // считаем по одному множителю, чтобы не переполнить
  }
  return Math.round(result);
}
```

`O(min(m, n))` времени, `O(1)` памяти. Красиво, но **работает только без препятствий** —
хороший повод сказать интервьюеру: _«для базовой версии есть формула, но DP-решение обобщается
на препятствия, поэтому предпочту его»_. Такое сравнение подходов ценится.

</details>
