# Climbing Stairs

**Тема:** dp (вход в тему) · **Сложность:** easy · **Приоритет:** 🔴 основная

> Самая правильная первая задача по DP: здесь виден весь путь «перебор → мемоизация → таблица →
> `O(1)` памяти» на предельно простом сюжете.

## Условие

Лестница из `n` ступенек. За один шаг можно подняться на **1 или 2** ступеньки.
Сколькими различными способами можно добраться до вершины?

## Примеры

```
n = 2  → 2      // (1+1), (2)
n = 3  → 3      // (1+1+1), (1+2), (2+1)
n = 4  → 5
n = 1  → 1
```

## Ограничения

- `1 <= n <= 45`

## 🎯 Цель по сложности

- Наивная рекурсия: `O(2^N)` — при `n = 45` не досчитается.
- С мемоизацией / таблицей: `O(N)` время, `O(N)` память.
- Оптимально: `O(N)` время, **`O(1)`** память.

## 🧠 Ментальная модель

Идём **от конца**: чтобы оказаться на ступеньке `n`, мы пришли либо с `n-1` (шагом на 1), либо с
`n-2` (шагом на 2). Других вариантов нет, и эти множества способов не пересекаются, значит:

```
ways(n) = ways(n - 1) + ways(n - 2)
```

Это Фибоначчи — но **важно не узнать его, а вывести**. Умение сказать «последний шаг был либо
таким, либо таким» — универсальный приём поиска перехода в DP.

**4 шага:**
- состояние: `dp[i]` = число способов дойти до ступеньки `i`;
- переход: `dp[i] = dp[i-1] + dp[i-2]`;
- база: `dp[1] = 1`, `dp[2] = 2`;
- порядок: слева направо.

## ⚠️ Подводные камни именно этой задачи

1. **База `dp[2] = 2`, а не `1`.** Это отличает задачу от классического Фибоначчи, где
   `F(2) = 1`. Если взять «фибоначчиевую» базу, все ответы сдвинутся на единицу.
   Проверяй базу **перебором вручную** для `n = 1, 2, 3`.
2. **Складываем, а не берём максимум.** Вопрос «сколько способов» → сумма. Вопрос «какая
   максимальная сумма» → `Math.max`. Перепутать легко, если писать «на автомате».
3. **Без мемоизации `n = 45` не посчитается** — примерно `2^45` вызовов. Обязательно назови
   сложность наивной версии, прежде чем оптимизировать.
4. **`n = 1`** — единственный ответ `1`; проверь, что цикл не выполняется и код не падает.
5. При `O(1)`-версии обмен переменных делай деструктуризацией, иначе потеряешь `prev`.

## 💡 Подсказки (открывай по очереди)

<details>
<summary>Подсказка 1 — найди переход</summary>

Спроси: «каким был **последний** шаг?» Их всего два варианта — с `n-1` или с `n-2`.
Значит способы складываются.

</details>

<details>
<summary>Подсказка 2 — проверь базу руками</summary>

`n = 1`: `[1]` → 1 способ. `n = 2`: `[1,1]`, `[2]` → 2 способа. `n = 3`: `[1,1,1]`, `[1,2]`,
`[2,1]` → 3 = 1 + 2 ✅

</details>

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Все три версии + объяснение</summary>

```js
// 1. TOP-DOWN: O(N) время, O(N) память (кеш + стек)
function climbStairsMemo(n, memo = new Map()) {
  if (n <= 2) return n;                            // база: 1 → 1, 2 → 2
  if (memo.has(n)) return memo.get(n);

  const result = climbStairsMemo(n - 1, memo) + climbStairsMemo(n - 2, memo);
  memo.set(n, result);
  return result;
}

// 2. BOTTOM-UP: O(N) время, O(N) память
function climbStairsTable(n) {
  if (n <= 2) return n;

  const dp = new Array(n + 1);
  dp[1] = 1;
  dp[2] = 2;

  for (let i = 3; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
  }

  return dp[n];
}

// 3. ОПТИМИЗИРОВАННО: O(N) время, O(1) память
function climbStairs(n) {
  if (n <= 2) return n;

  let prev = 1;     // dp[i - 2]
  let curr = 2;     // dp[i - 1]

  for (let i = 3; i <= n; i++) {
    [prev, curr] = [curr, prev + curr];
  }

  return curr;
}
```

**Трассировка** третьей версии для `n = 5`:

| i | prev | curr | после шага |
|:-:|:----:|:----:|---|
| старт | 1 | 2 | |
| 3 | 2 | 3 | `[2, 1+2]` |
| 4 | 3 | 5 | `[3, 2+3]` |
| 5 | 5 | 8 | `[5, 3+5]` |

Ответ `8` ✅ (проверь: `n=4 → 5`, `n=5 → 8`)

**Почему `O(1)` память возможна.** Переход `dp[i] = dp[i-1] + dp[i-2]` смотрит только на два
предыдущих значения — вся остальная таблица никогда больше не понадобится. Это общее правило:
**если переход зависит от `k` последних состояний, хватит `k` переменных.**

</details>

<details>
<summary>Почему наивная версия — O(2^N)</summary>

```js
function climbNaive(n) {
  if (n <= 2) return n;
  return climbNaive(n - 1) + climbNaive(n - 2);
}
```

Дерево вызовов ветвится надвое на каждом уровне, глубина `N` → около `2^N` вызовов.
`climbNaive(45)` — это ~`3.5 · 10^13` операций.

Дерево для `n = 5` (видно повторы):
```
                 f(5)
            /           \
        f(4)             f(3)
       /    \           /    \
    f(3)    f(2)     f(2)    f(1)
   /   \
f(2)  f(1)
```
`f(3)` считается дважды, `f(2)` — трижды. Мемоизация убирает все повторы.

</details>

<details>
<summary>Вариации, которые могут спросить следом</summary>

- **«А если шаг может быть 1, 2 или 3?»** → `dp[i] = dp[i-1] + dp[i-2] + dp[i-3]`, база на три
  значения. Обобщение: шаги из массива `steps` → `dp[i] = Σ dp[i - s]` для всех допустимых `s`.
- **«У каждой ступеньки есть стоимость, минимизируй затраты»** → Min Cost Climbing Stairs:
  вместо суммы `Math.min`, вместо «сколько способов» — «какая минимальная стоимость».
- **«Нельзя наступать на сломанные ступеньки»** → пропускаем их: `dp[i] = 0`.

Обрати внимание: меняется **операция комбинирования** (сумма / минимум / максимум), а каркас
остаётся тем же. Это и есть понимание DP.

</details>
