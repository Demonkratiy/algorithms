# Coin Change II — число комбинаций

**Тема:** dp / подсчёт способов · **Сложность:** medium · **Приоритет:** ⚪ дополнительная

## Условие

Реализуй `change(amount, coins)`: посчитай число комбинаций монет, дающих сумму `amount`. Монет каждого номинала неограниченно; **порядок не важен**. Это не минимальное число монет из [Coin Change](03-coin-change.md).

Номиналы — различные положительные целые числа; `amount` — неотрицательное целое. Для практики `amount <= 5000`, `coins.length <= 100`; все промежуточные количества помещаются в безопасное целое JS. Пустой список номиналов допустим.

Примеры: `change(5, [1,2,5]) → 4`, `change(3, [2]) → 0`, `change(0, []) → 1`, `change(4, []) → 0`.

## 🎯 Цель по сложности

Время `O(A · C + A + C)`, где `A = amount`, `C = coins.length` (обычно говорят `O(A · C)` для ненулевых A/C); память `O(A)` для таблицы.

## 🧠 Ментальная модель

Состояние — число способов, а не минимум. Нулевую сумму можно получить одним способом: не брать ничего. Порядок обработки номиналов должен исключать повторный подсчёт перестановок.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Важный родственник: Coin Change II (число комбинаций)</summary>

Другой вопрос: **сколькими способами** набрать сумму (порядок монет не важен)?

```js
function change(amount, coins) {
  const dp = new Array(amount + 1).fill(0);
  dp[0] = 1;                                   // один способ набрать 0 — не брать ничего

  for (const coin of coins) {                  // ВНЕШНИЙ цикл — по монетам!
    for (let sum = coin; sum <= amount; sum++) {
      dp[sum] += dp[sum - coin];
    }
  }

  return dp[amount];
}
```

Два отличия, оба принципиальные:
- база `dp[0] = 1` (один способ), а не `0`, и операция — **сложение**, а не минимум;
- **порядок циклов перевёрнут**: монеты снаружи, суммы внутри.

Если поменять циклы местами, будут считаться **перестановки** (`1+2` и `2+1` как разные), а не
комбинации. Это классический вопрос на понимание: _«почему здесь монеты во внешнем цикле?»_

</details>
