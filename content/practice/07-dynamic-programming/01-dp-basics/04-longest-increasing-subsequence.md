# Longest Increasing Subsequence (LIS)

**Тема:** dp (`O(N²)`) + бонус binary search (`O(N log N)`) · **Сложность:** medium · **Приоритет:** ⚪ дополнительная

## Условие

Дан массив `nums`. Верни длину самой длинной **строго возрастающей подпоследовательности**.

**Подпоследовательность** — элементы, взятые в исходном порядке, но **не обязательно подряд**
(в отличие от подмассива).

## Примеры

```
Вход:  [10, 9, 2, 5, 3, 7, 101, 18]
Выход: 4        // [2, 3, 7, 101] или [2, 3, 7, 18]

Вход:  [0, 1, 0, 3, 2, 3]
Выход: 4        // [0, 1, 2, 3]

Вход:  [7, 7, 7, 7]
Выход: 1        // строго возрастающая, равные не считаются

Вход:  [5]
Выход: 1
```

## Ограничения

- `1 <= nums.length <= 2500`
- `-10^4 <= nums[i] <= 10^4`

## 🎯 Цель по сложности

- DP: **`O(N²)`** время, `O(N)` память — это ожидаемый ответ.
- Продвинуто: **`O(N log N)`** через «терпеливую раскладку» + бинарный поиск.

## 🧠 Ментальная модель

**Состояние.** `dp[i]` = длина самой длинной возрастающей подпоследовательности, которая
**заканчивается ровно на элементе `i`**.

Это важная тонкость: не «в первых `i` элементах», а **«заканчивается на `i`»**. Иначе переход
не построить — нужно знать, какое значение стоит последним.

**Переход.** Смотрим на все предыдущие `j < i`. Если `nums[j] < nums[i]`, к их
последовательности можно приписать текущий элемент:

```
dp[i] = 1 + max( dp[j] )  по всем j < i, где nums[j] < nums[i]
dp[i] = 1,                если таких j нет
```

**Ответ** — `max(dp)`, а **не** `dp[n-1]`: самая длинная подпоследовательность может
заканчиваться где угодно.

## ⚠️ Подводные камни именно этой задачи

1. **Ответ — максимум по всему массиву `dp`**, а не последний элемент. Проверь на
   `[1, 2, 3, 0]`: `dp = [1, 2, 3, 1]`, ответ `3`, а `dp[3] = 1`. Самая частая ошибка.
2. **Подпоследовательность ≠ подмассив.** Элементы не обязаны идти подряд, поэтому sliding
   window здесь не применим.
3. **Строгое возрастание.** Условие `nums[j] < nums[i]`, а не `<=`. На `[7,7,7,7]` ответ `1`.
4. **Инициализация `dp` единицами** — каждый элемент сам по себе уже подпоследовательность
   длины 1. Ноль даст ответ на единицу меньше.
5. Массив из одного элемента → `1`. Пустой (по ограничениям не встречается) → `0`.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>DP-решение O(N²) + объяснение</summary>

```js
function lengthOfLIS(nums) {
  const n = nums.length;
  const dp = new Array(n).fill(1);      // каждый элемент — LIS длины 1

  for (let i = 1; i < n; i++) {
    for (let j = 0; j < i; j++) {
      if (nums[j] < nums[i]) {          // строго меньше
        dp[i] = Math.max(dp[i], dp[j] + 1);
      }
    }
  }

  return Math.max(...dp);
}
```

**Трассировка** `[10, 9, 2, 5, 3, 7, 101, 18]`:

| i | nums[i] | подходящие j (nums[j] < nums[i]) | dp[i] |
|:-:|:-------:|---|:-----:|
| 0 | 10 | — | 1 |
| 1 | 9 | — | 1 |
| 2 | 2 | — | 1 |
| 3 | 5 | 2 (значение 2) | 2 |
| 4 | 3 | 2 | 2 |
| 5 | 7 | 2, 5, 3 → лучший `dp = 2` | 3 |
| 6 | 101 | все → лучший `dp = 3` | 4 |
| 7 | 18 | 10,9,2,5,3,7 → лучший `dp = 3` | 4 |

`dp = [1,1,1,2,2,3,4,4]`, максимум **4** ✅

**Сложность:** время `O(N²)` — двойной цикл. Память `O(N)`.

⚠️ `Math.max(...dp)` со спредом на массиве в сотни тысяч элементов даст `RangeError`.
Здесь `N ≤ 2500` — безопасно, но привыкай к альтернативе:
```js
let best = 0;
for (const value of dp) best = Math.max(best, value);
```

</details>

<details>
<summary>Бонус: O(N log N) через бинарный поиск</summary>

```js
function lengthOfLISFast(nums) {
  const tails = [];        // tails[k] — минимальный возможный "хвост" LIS длины k+1

  for (const num of nums) {
    // ищем первую позицию, где tails[pos] >= num  (lower bound)
    let left = 0;
    let right = tails.length;
    while (left < right) {
      const mid = Math.floor((left + right) / 2);
      if (tails[mid] >= num) right = mid;
      else left = mid + 1;
    }

    if (left === tails.length) tails.push(num);   // num больше всех — удлиняем
    else tails[left] = num;                        // иначе улучшаем хвост
  }

  return tails.length;
}
```

**Что такое `tails`.** Это **не** сама подпоследовательность! `tails[k]` — минимальное значение,
которым может заканчиваться возрастающая подпоследовательность длины `k + 1`. Массив всегда
отсортирован по возрастанию — поэтому применим бинарный поиск.

Интуиция: чем меньше «хвост», тем больше шансов продолжить последовательность дальше. Поэтому
каждый новый элемент либо удлиняет цепочку, либо делает существующий хвост меньше.

**Трассировка** `[10, 9, 2, 5, 3, 7]`:
```
10 → tails = [10]
 9 → заменяет 10   → [9]
 2 → заменяет 9    → [2]
 5 → больше всех   → [2, 5]
 3 → заменяет 5    → [2, 3]
 7 → больше всех   → [2, 3, 7]
```
Длина `3` ✅ (при этом `[2,3,7]` здесь случайно совпала с реальной LIS — в общем случае
содержимое `tails` не является ответом, **только его длина**).

**Сложность:** `O(N log N)` время, `O(N)` память. Внутри — шаблон **lower bound** из
[Search Insert Position](../../04-search-sort/01-binary-search/02-search-insert-position.md).

На интервью достаточно назвать этот подход и объяснить идею; писать его целиком просят редко.

</details>

<details>
<summary>Семейство задач</summary>

Тот же каркас `dp[i]` = «ответ для последовательности, заканчивающейся на `i`»:

- **Longest Increasing Subsequence** — эта задача;
- **Number of LIS** — считать не только длину, но и количество;
- **Russian Doll Envelopes** — сортировка + LIS по второму измерению;
- **Longest Chain of Pairs**;
- **Maximum Sum Increasing Subsequence** — вместо `+1` прибавляем значение.

Признак: «подпоследовательность» (не подмассив!) + «самая длинная/лучшая».

</details>
