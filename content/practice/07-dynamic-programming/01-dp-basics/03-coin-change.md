# Coin Change

**Тема:** dp по сумме (минимизация) · **Сложность:** medium · **Приоритет:** 🔴 основная

> Самая важная DP-задача для интервью после House Robber. Здесь состояние — не индекс массива,
> а **сумма**; и здесь наглядно ломается жадность.

## Условие

Дан массив номиналов монет `coins` и целевая сумма `amount`.
Верни **минимальное количество монет**, которыми можно набрать `amount`.
Если набрать невозможно — верни `-1`.

Монет каждого номинала **неограниченно много**.

## Примеры

```
Вход:  coins = [1, 2, 5], amount = 11
Выход: 3        // 5 + 5 + 1

Вход:  coins = [2], amount = 3
Выход: -1

Вход:  coins = [1], amount = 0
Выход: 0        // ноль монет

Вход:  coins = [1, 3, 4], amount = 6
Выход: 2        // 3 + 3   ← жадность даст 3 монеты (4+1+1)
```

## Ограничения

- `1 <= coins.length <= 12`, `1 <= coins[i] <= 2^31 - 1`
- `0 <= amount <= 10^4`

## 🎯 Цель по сложности

- Время **`O(amount · C)`**, где `C` — количество номиналов. Память `O(amount)`.
- Перебор всех комбинаций — экспонента, не проходит.

## 🧠 Ментальная модель

**Состояние — сумма, а не индекс.** `dp[s]` = минимальное число монет, чтобы набрать сумму `s`.

**Переход.** Чтобы набрать `s`, последняя положенная монета была какой-то из `coins`. Если это
монета номинала `c`, то до неё была набрана сумма `s - c`:

```
dp[s] = 1 + min( dp[s - c] )  по всем монетам c, для которых s - c >= 0
```

**База.** `dp[0] = 0` — пустую сумму набирают нулём монет.

**Недостижимость.** Все ячейки инициализируем `Infinity`; если в конце `dp[amount]` так и остался
`Infinity` — набрать нельзя, возвращаем `-1`.

```
coins = [1,2,5]
s:     0  1  2  3  4  5  6 ...
dp:    0  1  1  2  2  1  2 ...
```

## ⚠️ Подводные камни именно этой задачи

1. **Жадность здесь неверна.** `coins = [1, 3, 4]`, `amount = 6`: жадно `4 + 1 + 1 = 3` монеты,
   оптимум `3 + 3 = 2`. Обязательно проговори этот контрпример на интервью — он показывает,
   что ты **проверил** применимость жадности, а не просто выбрал DP наугад.
2. **Инициализация `Infinity`, а не `0`.** Задача на **минимум**: нули заставят алгоритм считать
   любую сумму достижимой нулём монет. (Сравни с House Robber, где база `0` корректна, потому
   что там максимум.)
3. **`Infinity + 1 === Infinity`** — это удобно: недостижимые состояния не «портят» соседей.
   Но не забудь финальную проверку `dp[amount] === Infinity → -1`.
4. **Проверка `s - coin >= 0`** обязательна, иначе обратишься к отрицательному индексу и
   получишь `undefined` → `NaN`, который тихо распространится по всей таблице.
5. **`amount = 0` → ответ `0`**, а не `-1`. База это обеспечивает автоматически, но проверь.
6. **Порядок циклов.** Внешний — по суммам, внутренний — по монетам. При обратном порядке
   решение тоже работает **для этой задачи**, но для «числа комбинаций» порядок принципиален
   (см. последний спойлер) — привыкай думать о нём.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function coinChange(coins, amount) {
  const dp = new Array(amount + 1).fill(Infinity);
  dp[0] = 0;                                     // база: сумму 0 набираем нулём монет

  for (let sum = 1; sum <= amount; sum++) {
    for (const coin of coins) {
      if (coin > sum) continue;                  // монета не помещается
      dp[sum] = Math.min(dp[sum], dp[sum - coin] + 1);
    }
  }

  return dp[amount] === Infinity ? -1 : dp[amount];
}
```

**Трассировка** `coins = [1, 3, 4]`, `amount = 6`:

| sum | кандидаты `dp[sum-coin] + 1` | dp[sum] |
|:---:|---|:---:|
| 0 | — | 0 |
| 1 | `dp[0]+1 = 1` | 1 |
| 2 | `dp[1]+1 = 2` | 2 |
| 3 | `dp[2]+1 = 3`, `dp[0]+1 = 1` | **1** |
| 4 | `dp[3]+1 = 2`, `dp[1]+1 = 2`, `dp[0]+1 = 1` | **1** |
| 5 | `dp[4]+1 = 2`, `dp[2]+1 = 3`, `dp[1]+1 = 2` | **2** |
| 6 | `dp[5]+1 = 3`, `dp[3]+1 = 2`, `dp[2]+1 = 3` | **2** ✅ |

Ответ `2` (`3 + 3`) — DP нашёл то, что жадность пропустила.

**Проверка `-1`:** `coins = [2]`, `amount = 3`. `dp[1]` останется `Infinity` (двойка не
помещается), значит `dp[3] = dp[1] + 1 = Infinity` → возвращаем `-1` ✅
Заметь, как `Infinity + 1 === Infinity` избавляет от лишних `if`.

**Сложность:** время `O(amount · C)` — два вложенных цикла. Память `O(amount)`.

</details>

<details>
<summary>Top-down версия (если так думать привычнее)</summary>

```js
function coinChangeMemo(coins, amount) {
  const memo = new Map();

  function minCoins(rest) {
    if (rest === 0) return 0;
    if (rest < 0) return Infinity;
    if (memo.has(rest)) return memo.get(rest);

    let best = Infinity;
    for (const coin of coins) {
      best = Math.min(best, minCoins(rest - coin) + 1);
    }

    memo.set(rest, best);
    return best;
  }

  const result = minCoins(amount);
  return result === Infinity ? -1 : result;
}
```

Та же сложность. Плюс: считает только реально нужные состояния. Минус: глубина рекурсии до
`amount` — при `amount = 10^4` уже близко к пределу стека. На интервью можно начать с неё
(«так я думаю»), а потом развернуть в таблицу («так надёжнее»).

</details>

<details>
<summary>Важный родственник: Coin Change II (число комбинаций)</summary>

Другой вопрос: **сколькими способами** набрать сумму (порядок монет не важен)?

```js
function change(amount, coins) {
  const dp = new Array(amount + 1).fill(0);
  dp[0] = 1;                                   // один способ набрать 0 — не брать ничего

  for (const coin of coins) {                  // ВНЕШНИЙ цикл — по монетам!
    for (let sum = coin; sum <= amount; sum++) {
      dp[sum] += dp[sum - coin];
    }
  }

  return dp[amount];
}
```

Два отличия, оба принципиальные:
- база `dp[0] = 1` (один способ), а не `0`, и операция — **сложение**, а не минимум;
- **порядок циклов перевёрнут**: монеты снаружи, суммы внутри.

Если поменять циклы местами, будут считаться **перестановки** (`1+2` и `2+1` как разные), а не
комбинации. Это классический вопрос на понимание: _«почему здесь монеты во внешнем цикле?»_

</details>
