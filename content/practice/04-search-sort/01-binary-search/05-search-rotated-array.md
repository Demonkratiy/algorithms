# Search in Rotated Sorted Array

**Тема:** binary-search (модифицированный) · **Сложность:** medium · **Приоритет:** ⚪ дополнительная

## Условие

Массив был отсортирован по возрастанию, а затем **сдвинут (rotated)** на неизвестное число
позиций. Например, `[0,1,2,4,5,6,7]` мог стать `[4,5,6,7,0,1,2]`.

Дан такой массив `nums` (без дубликатов) и `target`. Верни индекс `target` или `-1`.

Требуется `O(log N)`.

## Примеры

```
Вход:  nums = [4,5,6,7,0,1,2], target = 0     Выход: 4
Вход:  nums = [4,5,6,7,0,1,2], target = 3     Выход: -1
Вход:  nums = [1], target = 0                 Выход: -1
Вход:  nums = [3, 1], target = 1              Выход: 1
```

## Ограничения

- `1 <= nums.length <= 5000`
- значения уникальны; сдвиг может быть нулевым (массив просто отсортирован).

## 🎯 Цель по сложности

- Время `O(log N)`, память `O(1)`.
- ⚠️ Линейный поиск `O(N)` даст верный ответ, но не засчитается — вся суть задачи в `log N`.

## 🧠 Ментальная модель

Ключевое наблюдение: сдвинутый массив — это **две отсортированные части**. Где бы ни оказался
`mid`, **хотя бы одна из половин `[left..mid]` или `[mid..right]` отсортирована**.

```
[4, 5, 6, 7, 0, 1, 2]
 l        m        r
 └── левая отсортирована ──┘   правая — нет (7 → 0 разрыв)
```

Как определить, какая половина отсортирована: сравнить `nums[left]` с `nums[mid]`.
Если `nums[left] <= nums[mid]` — левая половина упорядочена, иначе — правая.

Дальше: в **упорядоченной** половине легко проверить, лежит ли `target` в её диапазоне.
Если да — идём туда, если нет — во вторую.

## ⚠️ Подводные камни именно этой задачи

1. **Сравнение с `nums[left]`, а не с `nums[right]`.** Оба подхода существуют, но их условия
   разные; смешаешь — получишь труднообнаружимый баг. Выбери один и трассируй.
2. **Нестрогое `<=` в `nums[left] <= nums[mid]`.** Когда отрезок из двух элементов и
   `mid === left`, строгое `<` уведёт в неверную ветку. Проверь на `nums = [3, 1], target = 1`.
3. **Границы диапазона проверяются нестрого:** `nums[left] <= target && target < nums[mid]`.
   Слева `<=` (сам `left` — валидный кандидат), справа `<` (`mid` уже проверен).
4. **Сначала проверь `nums[mid] === target`** и выйди — иначе придётся закладывать `mid`
   в диапазоны и путаться.
5. Массив может быть **не сдвинут** вовсе — алгоритм обязан работать и в этом случае
   (проверка: `[1,2,3], target = 3`).

<details>
<summary>Подсказка 3 — условия внутри веток</summary>

Левая отсортирована: если `nums[left] <= target && target < nums[mid]` → `right = mid - 1`,
иначе `left = mid + 1`.
Правая отсортирована: если `nums[mid] < target && target <= nums[right]` → `left = mid + 1`,
иначе `right = mid - 1`.

</details>

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function search(nums, target) {
  let left = 0;
  let right = nums.length - 1;

  while (left <= right) {
    const mid = Math.floor((left + right) / 2);

    if (nums[mid] === target) return mid;

    if (nums[left] <= nums[mid]) {                 // левая половина отсортирована
      if (nums[left] <= target && target < nums[mid]) {
        right = mid - 1;                           // target внутри левой
      } else {
        left = mid + 1;
      }
    } else {                                       // правая половина отсортирована
      if (nums[mid] < target && target <= nums[right]) {
        left = mid + 1;                            // target внутри правой
      } else {
        right = mid - 1;
      }
    }
  }

  return -1;
}
```

**Трассировка** `nums = [4,5,6,7,0,1,2]`, `target = 0`:

| шаг | left | right | mid | nums[mid] | какая половина отсортирована | действие |
|:---:|:----:|:-----:|:---:|:---------:|---|---|
| 1 | 0 | 6 | 3 | 7 | левая (`4 <= 7`), `0` не в `[4, 7)` | left = 4 |
| 2 | 4 | 6 | 5 | 1 | левая (`0 <= 1`), `0` в `[0, 1)` ✅ | right = 4 |
| 3 | 4 | 4 | 4 | 0 | совпало → **вернуть 4** ✅ | |

**Трассировка** `nums = [3, 1]`, `target = 1`:

| шаг | left | right | mid | nums[mid] | ветка |
|:---:|:----:|:-----:|:---:|:---------:|---|
| 1 | 0 | 1 | 0 | 3 | `nums[0] <= nums[0]` (3 ≤ 3) → левая; `1` не в `[3, 3)` → left = 1 |
| 2 | 1 | 1 | 1 | 1 | совпало → **1** ✅ |

Здесь и видно, зачем нужно нестрогое `<=`: при `mid === left` сравнение элемента с самим собой
должно давать «отсортировано».

**Сложность:** время `O(log N)` — каждая итерация по-прежнему отбрасывает половину.
Память `O(1)`.

</details>

<details>
<summary>Альтернативный подход: найти точку сдвига</summary>

```js
function findPivot(nums) {              // индекс минимального элемента
  let left = 0, right = nums.length - 1;
  while (left < right) {
    const mid = Math.floor((left + right) / 2);
    if (nums[mid] > nums[right]) left = mid + 1;   // минимум правее
    else right = mid;
  }
  return left;
}
```

Затем обычный бинарный поиск в нужной половине (или во всём массиве со «сдвигом индексов»).
Итого `O(log N) + O(log N)` = `O(log N)`. Способ длиннее, но каждый шаг проще для рассуждения —
если запутался в едином цикле, используй его.

Функция `findPivot` сама по себе — популярная задача «Find Minimum in Rotated Sorted Array».

</details>

<details>
<summary>Что меняется, если разрешены дубликаты</summary>

Задача «Search in Rotated Sorted Array II». При `nums[left] === nums[mid] === nums[right]`
(например, `[1,1,1,0,1]`) невозможно определить, какая половина отсортирована. Тогда делают
`left++; right--;` — и худший случай деградирует до **`O(N)`**. Это правильный ответ на вопрос
«а если дубликаты?» — не «алгоритм сломается», а «сложность в худшем случае станет линейной».

</details>
