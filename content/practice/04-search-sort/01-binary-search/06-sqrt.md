# Sqrt(x) — целочисленный квадратный корень

**Тема:** binary-search по ответу (на числах) · **Сложность:** easy · **Приоритет:** ⚪ дополнительная

> Самый короткий пример «бинарного поиска по ответу». Отличная разминка перед задачами вроде
> Koko: та же логика, но без массива вообще.

## Условие

Дано неотрицательное целое `x`. Верни **целую часть** квадратного корня из `x`,
то есть максимальное целое `k`, для которого `k * k <= x`.

Встроенными `Math.sqrt` / `Math.pow` / `**` пользоваться **нельзя**.

## Примеры

```
Вход: x = 4       Выход: 2
Вход: x = 8       Выход: 2      // √8 ≈ 2.83 → целая часть 2
Вход: x = 0       Выход: 0
Вход: x = 1       Выход: 1
Вход: x = 2147395599   Выход: 46339
```

## Ограничения

- `0 <= x <= 2^31 - 1`

## 🎯 Цель по сложности

- Время **`O(log x)`**, память `O(1)`.
- Наивно: считать `k` от 0 вверх, пока `k*k <= x` → `O(√x)`. Для `x ≈ 2·10^9` это ~46000
  итераций — работает, но это не тот ответ, которого ждут.

## 🧠 Ментальная модель

Пространство ответов `[0, x]` монотонно относительно предиката `k * k <= x`:

```
k:            0   1   2   3   4   5
k*k <= 8:     ✓   ✓   ✓   ✗   ✗   ✗
                      ↑ ищем ПОСЛЕДНИЙ ✓ — это максимальный подходящий
```

Обрати внимание: здесь мы ищем **максимальный** подходящий (шаблон ✓✓✓✗✗✗), а в Koko искали
**минимальный** (✗✗✗✓✓✓). Это два зеркальных варианта одного приёма — важно уметь оба.

## ⚠️ Подводные камни именно этой задачи

1. **Зеркальный шаблон легко зациклить.** Если писать `while (left < right)` с `left = mid`,
   то при `right = left + 1` получится `mid === left` и цикл повиснет.
   Лечение — либо `mid = Math.ceil((left + right) / 2)`, либо использовать классический шаблон
   `while (left <= right)` и хранить последний удачный ответ в переменной. **Второй способ
   надёжнее и его проще объяснить.**
2. **`mid * mid` может быть большим.** Для `x ≈ 2^31` произведение доходит до `~4.6·10^18`, что
   больше `Number.MAX_SAFE_INTEGER` (`9·10^15`)? Нет — при разумных границах `mid <= x`, но если
   взять `right = x`, то `mid*mid` для `x = 2^31` даст `~10^18` → уже за пределами безопасных
   целых. **Безопаснее сравнивать делением:** `mid <= x / mid`, либо ограничить
   `right = Math.min(x, 46341)`. На интервью достаточно **проговорить** проблему.
3. **`x = 0` и `x = 1`** — обязательные edge cases. Проверь, что цикл их не ломает.
4. Ответ — **целая часть**, не округление. Для `x = 8` ответ `2`, не `3`.

## 💡 Подсказки (открывай по очереди)

<details>
<summary>Подсказка 1 — надёжный шаблон</summary>

```js
let left = 0, right = x, answer = 0;
while (left <= right) {
  const mid = Math.floor((left + right) / 2);
  if (mid * mid <= x) { answer = mid; left = mid + 1; }   // запомнили и пробуем больше
  else right = mid - 1;
}
return answer;
```
Приём «запоминать последний удачный кандидат» избавляет от размышлений о зеркальных границах.

</details>

<details>
<summary>Подсказка 2 — безопасное сравнение</summary>

Вместо `mid * mid <= x` можно писать `mid <= x / mid` (при `mid > 0`) — произведение не
вычисляется, переполнения нет.

</details>

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function mySqrt(x) {
  if (x < 2) return x;                  // 0 → 0, 1 → 1

  let left = 1;
  let right = Math.floor(x / 2);        // для x >= 4 корень не больше x/2
  let answer = 1;

  while (left <= right) {
    const mid = Math.floor((left + right) / 2);

    if (mid <= x / mid) {               // эквивалент mid*mid <= x, но без переполнения
      answer = mid;                     // кандидат подходит — запоминаем
      left = mid + 1;                   // пробуем больше
    } else {
      right = mid - 1;
    }
  }

  return answer;
}
```

**Трассировка** `x = 8`, диапазон `[1, 4]`:

| шаг | left | right | mid | `mid <= 8/mid`? | действие | answer |
|:---:|:----:|:-----:|:---:|:---------------:|---|:---:|
| 1 | 1 | 4 | 2 | `2 <= 4` да | left = 3 | 2 |
| 2 | 3 | 4 | 3 | `3 <= 2.67` нет | right = 2 | 2 |
| 3 | left(3) > right(2) → выход | | | | | **2** ✅ |

**Проверка edge cases:** `mySqrt(0)` → `0` (ранний выход), `mySqrt(1)` → `1` (ранний выход),
`mySqrt(4)`: диапазон `[1, 2]`, mid = 1 → подходит, answer = 1, left = 2; mid = 2 → `2 <= 2`
подходит, answer = 2 → **2** ✅

**Сложность:** время `O(log x)`, память `O(1)`.

</details>

<summary>Приём «запомнить последний удачный ответ» — обобщение</summary>

```js
let answer = -1;
while (left <= right) {

  if (isFeasible(mid)) {
    answer = mid;          // сохраняем

  } else {
    right = mid - 1;
  }
}
return answer;
```

Для **минимального** подходящего меняются две строки: `answer = mid; right = mid - 1;`.

Плюс этого шаблона: он использует **одни и те же** границы (`left <= right`, `mid ± 1`), что и
классический поиск — не нужно держать в голове второй набор правил. Минус: лишняя переменная.
Если границы в поиске путают — используй именно его.

<details>
<summary>Бонус: метод Ньютона (упомянуть, но не обязательно)</summary>

```js
function mySqrtNewton(x) {
  if (x < 2) return x;
  let r = x;
  while (r * r > x) r = Math.floor((r + x / r) / 2);
  return r;
}
```

Сходится быстрее бинарного поиска (квадратично), но требует знания численных методов.
На FE-интервью достаточно знать, что такой способ существует.

</details>
