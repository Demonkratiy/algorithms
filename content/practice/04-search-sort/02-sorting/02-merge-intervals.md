# Merge Intervals

**Тема:** sorting как инструмент · **Сложность:** medium · **Приоритет:** 🔴 основная

> Самая частая «интервальная» задача на интервью. Демонстрирует главную мысль темы:
> **сортировка не решение, а подготовка**, после которой задача становится линейной.

## Условие

Дан массив интервалов `intervals`, где `intervals[i] = [start, end]`.
Слей все **пересекающиеся** интервалы и верни массив непересекающихся интервалов, покрывающих
все исходные.

Интервалы считаются пересекающимися, если они имеют хотя бы одну общую точку
(`[1,4]` и `[4,5]` → `[1,5]`).

## Примеры

```
Вход:  [[1,3], [2,6], [8,10], [15,18]]
Выход: [[1,6], [8,10], [15,18]]

Вход:  [[1,4], [4,5]]
Выход: [[1,5]]

Вход:  [[1,4], [2,3]]
Выход: [[1,4]]              // один интервал полностью внутри другого

Вход:  [[1,4], [0,4]]
Выход: [[0,4]]
```

## Ограничения

- `1 <= intervals.length <= 10^4`
- `0 <= start <= end <= 10^4`
- порядок интервалов на входе **произвольный**.

## 🎯 Цель по сложности

- Время **`O(N log N)`** — доминирует сортировка; сам проход `O(N)`.
- Память `O(N)` под результат (`O(log N)` дополнительной, если не считать выход).

## 🧠 Ментальная модель

Без сортировки пересечения приходится искать «каждый с каждым» — `O(N²)`.
После сортировки **по началу** появляется важное свойство:

> Если очередной интервал не пересекается с последним в результате, то он не пересекается и со
> всеми предыдущими — потому что их начала ещё левее, а концы уже пройдены.

Значит, достаточно смотреть только на **последний добавленный** интервал:

```
после сортировки: [1,3] [2,6] [8,10] [15,18]

[1,3]  → результат: [[1,3]]
[2,6]  → 2 <= 3 (пересекается) → расширяем конец: max(3, 6) = 6 → [[1,6]]
[8,10] → 8 > 6 (не пересекается) → добавляем → [[1,6], [8,10]]
[15,18]→ 15 > 10 → добавляем → [[1,6], [8,10], [15,18]]
```

## ⚠️ Подводные камни именно этой задачи

1. **Компаратор для массивов.** `intervals.sort()` без функции сравнит **строки** —
   `"[10,12]" < "[9,11]"`. Нужно `sort((a, b) => a[0] - b[0])`.
2. **`Math.max` при слиянии обязателен.** Случай «вложенный интервал» `[[1,5], [2,3]]`: если
   написать `last[1] = current[1]`, конец сожмётся с `5` до `3` ❌. Правильно
   `last[1] = Math.max(last[1], current[1])`. Это самая частая ошибка задачи.
3. **Касание считается пересечением.** Условие — `current[0] <= last[1]` (нестрого). При строгом
   `<` интервалы `[1,4]` и `[4,5]` не сольются.
4. **Мутация входа.** `sort()` меняет исходный массив, а слияние через `last[1] = ...` меняет и
   сами интервалы. Если вход нельзя портить — копируй: `intervals.map(i => [...i])`.
5. Пустой вход и один интервал — проверь, что код не падает.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function merge(intervals) {
  if (intervals.length <= 1) return intervals;

  intervals.sort((a, b) => a[0] - b[0]);          // по НАЧАЛУ интервала

  const result = [intervals[0]];

  for (let i = 1; i < intervals.length; i++) {
    const last = result[result.length - 1];
    const current = intervals[i];

    if (current[0] <= last[1]) {                  // пересекаются или касаются
      last[1] = Math.max(last[1], current[1]);    // max! current может быть вложенным
    } else {
      result.push(current);
    }
  }

  return result;
}
```

**Трассировка** `[[1,3], [2,6], [8,10], [15,18]]` (уже отсортирован по началу):

| i | current | last | `current[0] <= last[1]`? | результат |
|:-:|---------|------|:---:|---|
| — | — | — | — | `[[1,3]]` |
| 1 | `[2,6]` | `[1,3]` | `2 <= 3` да | `[[1,6]]` |
| 2 | `[8,10]` | `[1,6]` | `8 <= 6` нет | `[[1,6],[8,10]]` |
| 3 | `[15,18]` | `[8,10]` | `15 <= 10` нет | `[[1,6],[8,10],[15,18]]` ✅ |

**Проверка вложенного случая** `[[1,5], [2,3]]`:
`2 <= 5` → сливаем, `last[1] = Math.max(5, 3) = 5` → `[[1,5]]` ✅
(без `Math.max` получили бы `[[1,3]]` ❌ — потеряли часть покрытия).

**Сложность:** время `O(N log N)` — сортировка доминирует над линейным проходом.
Память: `O(N)` под результат; сортировка в V8 добавляет `O(log N)`–`O(N)`.

</details>

<details>
<summary>Почему сортировать по началу, а не по концу</summary>

Сортировка по началу гарантирует, что при обработке `intervals[i]` все интервалы, которые могли
бы с ним пересечься, **уже находятся в результате**, и достаточно проверить последний
(у него самый правый конец среди уже обработанных — потому что мы всегда берём `Math.max`).

Сортировка по **концу** тоже используется — но в другой задаче: «максимальное количество
непересекающихся интервалов» (жадный алгоритм activity selection). Разные цели — разные ключи
сортировки; это хорошая иллюстрация того, что «отсортировать» ещё не значит «решить».

</details>

<details>
<summary>Семейство интервальных задач</summary>

Один и тот же приём («отсортировать + пройти линейно»):

- **Merge Intervals** — эта задача;
- **Insert Interval** — вставить новый интервал в уже отсортированный список;
- **Non-overlapping Intervals** — минимум удалений, чтобы не осталось пересечений
  (сортировка по **концу**, жадность);
- **Meeting Rooms I/II** — см. [`04-meeting-rooms`](04-meeting-rooms.md);
- **Interval List Intersections** — пересечение двух списков (two pointers).

Если в условии слово «интервал»/«отрезок»/«встреча» — первым делом думай про сортировку.

</details>
