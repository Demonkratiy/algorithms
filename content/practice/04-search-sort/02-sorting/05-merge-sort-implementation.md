# Реализовать Merge Sort (и объяснить Quick Sort)

**Тема:** sorting (divide & conquer) · **Сложность:** medium · **Приоритет:** ⚪ дополнительная

> Писать сортировку с нуля на FE-интервью просят нечасто, но **объяснять** — регулярно.
> Задача полезна ещё и как первое серьёзное упражнение по рекурсии перед разделом 05.

## Условие

**Часть A.** Реализуй `mergeSort(arr)` — возвращает **новый** отсортированный по возрастанию
массив. Встроенным `sort()` пользоваться нельзя.

**Часть B.** Реализуй `merge(a, b)` — слияние двух уже отсортированных массивов за `O(N + M)`.
(Если решал [Merge Sorted Arrays](../../02-arrays-strings/01-two-pointers/03-merge-sorted-arrays.md) — ты уже это умеешь.)

**Часть C (устно).** Объясни, чем merge sort отличается от quick sort и когда какой выбирать.

## Примеры

```
mergeSort([5, 2, 4, 1])           → [1, 2, 4, 5]
mergeSort([])                     → []
mergeSort([3, 3, 1])              → [1, 3, 3]
merge([1, 4, 7], [2, 3])          → [1, 2, 3, 4, 7]
```

## 🎯 Цель по сложности

- `mergeSort`: время **`O(N log N)`** в любом случае, память `O(N)`.
- `merge`: время `O(N + M)`, память `O(N + M)`.

## 🧠 Ментальная модель

**Divide & Conquer** — три шага:

```
        [5, 2, 4, 1]
       /            \        1. DIVIDE: делим пополам
   [5, 2]         [4, 1]
   /    \         /    \
 [5]    [2]     [4]    [1]   2. база: массив из 1 элемента отсортирован
   \    /         \    /
   [2, 5]         [1, 4]     3. CONQUER/COMBINE: сливаем отсортированные
       \            /
        [1, 2, 4, 5]
```

Ключ к пониманию: **рекурсия возвращает уже отсортированные половины**, и всё, что нужно
сделать на текущем уровне, — слить их. Не пытайся «представить весь стек» — доверяй базе и
контракту функции. Это главный навык рекурсивного мышления.

## ⚠️ Подводные камни именно этой задачи

1. **База рекурсии — `length <= 1`**, а не `=== 0`. Иначе массив из одного элемента будет
   делиться дальше и уйдёт в бесконечную рекурсию.
2. **`slice(0, mid)` и `slice(mid)`** — не перепутай границы; `slice` не включает правый конец.
   Обе половины должны быть **строго меньше** исходного массива, иначе рекурсия не сойдётся.
3. **Хвосты в `merge`.** После основного цикла один из массивов не пуст — его нужно дописать.
   Забыть это — потерять элементы.
4. **`<=` вместо `<`** при сравнении в `merge` сохраняет **стабильность**. Для чисел разницы не
   видно, но объяснить нужно уметь.
5. **`shift()` вместо индексов.** Соблазн писать `result.push(a.shift())` — красиво, но
   `shift()` это `O(N)`, и вся сортировка деградирует до `O(N² log N)`. Используй индексы.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function merge(a, b) {
  const result = [];
  let i = 0;
  let j = 0;

  while (i < a.length && j < b.length) {
    if (a[i] <= b[j]) result.push(a[i++]);      // <= сохраняет стабильность
    else result.push(b[j++]);
  }

  while (i < a.length) result.push(a[i++]);     // хвост a
  while (j < b.length) result.push(b[j++]);     // хвост b

  return result;
}

function mergeSort(arr) {
  if (arr.length <= 1) return arr;              // база

  const mid = Math.floor(arr.length / 2);
  const left = mergeSort(arr.slice(0, mid));
  const right = mergeSort(arr.slice(mid));

  return merge(left, right);
}
```

**Почему `O(N log N)`.** Глубина рекурсии — `log₂ N` (каждый раз делим пополам). На каждом
уровне суммарно сливается `N` элементов (все куски вместе дают исходный размер). Итого
`N × log N`.

```
уровень 0:  [5,2,4,1]            → слияние 4 элементов
уровень 1:  [5,2] [4,1]          → слияние 2 + 2 = 4
уровень 2:  [5][2][4][1]         → база
```

**Почему память `O(N)`.** На каждом уровне создаются новые массивы; одновременно живущих —
`O(N)` элементов. Плюс `O(log N)` на стек вызовов, что поглощается `O(N)`.

`a[i++]` — постфиксный инкремент: сначала используется текущее значение `i`, потом `i`
увеличивается. Если непривычно, пиши явно: `result.push(a[i]); i++;`

</details>

<details>
<summary>Quick Sort — для сравнения (часть C)</summary>

```js
function quickSort(arr) {
  if (arr.length <= 1) return arr;

  const pivot = arr[arr.length - 1];
  const less = [];
  const greater = [];

  for (let i = 0; i < arr.length - 1; i++) {
    if (arr[i] <= pivot) less.push(arr[i]);
    else greater.push(arr[i]);
  }

  return [...quickSort(less), pivot, ...quickSort(greater)];
}
```

**Сравнение, которое нужно уметь произнести:**

| | Merge Sort | Quick Sort |
|---|---|---|
| Время (среднее) | `O(N log N)` | `O(N log N)` |
| Время (худшее) | `O(N log N)` — гарантия | **`O(N²)`** при плохих pivot |
| Память | `O(N)` | `O(log N)` (in-place версия) |
| Стабильность | стабильная | нестабильная |
| На практике | предсказуема, хороша для связных списков и внешней сортировки | обычно быстрее (кеш, in-place) |

**Худший случай quick sort** наступает, когда pivot систематически оказывается минимумом или
максимумом — например, на **уже отсортированном** массиве при выборе последнего элемента.
Разбиение даёт части `N-1` и `0`, глубина становится `N`. Лечится случайным pivot или
«медианой трёх».

`Array.prototype.sort()` в V8 использует **TimSort** — гибрид merge sort и insertion sort,
стабильный, `O(N log N)` в худшем случае, с оптимизацией под частично отсортированные данные.

</details>

<details>
<summary>Как проверить себя офлайн</summary>

```js
// сравнение со встроенной сортировкой на случайных массивах
for (let t = 0; t < 100; t++) {
  const n = Math.floor(Math.random() * 20);
  const arr = Array.from({ length: n }, () => Math.floor(Math.random() * 50));
  const mine = mergeSort([...arr]).join(',');
  const ref  = [...arr].sort((a, b) => a - b).join(',');
  if (mine !== ref) { console.log('FAIL', arr, mine, ref); break; }
}
console.log('done');
```

Такой «стресс-тест» — очень полезная привычка: он находит краевые случаи, которые не приходят в
голову вручную. Применяй его к любой своей реализации, где есть эталон для сравнения.

</details>
