# Meeting Rooms I

**Тема:** sorting + интервалы · **Приоритет:** ⚪ дополнительная · **Сложность:** easy

Продолжение вынесено в отдельную задачу: [Meeting Rooms II](04-b-meeting-rooms-ii.md).

## Условие

Дан массив интервалов `intervals[i] = [start, end]`. Верни `true`, если человек может посетить **все** встречи, иначе `false`. Разрешено сортировать входной массив.

Встречи `[1, 5]` и `[5, 8]` не конфликтуют: касание границ разрешено.

`0 <= intervals.length <= 10^4`, `0 <= start < end <= 10^6`.

Примеры: `[[0,30],[5,10],[15,20]] → false`, `[[7,10],[2,4]] → true`, `[[1,5],[5,8]] → true`, `[] → true`.

## 🎯 Цель по сложности

Время `O(N log N)`. Сам проход использует `O(1)` памяти; дополнительная память сортировки зависит от реализации JS `sort` (обычно до `O(N)`).

## 🧠 Ментальная модель

Отсортировать по началу и проверить соседей: если начало следующей встречи раньше
конца предыдущей — конфликт. Достаточно смотреть только на **соседей**, потому что после
сортировки все более ранние встречи начинаются ещё левее.

## ⚠️ Подводные камни именно этой задачи

Касание — не конфликт: сравнение строгое. При сортировке нужен числовой компаратор. Пустой массив → `true`.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение</summary>

```js
function canAttendMeetings(intervals) {
  intervals.sort((a, b) => a[0] - b[0]);

  for (let i = 1; i < intervals.length; i++) {
    if (intervals[i][0] < intervals[i - 1][1]) return false;   // строгое <: касание ОК
  }

  return true;
}
```

Время `O(N log N)` (сортировка), память прохода `O(1)` плюс память встроенной сортировки (обычно до `O(N)`).
