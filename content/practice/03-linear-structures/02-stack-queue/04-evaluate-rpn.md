# Evaluate Reverse Polish Notation

**Тема:** stack · **Сложность:** medium · **Приоритет:** ⚪ дополнительная

## Условие

Дан массив токенов `tokens` — арифметическое выражение в **обратной польской записи**
(постфиксной): операнд, операнд, оператор. Вычисли значение выражения.

Операторы: `+`, `-`, `*`, `/`. Деление — **целочисленное с отсечением дробной части в сторону
нуля** (`6 / -4 = -1`, а не `-2`).

Гарантируется, что выражение корректно и деления на ноль нет.

## Примеры

```
Вход:  ["2", "1", "+", "3", "*"]
Выход: 9                            // ((2 + 1) * 3)

Вход:  ["4", "13", "5", "/", "+"]
Выход: 6                            // (4 + (13 / 5)) = 4 + 2

Вход:  ["10","6","9","3","+","-11","*","/","*","17","+","5","+"]
Выход: 22
```

## Ограничения

- `1 <= tokens.length <= 10^4`
- токен — либо оператор, либо целое число в диапазоне `[-200, 200]`.

## 🎯 Цель по сложности

- Время `O(N)`, память `O(N)`.

## 🧠 Ментальная модель

Постфиксная запись существует именно для того, чтобы её считал стек — без скобок и приоритетов.

Правило: число → `push`. Оператор → снять **два** последних, применить, результат `push`.

```
["2","1","+","3","*"]
 2      → [2]
 1      → [2, 1]
 +      → pop 1, pop 2 → 2+1=3 → [3]
 3      → [3, 3]
 *      → pop 3, pop 3 → 3*3=9 → [9]
ответ: 9 (единственный элемент стека)
```

## ⚠️ Подводные камни именно этой задачи

1. **Порядок операндов!** Первый `pop()` — это **правый** операнд, второй — **левый**.
   Для `+` и `*` неважно, а для `-` и `/` перепутать = неверный ответ.
   Правильно: `const b = stack.pop(); const a = stack.pop(); a - b`.
2. **Целочисленное деление с отсечением к нулю.** В JS `/` даёт дробь, а `Math.floor(-2.5)`
   даёт `-3` (округление вниз), тогда как нужно `-2`. Правильно: `Math.trunc(a / b)`
   (или `(a / b) | 0`, но это ломается на больших числах).
3. **Токены — строки.** `"2" + "1"` даст `"21"`. Нужно `Number(token)` или `+token`.
4. **Отрицательные числа выглядят как токены с минусом** (`"-11"`). Отличать оператор от числа
   по «есть ли минус» нельзя — сравнивай токен со списком операторов.
5. Результат — единственный оставшийся элемент стека: `stack.pop()`, а не `stack[0]`.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function evalRPN(tokens) {
  const operations = {
    '+': (a, b) => a + b,
    '-': (a, b) => a - b,
    '*': (a, b) => a * b,
    '/': (a, b) => Math.trunc(a / b),      // отсечение к нулю, не Math.floor
  };

  const stack = [];

  for (const token of tokens) {
    if (operations[token] !== undefined) {
      const b = stack.pop();               // ПРАВЫЙ операнд снимается первым
      const a = stack.pop();               // ЛЕВЫЙ
      stack.push(operations[token](a, b));
    } else {
      stack.push(Number(token));
    }
  }

  return stack.pop();
}
```

**Трассировка** `["4", "13", "5", "/", "+"]`:

| токен | действие | стек |
|---|---|---|
| `4` | push 4 | `[4]` |
| `13` | push 13 | `[4, 13]` |
| `5` | push 5 | `[4, 13, 5]` |
| `/` | b=5, a=13 → trunc(13/5)=2 | `[4, 2]` |
| `+` | b=2, a=4 → 6 | `[6]` |

Ответ `6` ✅

**Проверка порядка операндов** на `["3", "1", "-"]`: b=1, a=3 → `3 - 1 = 2` ✅
(если перепутать — получишь `-2`).

**Проверка деления** на `["6", "-4", "/"]`: `Math.trunc(6 / -4) = Math.trunc(-1.5) = -1` ✅
(`Math.floor` дал бы `-2` ❌).

**Сложность:** время `O(N)` — по одному действию на токен. Память `O(N)` — стек операндов.

</details>

<details>
<summary>Зачем вообще нужна постфиксная запись</summary>

В инфиксной записи (`2 + 3 * 4`) нужны приоритеты операций и скобки, а значит — парсер.
В постфиксной порядок вычислений уже зашит в саму последовательность, и вычисление сводится к
одному проходу со стеком. Именно так работают стековые виртуальные машины и калькуляторы.

Обратная задача — перевод инфикса в постфикс (алгоритм сортировочной станции, shunting-yard) —
на FE-интервью встречается редко, но знать название полезно.

</details>
