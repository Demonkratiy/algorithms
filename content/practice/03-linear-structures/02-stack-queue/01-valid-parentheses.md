# Valid Parentheses

**Тема:** stack · **Сложность:** easy · **Приоритет:** 🔴 основная

> ⚠️ Разобрана в теории ([stack-queue.md](../../../03-linear-structures/02-stack-queue.md)).
> Пиши **по памяти**. Это самая частая «разминочная» задача на стек на реальных интервью.

## Условие

Дана строка `s`, состоящая только из символов `(`, `)`, `[`, `]`, `{`, `}`.
Верни `true`, если скобки расставлены корректно:

- каждая открывающая закрыта скобкой **того же типа**;
- скобки закрываются в **правильном порядке** (нельзя «пересекать»);
- каждой закрывающей соответствует открывающая.

## Примеры

```
"()"        → true
"()[]{}"    → true
"(]"        → false
"([)]"      → false     // пересечение
"{[]}"      → true
""          → true      // пустая строка валидна
"]"         → false
```

## Ограничения

- `0 <= s.length <= 10^4`
- строка содержит только скобочные символы.

## 🎯 Цель по сложности

- Время `O(N)`, память `O(N)` (стек в худшем случае хранит всю строку).

## 🧠 Ментальная модель

Стек хранит **открытые, но ещё не закрытые** скобки. Встретил открывающую — отложил. Встретил
закрывающую — она обязана закрывать **последнюю отложенную**.

## ⚠️ Подводные камни именно этой задачи

1. **Финальная проверка `stack.length === 0`.** Без неё `"((("` вернёт `true`.
2. **Лишняя закрывающая при пустом стеке** (`")"`, `"()]"`). Обрабатывается либо явной проверкой
   `stack.length === 0`, либо тем, что `[].pop()` даёт `undefined`, который не равен ни одной
   открывающей.
3. **Счётчик вместо стека** — ловушка. `([)]` имеет правильные количества, но неверный порядок.
4. **Направление словаря пар.** Удобнее `{ ')': '(' }` (закрывающая → открывающая), потому что
   проверка идёт в момент встречи закрывающей. Обратный словарь тоже работает, но требует
   больше телодвижений — выбери одно и не путайся.
5. Нечётная длина строки — всегда `false`. Можно добавить ранний выход `if (s.length % 2) return false;`
   как микрооптимизацию (и как повод показать внимательность).

<summary>Подсказка 1 — структура данных</summary>

Обычный массив как стек: `push` для открывающих, `pop` для закрывающих.

</details>

<details>
<summary>Подсказка 2 — как отличить открывающую от закрывающей</summary>

Через словарь пар: `const pairs = { ')': '(', ']': '[', '}': '{' };`
Если `char in pairs` (или `pairs[char]` определён) — это **закрывающая**.

</details>

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function isValid(s) {
  const pairs = { ')': '(', ']': '[', '}': '{' };
  const stack = [];

  for (const char of s) {
    if (pairs[char] === undefined) {     // не закрывающая → значит открывающая
      stack.push(char);
    } else if (stack.pop() !== pairs[char]) {
      return false;                       // не та пара ИЛИ стек был пуст (undefined)
    }
  }

  return stack.length === 0;
}
```

**Разбор проверок:**

| вход | что происходит | результат |
|---|---|---|
| `"("` | push, стек `['(']`, в конце не пуст | `false` ✅ |
| `")"` | `pop()` → `undefined` ≠ `'('` | `false` ✅ |
| `"([)]"` | push `(`, push `[`, на `)` pop даёт `'['` ≠ `'('` | `false` ✅ |
| `""` | цикл не выполняется, стек пуст | `true` ✅ |

**Сложность:** время `O(N)` — по одному действию `O(1)` на символ. Память `O(N)` — худший
случай `"((((("`.

</details>

<details>
<summary>Вариант с явной проверкой пустоты (читается яснее)</summary>

```js
function isValid(s) {
  const pairs = { ')': '(', ']': '[', '}': '{' };
  const stack = [];

  for (const char of s) {
    if (char === '(' || char === '[' || char === '{') {
      stack.push(char);
      continue;
    }
    if (stack.length === 0) return false;     // закрывающая без пары
    if (stack.pop() !== pairs[char]) return false;
  }

  return stack.length === 0;
}
```

Функционально идентичен, но явная проверка `stack.length === 0` полезна как привычка: в задачах,
где в стеке лежат числа, `undefined` от `pop()` уже нельзя использовать как признак пустоты
(значение `0` — валидное).

</details>

<details>
<summary>Развитие задачи (о чём могут спросить дальше)</summary>

- **«А если в строке есть и другие символы?»** — тогда неизвестные символы просто игнорируем:
  добавь `else continue` для не-скобок.
- **«Верни индекс первой ошибки»** — храни в стеке пары `[char, index]`.
- **«Минимальное число вставок, чтобы строка стала валидной»** — вариация, где вместо раннего
  `return false` считается счётчик. Идея стека та же.

</details>
