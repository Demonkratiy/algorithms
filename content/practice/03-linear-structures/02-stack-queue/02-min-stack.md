# Min Stack

**Тема:** stack (проектирование структуры) · **Сложность:** medium · **Приоритет:** 🔴 основная

> Задача на **дизайн структуры данных** — отдельный жанр интервью-вопросов. Здесь важно не
> «придумать алгоритм», а понять trade-off «память ↔ время».

## Условие

Спроектируй стек, поддерживающий четыре операции, **каждая за `O(1)`**:

- `push(val)` — положить значение;
- `pop()` — снять верхнее;
- `top()` — посмотреть верхнее (не снимая);
- `getMin()` — вернуть **минимальное** значение в стеке.

```js
class MinStack {
  constructor() {}
  push(val) {}
  pop() {}
  top() {}
  getMin() {}
}
```

## Примеры

```
const st = new MinStack();
st.push(-2);
st.push(0);
st.push(-3);
st.getMin();   // -3
st.pop();
st.top();      // 0
st.getMin();   // -2   ← минимум "откатился" вместе с pop
```

## Ограничения

- `-2^31 <= val <= 2^31 - 1`
- `pop`, `top`, `getMin` вызываются только на непустом стеке.
- До `3 * 10^4` вызовов суммарно.

## 🎯 Цель по сложности

- **Все операции `O(1)`.** Память `O(N)`.
- Наивно: `getMin()` пробегает стек → `O(N)` на вызов. Это то, что нужно улучшить.

## 🧠 Ментальная модель

Ключевой вопрос: почему нельзя просто хранить одну переменную `min`?

Потому что при `pop()` минимума нужно **восстановить предыдущий** минимум, а он уже потерян.
Значит, для каждого состояния стека надо помнить «какой был минимум **на этот момент**».

Решение: **второй стек минимумов**, который двигается синхронно с основным. На каждом уровне
он хранит минимум среди всех элементов ниже и включая текущий.

```
push(-2)  main: [-2]        mins: [-2]
push(0)   main: [-2, 0]     mins: [-2, -2]   ← 0 не меньше, дублируем -2
push(-3)  main: [-2, 0, -3] mins: [-2, -2, -3]
pop()     main: [-2, 0]     mins: [-2, -2]   → getMin() = -2 ✅
```

Оба стека всегда одной высоты → `pop` из обоих, и минимум откатывается сам собой.

## ⚠️ Подводные камни именно этой задачи

1. **Одна переменная `min` не работает** — не забудь объяснить это вслух, иначе интервьюер решит,
   что ты «случайно» пришёл к правильному ответу.
2. **Дубликаты минимума.** Если использовать «оптимизацию» — класть в `mins` только когда
   `val < currentMin` (строго), то на входе `[2, 2]` первый `pop` снимет минимум, и `getMin()`
   вернёт неверное значение. Лечится либо `<=` при push, либо дублированием на каждом push.
   **Это главная ловушка задачи.**
3. **`pop()` должен снимать из обоих стеков.** Рассинхрон — источник тонких багов.
4. **`top()` — это не `getMin()`.** `top` — последний добавленный, `getMin` — минимальный.
   Название `top()` для «посмотреть верхний» стандартное, `peek()` — синоним.
5. Пустой стек: по условию не вызывается, но проговорить поведение стоит (`undefined` или ошибка).

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
class MinStack {
  constructor() {
    this.stack = [];
    this.mins = [];        // mins[i] — минимум среди stack[0..i]
  }

  push(val) {
    this.stack.push(val);
    const prevMin = this.mins.length === 0 ? val : this.mins[this.mins.length - 1];
    this.mins.push(Math.min(val, prevMin));
  }

  pop() {
    this.mins.pop();       // синхронно с основным
    return this.stack.pop();
  }

  top() {
    return this.stack[this.stack.length - 1];
  }

  getMin() {
    return this.mins[this.mins.length - 1];
  }
}
```

**Трассировка** примера:

| операция | stack | mins | результат |
|---|---|---|---|
| push(-2) | `[-2]` | `[-2]` | |
| push(0) | `[-2, 0]` | `[-2, -2]` | |
| push(-3) | `[-2, 0, -3]` | `[-2, -2, -3]` | |
| getMin() | | | `-3` ✅ |
| pop() | `[-2, 0]` | `[-2, -2]` | `-3` |
| top() | | | `0` ✅ |
| getMin() | | | `-2` ✅ |

**Сложность:** все операции `O(1)` — только `push`/`pop` на массивах и обращение по индексу.
Память `O(N)`, точнее `2N` — это и есть цена ответа `getMin()` за `O(1)`.
На интервью так и скажи: _«я плачу лишним O(N) памяти, чтобы получить O(1) по времени»_.

</details>

<details>
<summary>Почему «оптимизация со строгим <» ломается</summary>

```js
// ОПАСНЫЙ вариант
push(val) {
  this.stack.push(val);
  if (this.mins.length === 0 || val < this.mins[this.mins.length - 1]) {
    this.mins.push(val);         // кладём только строго меньшие
  }
}
pop() {
  const val = this.stack.pop();
  if (val === this.mins[this.mins.length - 1]) this.mins.pop();
  return val;
}
```

Прогон `push(2); push(2); pop(); getMin();`
— `mins` после двух push: `[2]` (второй не строго меньше). После `pop()` значение `2` совпало с
вершиной `mins`, её сняли → `mins` пуст. Но в стеке ещё лежит `2`! `getMin()` вернёт `undefined`.

Исправление: использовать `<=` вместо `<` при push. Тогда равные минимумы дублируются, и
снимаются по одному. Экономия памяти сохраняется, а баг уходит.

</details>

<details>
<summary>Вариант с одним стеком пар (тоже принимается)</summary>

```js
class MinStack {
  constructor() { this.stack = []; }          // элементы: { val, min }

  push(val) {
    const min = this.stack.length === 0 ? val : Math.min(val, this.getMin());
    this.stack.push({ val, min });
  }
  pop()    { return this.stack.pop().val; }
  top()    { return this.stack[this.stack.length - 1].val; }
  getMin() { return this.stack[this.stack.length - 1].min; }
}
```

Та же идея, один контейнер. Выбор — вопрос вкуса; объясни, что оба `O(1)`/`O(N)`.

</details>
