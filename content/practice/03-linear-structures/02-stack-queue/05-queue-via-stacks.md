# Implement Queue using Stacks

**Тема:** stack / queue (дизайн + амортизированный анализ) · **Сложность:** easy → medium · **Приоритет:** ⚪ дополнительная

> Ценность задачи не в коде (он короткий), а в **объяснении сложности**. Это классический
> способ проверить, понимаешь ли ты амортизированный анализ — а его же ты используешь в
> sliding window и monotonic stack.

## Условие

Реализуй очередь (FIFO), используя **только два стека**. Разрешены операции стека:
`push`, `pop`, `peek` (посмотреть вершину), `isEmpty`. Индексами и `shift()` пользоваться нельзя.

Методы:
- `push(x)` — добавить в конец очереди;
- `pop()` — извлечь из начала очереди;
- `peek()` — посмотреть начало очереди;
- `empty()` — пуста ли очередь.

## Примеры

```
const q = new MyQueue();
q.push(1);
q.push(2);
q.peek();    // 1
q.pop();     // 1
q.empty();   // false
```

## Ограничения

- `1 <= x <= 9`, до `100` вызовов.
- `pop` и `peek` вызываются на непустой очереди.

## 🎯 Цель по сложности

- `push` — `O(1)`.
- `pop` / `peek` — **амортизированно `O(1)`** (в худшем отдельном случае `O(N)`).
- Уметь объяснить, почему «амортизированно» — не то же самое, что «всегда».

## 🧠 Ментальная модель

Стек переворачивает порядок. Если пересыпать элементы из одного стека в другой, порядок
**инвертируется** — а два инвертирования подряд дают FIFO.

Два стека:
- `inStack` — сюда кладём всё новое;
- `outStack` — отсюда забираем.

Когда `outStack` пуст, **пересыпаем весь** `inStack` в `outStack` — порядок переворачивается,
и на вершине оказывается самый старый элемент.

```
push 1,2,3   in: [1,2,3]   out: []
pop()        → out пуст → пересыпаем → in: []  out: [3,2,1]
             → out.pop() = 1 ✅ (самый старый)
push 4       in: [4]       out: [3,2]
pop()        → out НЕ пуст → сразу out.pop() = 2 ✅
```

## ⚠️ Подводные камни именно этой задачи

1. **Пересыпать только когда `outStack` пуст.** Если пересыпать при каждом `pop`, порядок
   сломается: новые элементы окажутся впереди старых. Это главная логическая ошибка.
2. **Не пересыпать обратно.** Элементы живут в `outStack` до тех пор, пока их не заберут.
3. **Амортизированная оценка.** Каждый элемент переносится **ровно один раз** за свою жизнь:
   `push` в `in`, перенос в `out`, `pop` из `out` — три операции на элемент. Значит, `N`
   операций стоят `O(N)` суммарно → `O(1)` в среднем на операцию, хотя **отдельный** `pop`
   может стоить `O(N)`.
4. **`peek` использует ту же логику переноса**, что и `pop` — вынеси её в общий приватный метод,
   иначе продублируешь код и рассинхронишь.
5. `empty()` — очередь пуста, только когда **оба** стека пусты.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
class MyQueue {
  constructor() {
    this.inStack = [];       // приём новых элементов
    this.outStack = [];      // выдача, порядок уже перевёрнут
  }

  push(x) {
    this.inStack.push(x);                       // O(1)
  }

  pop() {
    this.#transfer();
    return this.outStack.pop();
  }

  peek() {
    this.#transfer();
    return this.outStack[this.outStack.length - 1];
  }

  empty() {
    return this.inStack.length === 0 && this.outStack.length === 0;
  }

  #transfer() {
    if (this.outStack.length > 0) return;       // пересыпаем ТОЛЬКО когда out пуст
    while (this.inStack.length > 0) {
      this.outStack.push(this.inStack.pop());
    }
  }
}
```

**Трассировка** `push(1) push(2) peek() pop() push(3) pop() pop()`:

| операция | inStack | outStack | результат |
|---|---|---|---|
| push(1) | `[1]` | `[]` | |
| push(2) | `[1,2]` | `[]` | |
| peek() | `[]` | `[2,1]` | `1` ✅ |
| pop() | `[]` | `[2]` | `1` ✅ |
| push(3) | `[3]` | `[2]` | |
| pop() | `[3]` | `[]` | `2` ✅ (out не пуст → без переноса) |
| pop() | `[]` | `[]` | `3` ✅ (перенос) |

FIFO соблюдён: 1, 2, 3.

**Сложность:**
- `push` — `O(1)`;
- `pop` / `peek` — в худшем случае `O(N)` (когда происходит перенос), но
  **амортизированно `O(1)`**: каждый элемент участвует в переносе ровно один раз за всю жизнь,
  поэтому `N` операций суммарно стоят `O(N)`;
- память `O(N)`.

</details>

<details>
<summary>Как правильно объяснить «амортизированно» вслух</summary>

> _«Один вызов pop может стоить O(N), если случился перенос. Но перенос происходит не чаще, чем
> раз на "порцию" элементов, и каждый элемент переносится ровно один раз за свою жизнь в
> очереди. Значит, суммарная стоимость любых M операций — O(M), то есть амортизированная
> стоимость одной операции — O(1). Это не то же самое, что "всегда O(1)": гарантия даётся на
> последовательность, а не на отдельный вызов»._

Тот же аргумент ты уже применял в
[sliding window](../../../02-arrays-strings/02-sliding-window.md) (левая граница движется вперёд не
более `N` раз) и в [Daily Temperatures](03-daily-temperatures.md) (каждый индекс входит в стек
и выходит один раз). Это **один и тот же приём рассуждения** — очень ценно, что ты его узнаёшь.

</details>

<details>
<summary>Обратная задача: стек через две очереди</summary>

Иногда спрашивают наоборот. Там симметричного «дешёвого» решения нет: либо `push` за `O(N)`
(переливаем очередь после каждой вставки), либо `pop` за `O(N)`. Амортизации, как здесь, не
получается — стоит уметь объяснить и эту асимметрию.

</details>
