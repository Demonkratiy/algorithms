# Merge Two Sorted Lists

**Тема:** linked-lists (dummy node + два указателя) · **Сложность:** easy · **Приоритет:** 🔴 основная

## Условие

Даны головы двух списков `list1` и `list2`, каждый **отсортирован по возрастанию**. Слей их в
один отсортированный список и верни его голову.

Новый список нужно собрать **переиспользуя существующие узлы** (не создавая новые), кроме
служебного dummy.

## Примеры

```
Вход:  list1 = 1 → 2 → 4,  list2 = 1 → 3 → 4
Выход: 1 → 1 → 2 → 3 → 4 → 4

Вход:  list1 = null, list2 = null      Выход: null
Вход:  list1 = null, list2 = 0         Выход: 0
```

## Ограничения

- `0 <= n, m <= 50`
- Оба списка отсортированы по неубыванию.

## 🎯 Цель по сложности

- Время `O(N + M)`, память **`O(1)`** (не считая выходного списка — узлы переиспользуются).

## 🧠 Ментальная модель

Это то же слияние, что в **merge sort** и в задаче «Merge Sorted Arrays» из two-pointers,
только вместо `push` в массив мы **пришиваем узел к хвосту**.

```
dummy → [ ] → ...
          ↑ tail — сюда пришиваем следующий минимальный узел
```

Алгоритм:
1. `dummy` + `tail = dummy`;
2. пока оба списка не пусты — сравнить головы, меньшую пришить к `tail`, сдвинуть её список;
3. `tail` сдвинуть на пришитый узел;
4. когда один список кончился — **пришить остаток второго целиком** (он уже отсортирован).

## ⚠️ Подводные камни именно этой задачи

1. **Без dummy** придётся отдельно определять голову результата — лишняя ветка `if` и любимый
   источник багов. С dummy код единообразен, в конце `return dummy.next`.
2. **Хвост не забыт.** После основного цикла один из списков ещё не пуст. Забыть строку
   `tail.next = list1 || list2` — самая частая ошибка здесь.
3. **`<=` вместо `<`** при сравнении сохраняет стабильность (равные элементы из `list1` идут
   первыми). На корректность в этой задаче не влияет, но проговорить стоит.
4. **Сдвигать нужно и `tail`, и указатель того списка, из которого взяли узел.** Забыл сдвинуть
   список — бесконечный цикл.
5. Оба входа могут быть `null` — код должен вернуть `null`, а не упасть.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function mergeTwoLists(list1, list2) {
  const dummy = new ListNode();
  let tail = dummy;

  while (list1 !== null && list2 !== null) {
    if (list1.val <= list2.val) {
      tail.next = list1;
      list1 = list1.next;
    } else {
      tail.next = list2;
      list2 = list2.next;
    }
    tail = tail.next;          // общая для обеих веток
  }

  tail.next = list1 !== null ? list1 : list2;   // остаток пришиваем целиком

  return dummy.next;
}
```

**Почему остаток можно пришить одной строкой.** Оставшийся список уже отсортирован, и все его
значения ≥ последнего пришитого (иначе он был бы выбран раньше). Поэлементно копировать не надо
— это `O(1)` вместо `O(N)`.

**Трассировка** `list1 = 1→2→4`, `list2 = 1→3→4`:

| шаг | сравнение | пришили | результат |
|:---:|-----------|:-------:|-----------|
| 1 | 1 ≤ 1 | из list1 | `1` |
| 2 | 2 > 1 | из list2 | `1→1` |
| 3 | 2 < 3 | из list1 | `1→1→2` |
| 4 | 4 > 3 | из list2 | `1→1→2→3` |
| 5 | 4 ≤ 4 | из list1 | `1→1→2→3→4` |
| — | list1 пуст | остаток list2 | `1→1→2→3→4→4` ✅ |

**Сложность:** время `O(N + M)` — каждый узел рассматривается один раз.
Память `O(1)` — создаём только dummy, остальное переиспользуем.

</details>

<details>
<summary>Рекурсивная версия (короткая, но O(N+M) памяти)</summary>

```js
function mergeTwoListsRecursive(list1, list2) {
  if (list1 === null) return list2;
  if (list2 === null) return list1;

  if (list1.val <= list2.val) {
    list1.next = mergeTwoListsRecursive(list1.next, list2);
    return list1;
  }
  list2.next = mergeTwoListsRecursive(list1, list2.next);
  return list2;
}
```

Красиво читается, но глубина стека — `O(N + M)`. На интервью назови обе и объясни выбор.

</details>
