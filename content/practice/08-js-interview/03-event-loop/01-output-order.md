# «Что выведется?» — порядок выполнения

**Тема:** js-interview / event loop · **Сложность:** medium · **Приоритет:** 🔴 основная

> Формат этой задачи отличается от остальных: здесь не нужно писать код — нужно **предсказать
> вывод и объяснить почему**. Именно так спрашивают на реальных интервью.
>
> Правила работы: для каждого сниппета **сначала запиши свой ответ** в блоке «✍️ Мои ответы»,
> и только потом открывай разбор. Проверять в консоли — тоже **после** своей версии, иначе
> упражнение бесполезно.

## Что нужно помнить (без подглядывания в теорию)

1. Весь синхронный код.
2. **Все** микрозадачи (`.then`, `await`-продолжение, `queueMicrotask`), включая добавленные
   по ходу.
3. **Одна** макрозадача (`setTimeout`), затем снова все микрозадачи.

---

## Сниппет 1 — база

```js
console.log('start');
setTimeout(() => console.log('timeout'), 0);
Promise.resolve().then(() => console.log('promise'));
console.log('end');
```

## Сниппет 2 — цепочка `.then`

```js
Promise.resolve()
  .then(() => console.log('A'))
  .then(() => console.log('B'));

Promise.resolve()
  .then(() => console.log('C'))
  .then(() => console.log('D'));
```

## Сниппет 3 — async / await

```js
async function foo() {
  console.log('foo start');
  await bar();
  console.log('foo end');
}

async function bar() {
  console.log('bar');
}

console.log('script start');
setTimeout(() => console.log('timeout'), 0);
foo();
new Promise((resolve) => {
  console.log('executor');
  resolve();
}).then(() => console.log('then'));
console.log('script end');
```

## Сниппет 4 — вложенные таймеры и промисы

```js
setTimeout(() => {
  console.log('t1');
  Promise.resolve().then(() => console.log('p1'));
}, 0);

setTimeout(() => {
  console.log('t2');
  Promise.resolve().then(() => console.log('p2'));
}, 0);

Promise.resolve().then(() => console.log('p0'));
```

## Сниппет 5 — `await` в цикле

```js
async function run() {
  for (const n of [1, 2, 3]) {
    await null;
    console.log('loop', n);
  }
}

run();
Promise.resolve().then(() => console.log('micro 1'));
Promise.resolve().then(() => console.log('micro 2'));
console.log('sync');
```

## Сниппет 6 — ошибки и `finally`

```js
console.log('1');

Promise.reject(new Error('boom'))
  .then(() => console.log('2'))
  .catch(() => console.log('3'))
  .finally(() => console.log('4'))
  .then(() => console.log('5'));

console.log('6');
```

## 🔍 Разбор — открывай ТОЛЬКО после своих ответов

<details>
<summary>Сниппет 1</summary>

**Ответ:** `start`, `end`, `promise`, `timeout`

- `start` и `end` — синхронные;
- `promise` — микрозадача, выполняется сразу после синхронного кода;
- `timeout` — макрозадача, всегда после всех микрозадач, даже с задержкой `0`.

Это базовый шаблон: **синхронное → микро → макро**.

</details>

<details>
<summary>Сниппет 2</summary>

**Ответ:** `A`, `C`, `B`, `D`

Цепочки выполняются **по слоям**, а не целиком по очереди.

| тик микроочереди | очередь | вывод |
|:---:|---|:---:|
| старт | `[A, C]` | |
| 1 | берём `A`, он добавляет `B` → `[C, B]` | **A** |
| 2 | берём `C`, он добавляет `D` → `[B, D]` | **C** |
| 3 | берём `B` | **B** |
| 4 | берём `D` | **D** |

Второй `.then` появляется в очереди **только когда выполнился первый** — обработчики цепочки
не ставятся все сразу. Это самое частое место, где ошибаются.

</details>

<details>
<summary>Сниппет 3</summary>

**Ответ:** `script start`, `foo start`, `bar`, `executor`, `script end`, `foo end`, `then`, `timeout`

Разбор:

| шаг | что выполняется | вывод |
|:---:|---|:---:|
| 1 | синхронный лог | script start |
| 2 | `setTimeout` → макроочередь | |
| 3 | `foo()` — тело до `await` синхронно | foo start |
| 4 | вычисляется аргумент `await`, то есть вызов `bar()` — тоже синхронно | bar |
| 5 | `await` ставит продолжение `foo` в микроочередь | |
| 6 | исполнитель `new Promise` — **синхронный** | executor |
| 7 | `.then` в микроочередь (после продолжения `foo`) | |
| 8 | последний синхронный лог | script end |
| 9 | микрозадачи по порядку | foo end, then |
| 10 | макрозадача | timeout |

Два места, где обычно ошибаются: **исполнитель промиса синхронен** (шаг 6) и **вызов внутри
`await` синхронен** (шаг 4).

</details>

<details>
<summary>Сниппет 4</summary>

**Ответ:** `p0`, `t1`, `p1`, `t2`, `p2`

Ключ: микроочередь выгребается **после каждой** макрозадачи, а не после всех сразу.

```
синхронно:      ставим t1, t2 (макро), p0 (микро)
микрозадачи:    p0
макрозадача 1:  t1 → добавляет p1 в микроочередь
микрозадачи:    p1        ← ДО того, как возьмётся t2
макрозадача 2:  t2 → добавляет p2
микрозадачи:    p2
```

Типичная ошибка — ответить `p0, t1, t2, p1, p2`, решив, что таймеры выполняются подряд.

</details>

<details>
<summary>Сниппет 5</summary>

**Ответ:** `sync`, `loop 1`, `micro 1`, `micro 2`, `loop 2`, `loop 3`

Разбор по тикам микроочереди:

| шаг | очередь | вывод |
|:---:|---|:---:|
| синхронно | `run()` доходит до первого `await` и ставит продолжение → `[run₁]`; затем `[run₁, micro1, micro2]` | **sync** |
| 1 | `run₁`: печатает `loop 1`, второй `await` ставит `run₂` → `[micro1, micro2, run₂]` | **loop 1** |
| 2 | `micro1` | **micro 1** |
| 3 | `micro2` | **micro 2** |
| 4 | `run₂`: `loop 2`, ставит `run₃` | **loop 2** |
| 5 | `run₃`: `loop 3` | **loop 3** |

Вывод: **каждая итерация цикла с `await` — отдельная микрозадача**, и между ними успевают
выполниться другие микрозадачи. Цикл `await` не «захватывает» очередь целиком.

</details>

<details>
<summary>Сниппет 6</summary>

**Ответ:** `1`, `6`, `3`, `4`, `5`

- `.then(() => 2)` **пропускается**: промис отклонён, обработчик успеха не вызывается — но
  сам `.then` возвращает новый отклонённый промис и занимает тик очереди;
- `.catch` ловит ошибку → печатает `3` и возвращает **выполненный** промис;
- `.finally` выполняется всегда, печатает `4`, **не меняет** значение и не «съедает» ошибку;
- дальнейший `.then` печатает `5`, потому что после `catch` цепочка снова в успешном состоянии.

Важная деталь про `finally`: он прозрачен для значения и ошибки. Если бы `catch` не было,
`finally` всё равно бы отработал, а ошибка полетела бы дальше.

</details>

<details>
<summary>Как отвечать на такие вопросы вслух</summary>

Не выпаливай список — рассуждай вслух по шагам:

> _«Сначала весь синхронный код: сюда попадают логи вне колбэков и исполнитель промиса. Потом
> микрозадачи — это then и продолжения после await, в порядке постановки. Потом одна
> макрозадача, то есть setTimeout. Разберу по шагам: …»_

Даже если ошибёшься в одной позиции, правильный **процесс** рассуждения оценивается выше
угаданного ответа. И наоборот: верный список без объяснения выглядит как заученный.

</details>
