# Curry (каррирование)

**Тема:** js-interview / function-utils · **Сложность:** medium · **Приоритет:** ⚪ дополнительная

## Условие

Реализуй `curry(fn)` — обёртку, которая позволяет вызывать функцию **по частям**: если передано
меньше аргументов, чем ожидает `fn`, возвращается новая функция, ждущая остальные.

Как только аргументов набралось достаточно — `fn` вызывается и возвращает результат.

## Примеры

```js
function sum(a, b, c) { return a + b + c; }
const curried = curry(sum);

curried(1)(2)(3);      // 6
curried(1, 2)(3);      // 6
curried(1)(2, 3);      // 6
curried(1, 2, 3);      // 6

// частичное применение — практический смысл
const add10 = curried(10);
add10(5, 1);           // 16
add10(1, 1);           // 12
```

## 🎯 Требования

- Работает при любом разбиении аргументов.
- Частично применённая функция **переиспользуема** (вызов `add10` дважды даёт корректные
  результаты, состояние не «протекает»).
- `this` сохраняется.

## 🧠 Ментальная модель

У каждой функции есть свойство **`fn.length`** — количество объявленных параметров (арность).
Это и есть критерий «хватит ли аргументов»:

```js
function sum(a, b, c) {}
sum.length;            // 3
```

Алгоритм рекурсивный:

```
curried(...args):
   если args.length >= fn.length → вызвать fn(...args)
   иначе → вернуть функцию, которая примет ещё аргументы
           и вызовет curried(...args, ...next)
```

Накопленные аргументы живут в **замыкании** — и это же объясняет, почему `add10`
переиспользуема: каждый вызов создаёт **новый** массив, а не мутирует общий.

## ⚠️ Подводные камни именно этой задачи

1. **`fn.length` не считает** параметры со значением по умолчанию и rest-параметр:
   ```js
   function f(a, b = 1) {}   // f.length === 1
   function g(...args) {}    // g.length === 0
   ```
   Значит универсальное каррирование таких функций невозможно — стоит **проговорить это
   ограничение** на интервью, это ценится.
2. **Не мутировать накопленные аргументы.** `args.push(...next)` испортит частично применённую
   функцию при повторном использовании. Нужен новый массив: `[...args, ...next]`.
   Проверь на примере с `add10`, вызванным дважды.
3. **`>=`, а не `===`** при сравнении с `fn.length` — лишние аргументы допустимы.
4. **`this`** прокидывается через `fn.apply(this, args)`, если каррируют метод объекта.
5. Вызов вообще без аргументов (`curried()`) обычно должен возвращать функцию, а не вызывать
   `fn` — с `>=` это работает само (кроме случая `fn.length === 0`).

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) return fn.apply(this, args);
    return (...next) => curried.apply(this, [...args, ...next]);
  };
}
```

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);                       // аргументов хватает — вызываем
    }

    return function (...next) {
      return curried.apply(this, [...args, ...next]);    // НОВЫЙ массив, не мутация
    };
  };
}
```

**Разбор `curried(1)(2)(3)` для `sum(a, b, c)` (`fn.length === 3`):**

| вызов | args | хватает? | что возвращает |
|---|---|:---:|---|
| `curried(1)` | `[1]` | 1 < 3 | функцию, помнящую `[1]` |
| `(2)` | `[1, 2]` | 2 < 3 | функцию, помнящую `[1, 2]` |
| `(3)` | `[1, 2, 3]` | 3 >= 3 | `sum(1, 2, 3)` = **6** ✅ |

**Почему `[...args, ...next]`, а не `args.push(...next)`.** Проверь:

```js
const add10 = curried(10);
add10(5, 1);     // 16
add10(1, 1);     // 12  — с push было бы 26: массив [10] превратился бы в [10,5,1]
```

Каждое частичное применение обязано быть **иммутабельным** — иначе одна и та же
«заготовка» будет накапливать мусор от предыдущих вызовов. Это главный подводный камень задачи
и то, что специально проверяют.

**Именованное функциональное выражение `function curried(...)`** позволяет рекурсивно
обратиться к себе изнутри — без имени пришлось бы городить дополнительную переменную.

</details>

<details>
<summary>Вариант с placeholder (продвинутый, как в lodash)</summary>

```js
const _ = Symbol('placeholder');

function curry(fn) {
  return function curried(...args) {
    const complete = args.length >= fn.length && !args.slice(0, fn.length).includes(_);

    if (complete) return fn.apply(this, args);

    return function (...next) {
      const merged = args.map((arg) => (arg === _ && next.length ? next.shift() : arg));
      return curried.apply(this, [...merged, ...next]);
    };
  };
}

// curried(1, _, 3)(2) → sum(1, 2, 3)
```

Позволяет пропускать позиции: `curried(_, 2)(1)`. На интервью писать не требуют, но упомянуть,
что в lodash это есть, — хороший штрих.

</details>

<details>
<summary>Зачем каррирование на практике</summary>

- **Частичное применение**: `const fetchJson = request('GET', 'application/json')` — фиксируем
  часть параметров один раз.
- **Композиция функций**: `pipe(map(double), filter(isEven))` — каждая функция принимает по
  одному аргументу, что и требуется для композиции.
- **Redux / RxJS / Ramda** построены вокруг этой идеи: `connect(mapState)(Component)`,
  операторы `map(fn)` возвращают функцию, ожидающую поток.

Если спросят «зачем это в реальном коде» — отвечай про **композицию и переиспользование
конфигурации**, а не про «красиво».

</details>
