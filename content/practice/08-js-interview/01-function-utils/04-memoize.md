# Memoize

**Тема:** js-interview / function-utils · **Сложность:** medium · **Приоритет:** ⚪ дополнительная

> Мостик между JS-разделом и алгоритмами: это та же мемоизация, что в
> [Фибоначчи](../../05-recursion-trees/01-recursion/01-fibonacci-memo.md), но в виде универсальной
> обёртки над **любой** функцией.

## Условие

Реализуй `memoize(fn)` — обёртку, которая кеширует результаты вызовов: при повторном вызове с
теми же аргументами `fn` не выполняется, а возвращается сохранённое значение.

Требования:
- **A.** Базовая версия для функции с несколькими аргументами-примитивами.
- **B.** Возможность передать свою функцию-резолвер ключа: `memoize(fn, keyResolver)`.
- **C.** Ответить на вопрос: что делать с объектами-аргументами и утечками памяти?

## Примеры

```js
let calls = 0;
const slowAdd = (a, b) => { calls++; return a + b; };
const fast = memoize(slowAdd);

fast(1, 2);     // 3, calls = 1
fast(1, 2);     // 3, calls = 1   ← из кеша
fast(2, 1);     // 3, calls = 2   ← другие аргументы

// мемоизация рекурсии
const fib = memoize((n) => (n < 2 ? n : fib(n - 1) + fib(n - 2)));
fib(50);        // мгновенно
```

## 🎯 Требования

- Кеш **свой** у каждой обёртки.
- `this` сохраняется.
- Результат `undefined` тоже должен кешироваться (см. подводные камни).

## 🧠 Ментальная модель

Кеш — `Map`, живущая в замыкании. Ключ строится из аргументов.

```
вызов → построить ключ → есть в Map? → вернуть готовое
                        ↓ нет
                     вызвать fn, положить в Map, вернуть
```

Вся сложность задачи — **в выборе ключа**.

## ⚠️ Подводные камни именно этой задачи

1. **Ключ из аргументов.** `args.join(',')` ломается на неоднозначностях:
   `f(1, '2')` и `f('1', 2)` дадут один ключ `"1,2"`. `JSON.stringify(args)` надёжнее (различает
   типы), но медленнее и не работает с функциями/циклами. Универсального решения нет — **это и
   есть тема для обсуждения** на интервью.
2. **Проверять `map.has(key)`, а не `map.get(key)`.** Если функция вернула `undefined`, `0`,
   `''` или `false`, проверка через `get` посчитает это «промахом» и вызовет `fn` заново.
   Классическая ошибка.
3. **Объекты в аргументах.** По значению их сравнить дёшево нельзя. Варианты: `keyResolver`
   (например, по `obj.id`) или `WeakMap` для одноаргументного случая.
4. **Утечка памяти.** Кеш растёт бесконечно. В проде нужен лимит (LRU) или `WeakMap`.
   Упомянуть это — сильный ход: показывает, что ты думаешь о жизненном цикле.
5. **Кеш должен быть внутри `memoize`**, иначе две обёртки будут делить его.
6. Мемоизировать имеет смысл только **чистые** функции. Если `fn` зависит от внешнего состояния
   или времени — кеш вернёт устаревший результат.

## 🔍 Разбор — открывай ТОЛЬКО после своей попытки

<details>
<summary>Решение + объяснение</summary>

```js
function memoize(fn, keyResolver = (...args) => JSON.stringify(args)) {
  const cache = new Map();

  function memoized(...args) {
    const key = keyResolver(...args);

    if (cache.has(key)) return cache.get(key);      // has, а не get!

    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  }

  memoized.clear = () => cache.clear();             // полезное дополнение
  return memoized;
}
```

**Почему `cache.has(key)`, а не `if (cache.get(key) !== undefined)`.**
Функция вполне может легитимно вернуть `undefined`:

```js
const find = memoize((arr, x) => arr.find((v) => v === x));
find([1, 2], 5);     // undefined — валидный результат
find([1, 2], 5);     // с проверкой через get вызвалась бы заново
```

`has` различает «нет в кеше» и «в кеше лежит undefined». То же касается `0`, `''`, `false`,
`null` — все они falsy, но валидны.

**Почему `Map`, а не объект.** Ключи объекта приводятся к строкам, а имена вроде `constructor`
и `__proto__` уже «существуют» в прототипе — `obj['constructor']` вернёт функцию, и обёртка
решит, что результат в кеше. `Map` от этого свободна и даёт честный `O(1)`.

**Сложность:** попадание в кеш — `O(1)` плюс стоимость построения ключа (`JSON.stringify` —
`O(размер аргументов)`). Память растёт с числом различных вызовов.

</details>

<details>
<summary>Версия с WeakMap для объектов-аргументов</summary>

```js
function memoizeOne(fn) {                    // для функции ОДНОГО объектного аргумента
  const cache = new WeakMap();

  return function (obj) {
    if (cache.has(obj)) return cache.get(obj);

    const result = fn.call(this, obj);
    cache.set(obj, result);
    return result;
  };
}
```

**`WeakMap` держит ключи слабо**: если на объект больше никто не ссылается, запись из кеша
удаляется сборщиком мусора автоматически. Это решает проблему утечки — но работает **только с
объектными ключами** и не позволяет перебрать содержимое.

Именно на `WeakMap` строятся кеши в React и многих библиотеках селекторов.

</details>

<details>
<summary>Продакшн-нюанс: ограничение размера (LRU)</summary>

```js
function memoizeLRU(fn, limit = 100) {
  const cache = new Map();

  return function (...args) {
    const key = JSON.stringify(args);

    if (cache.has(key)) {
      const value = cache.get(key);
      cache.delete(key);
      cache.set(key, value);          // переставляем в конец — "недавно использован"
      return value;
    }

    const result = fn.apply(this, args);
    cache.set(key, result);

    if (cache.size > limit) {
      cache.delete(cache.keys().next().value);   // удаляем самый старый ключ
    }

    return result;
  };
}
```

Трюк основан на том, что **`Map` сохраняет порядок вставки**: первый ключ из `keys()` — самый
давно добавленный. Удаление и повторная вставка «омолаживают» запись.

Полноценный LRU-cache (`get`/`put` за `O(1)`) — отдельная популярная задача на дизайн
структуры; она решается связкой `Map` + двусвязный список, и `Map` в JS позволяет упростить её
до этого приёма.

</details>
