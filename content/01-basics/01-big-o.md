# Big O — оценка сложности

## 🎯 Идея

**Big O** — это язык, которым программисты описывают, **как быстро растёт число операций
(или объём памяти) при росте размера входных данных `N`**.

Ключевая мысль: нас не интересует точное время в миллисекундах (оно зависит от компьютера).
Нас интересует **тенденция роста**: если вход вырастет в 10 раз, во сколько раз вырастет работа?

> 📌 На собеседовании фраза _«какая сложность вашего решения?»_ звучит почти всегда.
> Уметь ответить — обязательный навык.

---

## 🧠 Ментальная модель

Big O отвечает на вопрос: **«сколько шагов сделает алгоритм в худшем случае как функция от N?»**

Два правила упрощения:

1. **Отбрасываем константы.** `O(2N)` → `O(N)`, `O(N/2)` → `O(N)`. Нам важна форма роста,
   а не множитель.
2. **Оставляем только старший член.** `O(N² + N)` → `O(N²)`. При большом `N` меньший член
   несущественен.

```js
// O(2N + 3) → упрощаем → O(N)
function example(arr) {
  console.log(arr[0]);        // O(1)
  for (const x of arr) { }    // O(N)
  for (const x of arr) { }    // O(N)
  console.log('done');        // O(1)
}
// 1 + N + N + 1 = 2N + 2 → O(N)
```

## ⏱️ Классы сложности (от лучшего к худшему)

| Big O        | Название            | Пример на JS                               | Как растёт |
|--------------|---------------------|--------------------------------------------|-----------|
| `O(1)`       | константная         | `arr[5]`, `map.get(key)`, `obj.prop`       | не зависит от N |
| `O(log N)`   | логарифмическая     | бинарный поиск в отсортированном массиве    | очень медленно растёт |
| `O(N)`       | линейная            | один цикл `for` по массиву                  | пропорционально N |
| `O(N log N)` | линеаритмическая    | эффективные сортировки (`.sort()`, merge)   | чуть хуже линейной |
| `O(N²)`      | квадратичная        | вложенные циклы                             | быстро становится медленной |
| `O(2ⁿ)`      | экспоненциальная    | наивная рекурсия Фибоначчи                  | практически неприменимо |

**Интуиция масштаба** (при `N = 1000`):
- `O(1)` → 1 операция
- `O(log N)` → ~10 операций
- `O(N)` → 1 000 операций
- `O(N log N)` → ~10 000 операций
- `O(N²)` → 1 000 000 операций 😱

Именно поэтому цель почти всегда — **уйти от `O(N²)` к `O(N)` или `O(N log N)`**.

## 📝 Эталонный разбор: считаем сложность по коду

Разберём **ход мысли**, как определять Big O, глядя на код.

### Пример 1 — один цикл
```js
function sum(arr) {
  let total = 0;              // O(1)
  for (let i = 0; i < arr.length; i++) {
    total += arr[i];          // выполняется N раз
  }
  return total;               // O(1)
}
```
**Мысль:** есть один цикл по всему массиву → работа пропорциональна `N`.
**Ответ:** время `O(N)`, память `O(1)` (только переменная `total`, не зависит от N).

### Пример 2 — вложенные циклы (красный флаг!)
```js
function hasDuplicate(arr) {
  for (let i = 0; i < arr.length; i++) {
    for (let j = i + 1; j < arr.length; j++) {
      if (arr[i] === arr[j]) return true;   // сравниваем каждую пару
    }
  }
  return false;
}
```
**Мысль:** цикл внутри цикла, оба по `N` → примерно `N × N` сравнений.
**Ответ:** время `O(N²)`, память `O(1)`.

### Пример 3 — деление пополам
```js
function countHalvings(n) {
  let count = 0;
  while (n > 1) {
    n = Math.floor(n / 2);    // каждый шаг уменьшает n вдвое
    count++;
  }
  return count;
}
```
**Мысль:** `n` каждый раз делится на 2. Сколько раз можно поделить 1000 на 2, пока не дойдём
до 1? ~10 раз. Это и есть `log₂ N`.
**Ответ:** время `O(log N)`. Логарифм = «сколько раз делим пополам».

### Ключевые сигналы для быстрой оценки
- Один цикл по входу → `O(N)`.
- Вложенный цикл по входу → `O(N²)`.
- Каждый шаг **делит** данные пополам → `O(log N)`.
- Сортировка внутри → как минимум `O(N log N)`.
- Обращение по индексу/ключу (`arr[i]`, `map.get`) → `O(1)`.

## 💾 Space complexity (память)

Считаем **дополнительную** память, которую создаёт алгоритм (не считая входных данных).

```js
function double(arr) {
  const result = [];              // новый массив
  for (const x of arr) result.push(x * 2);
  return result;                  // размер N → O(N) памяти
}

function sumInPlace(arr) {
  let total = 0;                  // одна переменная
  for (const x of arr) total += x;
  return total;                   // O(1) памяти
}
```

> ⚖️ Частый **trade-off**: потратить `O(N)` памяти (например, завести Map), чтобы ускорить
> время с `O(N²)` до `O(N)`. Это классический размен «память ↔ скорость».

## ⚠️ Частые ошибки / чек-лист

- ❌ **Забыть про худший случай.** Big O описывает именно worst case (если не сказано иное).
- ❌ **Считать `.includes()` / `.indexOf()` / `arr.find()` за O(1).** Они `O(N)` — внутри цикл!
  Вложение их в другой цикл незаметно даёт `O(N²)`.
- ❌ **Путать `O(log N)` и `O(N log N)`.** Просто бинарный поиск — `log N`. Сортировка — `N log N`.
- ❌ **Забывать про память.** Всегда называй и время, **и** память.
- ✅ Два независимых цикла подряд — это `O(N + N) = O(N)`, а **не** `O(N²)`. `O(N²)` — только
  когда цикл **вложен** в цикл.
