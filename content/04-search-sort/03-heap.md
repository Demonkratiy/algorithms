# Heap / Priority Queue (куча и очередь с приоритетом)

## 🎯 Идея

**Куча (heap)** — структура, которая за `O(1)` отдаёт **минимум (или максимум)** и за `O(log N)`
позволяет добавить элемент или удалить этот минимум.

Это ровно то, чего не хватает, когда задача звучит как «мне постоянно нужен самый маленький /
самый большой из текущих элементов»: сортировать заново — `O(N log N)` на каждый шаг, линейно
искать — `O(N)`, а куча делает это за логарифм.

> ⚠️ **В JavaScript кучи нет во встроенных типах.** Ни `Array`, ни `Map`, ни что-либо ещё её не
> заменяют. Это важный факт для интервью: в Python есть `heapq`, в Java `PriorityQueue`, в C++
> `priority_queue`, а в JS её **придётся написать самому** (или сказать, что взял бы библиотеку).

---

## 🧠 Как устроена: дерево внутри массива

**Min-heap** — почти полное бинарное дерево, где родитель **не больше** потомков.
Хранится в обычном массиве без ссылок:

```
индексы:  0   1   2   3   4   5
значения: 1   3   2   7   5   4

            1(0)
          /      \
       3(1)      2(2)
      /    \     /
   7(3)   5(4) 4(5)
```

Навигация — арифметика по индексам:

```js
parent(i) = Math.floor((i - 1) / 2)
left(i)   = 2 * i + 1
right(i)  = 2 * i + 2
```

**Важно:** куча **не отсортирована**. Гарантия только одна — в корне (`heap[0]`) лежит минимум.
Соседние элементы в массиве между собой не упорядочены. Это частое заблуждение.

### Две операции, на которых всё держится

**`push` — «всплытие» (sift up).** Кладём элемент в конец и меняем местами с родителем, пока он
меньше родителя. Высота дерева `log N` → `O(log N)`.

**`pop` — «просеивание» (sift down).** Забираем корень, ставим на его место последний элемент и
опускаем его вниз, меняя с **меньшим** из потомков, пока порядок не восстановится. `O(log N)`.

---

## ⏱️ Сложность

| Операция | Стоимость |
|---|:---:|
| `peek` (посмотреть минимум) | `O(1)` |
| `push` | `O(log N)` |
| `pop` | `O(log N)` |
| Построение кучи из массива (heapify) | **`O(N)`** — не `O(N log N)`! |
| Поиск произвольного элемента | `O(N)` — куча для этого не предназначена |

**Сравнение подходов для «k наибольших из N»:**

| Способ | Время | Память |
|---|:---:|:---:|
| Полная сортировка | `O(N log N)` | `O(N)` |
| **Min-heap размера k** | **`O(N log k)`** | **`O(k)`** |
| Quickselect | `O(N)` в среднем | `O(1)` |

Куча выигрывает, когда `k << N` **или когда данные приходят потоком** и не помещаются в память
целиком — отсортировать их просто невозможно.

## 📝 Реализация min-heap

```js
class MinHeap {
  constructor(compare = (a, b) => a - b) {
    this.items = [];
    this.compare = compare;              // < 0 ⇒ a приоритетнее b
  }

  get size() { return this.items.length; }

  peek() { return this.items[0]; }

  push(value) {
    this.items.push(value);
    this.#siftUp(this.items.length - 1);
  }

  pop() {
    if (this.items.length === 0) return undefined;

    const top = this.items[0];
    const last = this.items.pop();

    if (this.items.length > 0) {
      this.items[0] = last;              // последний элемент — в корень
      this.#siftDown(0);
    }

    return top;
  }

  #siftUp(index) {
    while (index > 0) {
      const parent = Math.floor((index - 1) / 2);
      if (this.compare(this.items[index], this.items[parent]) >= 0) break;

      [this.items[index], this.items[parent]] = [this.items[parent], this.items[index]];
      index = parent;
    }
  }

  #siftDown(index) {
    const n = this.items.length;

    while (true) {
      const left = 2 * index + 1;
      const right = 2 * index + 2;
      let smallest = index;

      if (left < n && this.compare(this.items[left], this.items[smallest]) < 0) smallest = left;
      if (right < n && this.compare(this.items[right], this.items[smallest]) < 0) smallest = right;

      if (smallest === index) break;     // порядок восстановлен

      [this.items[index], this.items[smallest]] = [this.items[smallest], this.items[index]];
      index = smallest;
    }
  }
}
```

**Max-heap** получается сменой компаратора: `new MinHeap((a, b) => b - a)`.
**Очередь с приоритетом** — та же куча с компаратором по полю:
`new MinHeap((a, b) => a.priority - b.priority)`.

### Разбор `pop` по шагам

```
до:      [1, 3, 2, 7, 5, 4]     минимум = 1
1) забрали корень (1), взяли последний (4)
         [4, 3, 2, 7, 5]
2) siftDown(0): потомки 3 и 2 → меньший 2 → меняем
         [2, 3, 4, 7, 5]
3) у индекса 2 потомков нет → стоп
после:   [2, 3, 4, 7, 5]        минимум = 2 ✅
```

## ⚠️ Частые ошибки / чек-лист

- ❌ **Считать, что куча отсортирована.** Упорядочен только путь «родитель → потомок».
  `heap.items` в общем случае — не отсортированный массив.
- ❌ **В `siftDown` сравнивать только с левым потомком** — надо выбрать **меньшего из двух**.
- ❌ **Проверять границы после обращения**: `items[left]` при `left >= n` даст `undefined`, и
  сравнение молча даст `NaN`. Проверка `left < n` — до сравнения.
- ❌ **Забыть `siftDown` после `pop`** — куча развалится, но ошибки не будет: баг проявится
  позже неверными ответами.
- ❌ **Пустая куча:** `pop()` и `peek()` должны возвращать `undefined`, а не падать.
- ❌ **Использовать max-heap там, где нужен min-heap.** Для «k наибольших» держат
  **min**-heap размера `k` (выбрасывая наименьший) — это контринтуитивно, но правильно.
- ✅ На интервью честно скажи: _«в JS кучи нет, напишу минимальную версию — мне нужны только
  push, pop и peek»_. Полный класс с `compare` и приватными методами писать не обязательно.

## 🧭 Когда брать кучу

| Признак в условии | Решение |
|---|---|
| «k наибольших / наименьших» | min-heap размера `k` → `O(N log k)` |
| «медиана потока» | две кучи (max для левой половины, min для правой) |
| «слить k отсортированных списков» | куча из `k` голов → `O(N log k)` |
| «следующее событие по времени» | очередь с приоритетом (планировщик) |
| «кратчайший путь во взвешенном графе» | алгоритм Дейкстры = BFS + куча |
| Данные приходят **потоком** | куча, потому что отсортировать нельзя |

## ✅ Мини-опрос для самопроверки

1. Что гарантирует куча и чего она **не** гарантирует?
2. Как по индексу `i` найти родителя и потомков?
3. Почему `pop` — это `O(log N)`, а `peek` — `O(1)`?
4. Для задачи «k наибольших элементов» какую кучу заводить и почему?
5. Почему в JS нельзя просто взять встроенную приоритетную очередь?
6. Когда куча лучше сортировки, а когда хуже?

<details>
<summary>Ответы</summary>

1. Гарантирует, что в корне лежит минимум (для min-heap) и что каждый родитель не больше своих
   потомков. **Не** гарантирует общей отсортированности: соседние элементы массива между собой
   не упорядочены, и найти произвольный элемент можно только за `O(N)`.
2. `parent = Math.floor((i - 1) / 2)`, `left = 2i + 1`, `right = 2i + 2`.
3. `peek` — просто чтение `items[0]`. `pop` требует переместить последний элемент в корень и
   «просеять» его вниз; путь от корня до листа равен высоте дерева, то есть `log N`.
4. **Min-heap размера `k`**. Держим в ней `k` наибольших встреченных: если новый элемент больше
   корня (наименьшего из отобранных), выбрасываем корень и вставляем новый. В итоге корень — это
   `k`-й по величине. Max-heap заставила бы хранить все `N` элементов.
5. В стандарте JS её нет: `Array`, `Map`, `Set` не дают `O(log N)` вставки с поддержанием
   порядка. Нужно писать самому либо брать библиотеку. Об этом стоит сказать вслух.
6. Куча лучше, когда `k << N` (`O(N log k)` против `O(N log N)`), когда данные идут потоком или
   нужно динамически добавлять/извлекать. Сортировка лучше, когда нужен **весь** упорядоченный
   результат или когда данных мало и важна простота кода.

</details>
