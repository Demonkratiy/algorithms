# Поиск и сортировка

Этот раздел о том, как использовать порядок: полностью упорядочить данные, найти границу или поддерживать только самый приоритетный элемент. На обзор хватит 5–10 минут. Цель — различать эти задачи до реализации и не оплачивать более сильную операцию, чем требуется.

## Общая идея

Обычный перебор проверяет варианты по одному. **Binary Search** может исключать целый диапазон, если известна монотонность: проверка делит кандидатов на две группы с одной границей перехода. Отсортированный массив — знакомый пример, но областью поиска могут быть и возможные значения ответа.

Монотонность здесь означает не просто «числа растут». Нужна проверка вида «до некоторой границы ответ false, после неё true» или наоборот. Например, при неизменных остальных условиях увеличение допустимого лимита ресурса не должно превращать выполнимый план в невыполнимый. Такое свойство надо доказать для конкретной задачи, а не предполагать по слову «минимальный».

**Sorting** создаёт общий порядок между элементами. После неё проще рассматривать соседей, сравнивать интервалы и применять другие паттерны. Но сортировка меняет расположение данных: исходные индексы и порядок могут быть частью требуемого ответа.

**Heap** поддерживает более слабое условие. В Min-heap значение родителя не больше значений его детей, поэтому в корне находится минимум. Это не значит, что все элементы массива-хранилища отсортированы. Priority Queue — интерфейс «добавить элемент, взять наиболее приоритетный»; Heap — распространённая реализация этого интерфейса.

Отсюда три разных вопроса:

- Нужен конкретный элемент или граница в уже упорядоченной области? Рассмотри Binary Search.
- Нужен порядок всех элементов? Рассмотри Sorting.
- Данные меняются, а каждый раз нужен ближайший приоритет? Рассмотри Heap.

Они могут работать вместе. Например, предварительная сортировка способна подготовить данные для поиска, но её стоимость входит в общую оценку.

## Где это встречается

В интерфейсах встречаются упорядоченные списки, временные интервалы и приоритеты задач. На интервью похожие модели проверяют разные навыки: Binary Search — границы и исключение вариантов, Sorting — выбор порядка, Heap — поддержку состояния при изменениях.

Итеративный Binary Search по массиву из `N` элементов требует `O(log N)` времени и `O(1)` дополнительной памяти. Для Binary Search по ответу нужно дополнительно учесть работу и память самой проверки: она не обязана быть константной.

Для бинарной Heap из `N` элементов просмотр корня занимает `O(1)` времени; вставка и извлечение корня — `O(log N)` времени в худшем случае. Итеративное восстановление свойства Heap использует `O(1)` дополнительной памяти, а сама структура хранит `O(N)` элементов. Размер структуры и память отдельной операции — разные оценки.

У JS есть важные детали: `sort()` меняет исходный массив, а без comparator сравнивает строковые представления. Comparator должен задавать согласованный порядок. Стабильность сортировки сохраняет относительный порядок элементов, которые comparator считает равными, но не сохраняет весь исходный порядок. ECMAScript не задаёт единственную оценку времени и памяти встроенной сортировки: на интервью уточняй принятую модель и учитывай копию массива, если она создаётся.

## Маршрут изучения

1. [Binary Search](01-binary-search.md). Освой смысл границ, условие завершения и разные контракты: найти совпадение, позицию вставки или границу допустимых ответов.
2. [Sorting](02-sorting.md). Разбери comparator, mutation и использование порядка как подготовительного шага; сравни идеи Merge Sort и Quick Sort.
3. [Heap / Priority Queue](03-heap.md). Научись поддерживать экстремум без полной сортировки; свяжи дерево отношений с индексами массива-хранилища.

На каждом шаге формулируй invariant: что остаётся истинным после изменения диапазона или структуры. Для Binary Search вручную проверь пустой диапазон, одного кандидата, отсутствие ответа и повторы.

## Что получится после раздела

Ты сможешь объяснить, сколько порядка действительно нужно задаче, и выбрать соответствующий инструмент.

Перед переходом ответь:

- Почему отброшенная половина не содержит нужный ответ?
- Чем поиск любого совпадения отличается от поиска первого?
- Можно ли сортировать вход без потери нужной информации?
- Почему Heap не является полностью отсортированным массивом?
- Учтены ли в оценках и время, и память подготовки?
