# Linked Lists (связные списки)

## 🎯 Идея

**Связный список** — структура из «узлов» (nodes). Каждый узел хранит **значение** и **ссылку**
на следующий узел. Последний ссылается на `null`.

```js
class ListNode {
  constructor(val = 0, next = null) {
    this.val = val;
    this.next = next;
  }
}
```

```
head
 ↓
[1|•]→[2|•]→[3|•]→[4|null]
```

Главное отличие от массива: **нет индексов и нет непрерывной памяти**. Чтобы попасть в 5-й
элемент, нужно пройти по ссылкам 5 раз. Зато вставка/удаление в середине — просто
переприсваивание пары ссылок, без сдвига остальных элементов.

> 💡 В JS связные списки редко нужны «в проде» (у нас есть массивы), но их обожают на интервью:
> они проверяют **аккуратность работы с указателями** — то, что нельзя подсмотреть в API языка.

---

## 🧠 Как распознать (ментальная модель)

Признаки в условии:
- Дан `head` списка, `ListNode`, `.next` — это уже прямая подсказка;
- «развернуть список», «найти цикл», «найти середину», «удалить N-й с конца»,
  «слить два отсортированных списка»;
- «сделать за `O(1)` памяти» — значит переставлять ссылки, а не копировать в массив.

### Три техники, которые закрывают ~90% задач

**1. Три указателя (`prev` / `curr` / `next`)** — для разворота и любых перестановок ссылок.
Ментальная модель: идёшь по списку и «переворачиваешь стрелки» одну за другой, но перед
переворотом обязан **сохранить** ссылку вперёд, иначе потеряешь хвост.

**2. Fast / Slow (два указателя разной скорости)** — «черепаха и заяц».
`slow` шагает на 1, `fast` — на 2. Когда `fast` дошёл до конца, `slow` ровно в середине.
Тот же приём находит цикл: в цикле быстрый неизбежно догонит медленного.

**3. Dummy node (фиктивная голова)** — узел-заглушка перед настоящей головой:
```js
const dummy = new ListNode(0, head);
```
Убирает частный случай «а если операция затрагивает первый элемент?». Нужен почти всегда, когда
голова списка может измениться. В конце возвращаем `dummy.next`.

> ⚠️ Общее правило: **связные списки — это про edge cases**, а не про сложную логику.
> Пустой список, один узел, изменение головы, последний узел — проверяй всегда.

## ⏱️ Сложность

| Операция | Linked List | Array (для сравнения) |
|---|:---:|:---:|
| Доступ по «индексу» | `O(N)` | `O(1)` |
| Поиск значения | `O(N)` | `O(N)` |
| Вставка/удаление в **начало** | `O(1)` | `O(N)` (сдвиг) |
| Вставка/удаление, когда узел уже найден | `O(1)` | `O(N)` |
| Вставка/удаление в **конец** (без ссылки на хвост) | `O(N)` | `O(1)` амортиз. |

Почти все алгоритмы на списках — один-два прохода: **время `O(N)`, память `O(1)`**.
Если используешь массив или `Set` для хранения узлов — память становится `O(N)`, и на интервью
попросят улучшить.

## 📝 Эталонный разбор

### Задача: Reverse Linked List
Дан `head` односвязного списка. Развернуть его и вернуть новую голову.

```
Вход:  1 → 2 → 3 → 4 → null
Выход: 4 → 3 → 2 → 1 → null
```

### Ход мысли (UMPIRE)

**Understand:** на входе голова (может быть `null`). На выходе — голова развёрнутого списка.
Edge cases: пустой список, один узел.

**Match:** перестановка ссылок → **три указателя** `prev / curr / next`.

**Plan (на словах):**
- `prev = null` — то, что уже развёрнуто (сначала ничего, и это же будущий `null`-хвост);
- `curr = head` — текущий узел;
- на каждом шаге: запомнить `curr.next`, развернуть стрелку `curr.next = prev`,
  сдвинуть оба указателя вперёд;
- когда `curr === null`, `prev` — новая голова.

**Ключевой момент:** порядок из 4 строк, который нельзя менять местами.

### Решение
```js
function reverseList(head) {
  let prev = null;
  let curr = head;

  while (curr !== null) {
    const next = curr.next;   // 1. СОХРАНИТЬ, иначе после шага 2 хвост потерян
    curr.next = prev;         // 2. развернуть стрелку назад
    prev = curr;              // 3. prev двигается на текущий
    curr = next;              // 4. curr двигается на сохранённый следующий
  }

  return prev;                // curr === null, значит prev — последний реальный узел
}
```

### Трассировка `1 → 2 → 3 → null`

| шаг | prev | curr | next | что уже развёрнуто |
|:---:|:----:|:----:|:----:|--------------------|
| старт | null | 1 | — | — |
| 1 | 1 | 2 | 2 | `1→null`, остаток `2→3→null` |
| 2 | 2 | 3 | 3 | `2→1→null`, остаток `3→null` |
| 3 | 3 | null | null | `3→2→1→null` |

Возвращаем `prev = 3` ✅

**Почему возвращаем `prev`, а не `curr`:** цикл заканчивается, когда `curr` стал `null`, то есть
«свалился» за конец. Последний реальный узел остался в `prev`.

**Сложность:** время `O(N)` — один проход. Память `O(1)` — три переменные, новых узлов нет.

### Тот же разворот рекурсией (для сравнения)
```js
function reverseListRecursive(head) {
  if (head === null || head.next === null) return head;   // база: пусто или один узел

  const newHead = reverseListRecursive(head.next);        // развернули хвост
  head.next.next = head;                                  // сосед справа теперь смотрит на нас
  head.next = null;                                       // а мы — в null (иначе цикл из двух!)
  return newHead;
}
```
Время `O(N)`, но память **`O(N)`** — глубина стека вызовов. На интервью назови это как
trade-off: итеративная версия лучше по памяти.

## 🔧 Как тестировать себя офлайн

Чтобы прогонять решения в консоли браузера или Node, держи под рукой хелперы:

```js
class ListNode {
  constructor(val = 0, next = null) { this.val = val; this.next = next; }
}

// массив → список
function buildList(arr) {
  const dummy = new ListNode();
  let tail = dummy;
  for (const v of arr) { tail.next = new ListNode(v); tail = tail.next; }
  return dummy.next;
}

// список → массив (для наглядного сравнения)
function toArray(head) {
  const out = [];
  while (head) { out.push(head.val); head = head.next; }
  return out;
}

// пример: toArray(reverseList(buildList([1, 2, 3, 4]))) → [4, 3, 2, 1]
```

> ⚠️ `toArray` зациклится, если в списке есть цикл. Для задач про цикл ограничивай счётчиком.

## ⚠️ Частые ошибки / чек-лист

- ❌ **Потеря ссылки.** Присвоил `curr.next = prev` до того, как сохранил `curr.next` — остаток
  списка недостижим. Правило: **сначала сохраняем, потом переписываем**.
- ❌ **Не обработан пустой список.** `head === null` — валидный вход почти везде. Проверь, что
  код не падает на `head.next` при `head === null`.
- ❌ **Список из одного узла.** Часто ломает fast/slow и «удалить N-й с конца».
- ❌ **Забыть про изменение головы** → отсюда привычка использовать `dummy`.
- ❌ **Порядок проверок в `while (fast && fast.next)`.** Сначала `fast`, потом `fast.next`,
  иначе `Cannot read properties of null`.
- ❌ **Возвращать не то.** После цикла разворота возвращается `prev`, а не `curr` и не `head`.
- ❌ **Забыть `head.next = null`** в рекурсивном развороте → цикл из двух узлов и вечный обход.
- ✅ После написания кода **прогони руками список из 2 элементов** — этого хватает, чтобы поймать
  большинство ошибок с указателями.

## ✅ Мини-опрос для самопроверки

1. Почему в развороте нельзя сначала написать `curr.next = prev`, а потом `const next = curr.next`?
2. Что вернёт `reverseList(null)` и почему код не падает?
3. Зачем нужен dummy node? Приведи задачу, где без него появляется лишняя ветка `if`.
4. Как за один проход найти середину списка? Что вернёт этот способ при чётной длине?
5. Почему fast/slow гарантированно находит цикл, а не проскакивает медленного?
6. Какая сложность по памяти у рекурсивного разворота и почему она хуже итеративного?

<details>
<summary>Ответы</summary>

1. Потому что `curr.next` — единственная ссылка на весь остаток списка. Переписав её, теряешь
   доступ к хвосту: из `curr` уже никак не попасть в следующий узел.
2. Вернёт `null`. Цикл `while (curr !== null)` не выполнится ни разу, вернётся `prev`, который
   остался `null`. Это и есть правильный ответ для пустого списка.
3. Dummy убирает частный случай «операция затрагивает саму голову». Пример — «удалить N-й узел
   с конца»: если удаляется первый узел, без dummy нужна отдельная ветка `return head.next`.
   С dummy код удаления единообразен, а в конце возвращаем `dummy.next`.
4. `slow` на 1 шаг, `fast` на 2, пока `fast && fast.next`. При **чётной** длине вернётся
   **вторая** из двух средних (для `[1,2,3,4]` — узел `3`). Если нужна первая, условие пишут как
   `while (fast.next && fast.next.next)`.
5. Потому что относительная скорость сближения — ровно 1 узел за шаг: `fast` приближается к
   `slow` на одну позицию за итерацию, значит перескочить не может — обязательно совпадут.
6. `O(N)` — каждый вложенный вызов держит фрейм в стеке до самого конца списка. Итеративная
   версия использует `O(1)`. На длинном списке рекурсия может дать stack overflow.

</details>
