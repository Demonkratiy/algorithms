# Binary Trees (DFS / BFS)

## 🎯 Идея

**Бинарное дерево** — структура, где у каждого узла есть значение и **не более двух** потомков:
`left` и `right`.

```js
class TreeNode {
  constructor(val = 0, left = null, right = null) {
    this.val = val;
    this.left = left;
    this.right = right;
  }
}
```

```
        1
       / \
      2   3
     / \
    4   5
```

Ключевое свойство: **каждое поддерево — само по себе дерево**. Отсюда почти все задачи на
деревья решаются рекурсией в три строки, если правильно сформулировать контракт.

> 💡 Для фронтендера аналогия прямая: **DOM — это дерево**, Virtual DOM — тоже, дерево
> комментариев, меню, файловая система, JSON. Обходы деревьев — это то, что React делает
> при reconciliation.

## 🧠 Как распознать (ментальная модель)

### Универсальный рекурсивный контракт

Для 80% задач на деревья работает один шаблон:

```js
function solve(node) {
  if (node === null) return /* ответ для пустого дерева */;   // БАЗА

  const left = solve(node.left);        // доверяем: вернёт верный ответ
  const right = solve(node.right);

  return /* как скомбинировать left, right и node.val */;
}
```

Всё, что нужно решить, — **два вопроса**:
1. Что вернуть для `null`?
2. Как из ответов поддеревьев и текущего значения получить ответ для себя?

### Два способа обхода

**DFS (в глубину)** — рекурсия (или явный стек). Три порядка:

| Порядок | Когда обрабатываем узел | Применение |
|---|---|---|
| **Pre-order** (NLR) | до потомков | копирование дерева, сериализация, «сверху вниз» |
| **In-order** (LNR) | между левым и правым | **BST → отсортированная последовательность** |
| **Post-order** (LRN) | после потомков | удаление, подсчёт высоты, «снизу вверх» |

```js
function dfs(node) {
  if (node === null) return;

  // pre-order:  console.log(node.val);
  dfs(node.left);
  // in-order:   console.log(node.val);
  dfs(node.right);
  // post-order: console.log(node.val);
}
```

Для дерева выше: pre → `1 2 4 5 3`, in → `4 2 5 1 3`, post → `4 5 2 3 1`.

**BFS (в ширину, по уровням)** — очередь.

```js
function bfs(root) {
  if (root === null) return [];

  const result = [];
  const queue = [root];

  while (queue.length > 0) {
    const levelSize = queue.length;        // ФИКСИРУЕМ размер уровня!
    const level = [];

    for (let i = 0; i < levelSize; i++) {
      const node = queue.shift();
      level.push(node.val);
      if (node.left) queue.push(node.left);
      if (node.right) queue.push(node.right);
    }

    result.push(level);
  }

  return result;
}
```

**Приём «зафиксировать `levelSize`»** — то, что превращает обычный BFS в обход **по уровням**.
Без него все узлы смешаются в один список. Запомни его — он нужен в половине задач на BFS.

### Что выбрать: DFS или BFS

| Признак в условии | Обход |
|---|---|
| глубина, высота, «есть ли путь», сумма пути | **DFS** |
| «по уровням», «правый вид дерева», «средние по уровням» | **BFS** |
| **кратчайший** путь / минимальная глубина | **BFS** (найдёт раньше) |
| проверка BST, поиск в BST | DFS (in-order) |

### Binary Search Tree (BST)

Особый вид дерева: для **каждого** узла все значения в левом поддереве **меньше**, в правом —
**больше**.

```
     5
    / \
   3   8
  / \   \
 1   4   9
```

Свойства:
- поиск/вставка/удаление — `O(h)`, где `h` — высота: `O(log N)` для сбалансированного,
  **`O(N)` для вырожденного** (дерево-«палка»);
- **in-order обход даёт отсортированную последовательность** — важнейшее свойство,
  на нём строится проверка BST и поиск k-го наименьшего.

## ⏱️ Сложность

| Операция | Время | Память |
|---|:---:|:---:|
| Любой обход (DFS/BFS) | `O(N)` | см. ниже |
| DFS (рекурсия) | | `O(h)` — глубина стека |
| BFS | | `O(w)` — максимальная ширина уровня |
| Поиск в BST | `O(h)` | `O(h)` |

Где `h` — высота дерева, `w` — максимальная ширина.

**Важные оценки для интервью:**
- сбалансированное дерево: `h = O(log N)`, `w = O(N)` (последний уровень — половина узлов);
- вырожденное («палка»): `h = O(N)`, `w = O(1)`;
- поэтому **DFS выгоднее по памяти на узких деревьях, BFS — на глубоких**.

> ⚠️ Отвечая «память `O(N)`», уточняй: _«O(h) на стек рекурсии; в худшем случае вырожденного
> дерева это O(N), для сбалансированного — O(log N)»_. Такой ответ ценится намного выше.

## 📝 Эталонный разбор

### Задача: Maximum Depth of Binary Tree
Найти максимальную глубину — число узлов на самом длинном пути от корня до листа.

```
        3
       / \
      9  20        → глубина 3
        /  \
       15   7
```

### Ход мысли

**Контракт:**
1. Что вернуть для `null`? Пустое дерево имеет глубину `0`.
2. Как скомбинировать? Глубина моего дерева = `1` (я) + максимум из глубин поддеревьев.

### Решение (DFS)
```js
function maxDepth(root) {
  if (root === null) return 0;                                    // база

  return 1 + Math.max(maxDepth(root.left), maxDepth(root.right));
}
```

Три строки — потому что контракт сформулирован верно. Не пытайся раскручивать стек в голове;
доверяй тому, что вложенные вызовы вернут правильные глубины.

**Трассировка (снизу вверх):**
```
maxDepth(15) = 1 + max(0, 0) = 1
maxDepth(7)  = 1
maxDepth(20) = 1 + max(1, 1) = 2
maxDepth(9)  = 1
maxDepth(3)  = 1 + max(1, 2) = 3 ✅
```

**Сложность:** время `O(N)` — каждый узел посещается один раз.
Память `O(h)`: `O(log N)` для сбалансированного, `O(N)` для вырожденного.

### То же самое через BFS (считаем уровни)
```js
function maxDepthBFS(root) {
  if (root === null) return 0;

  let depth = 0;
  const queue = [root];

  while (queue.length > 0) {
    const levelSize = queue.length;
    for (let i = 0; i < levelSize; i++) {
      const node = queue.shift();
      if (node.left) queue.push(node.left);
      if (node.right) queue.push(node.right);
    }
    depth++;                       // прошли целый уровень
  }

  return depth;
}
```
Время `O(N)`, память `O(w)`. Полезно уметь показать оба способа и объяснить разницу в памяти.

## 🔧 Как тестировать себя офлайн

```js
class TreeNode {
  constructor(val = 0, left = null, right = null) {
    this.val = val; this.left = left; this.right = right;
  }
}

// массив в формате LeetCode (по уровням, null для пропусков) → дерево
function buildTree(arr) {
  if (arr.length === 0 || arr[0] === null) return null;

  const root = new TreeNode(arr[0]);
  const queue = [root];
  let i = 1;

  while (i < arr.length) {
    const node = queue.shift();
    if (i < arr.length && arr[i] !== null) {
      node.left = new TreeNode(arr[i]);
      queue.push(node.left);
    }
    i++;
    if (i < arr.length && arr[i] !== null) {
      node.right = new TreeNode(arr[i]);
      queue.push(node.right);
    }
    i++;
  }

  return root;
}

// пример: maxDepth(buildTree([3, 9, 20, null, null, 15, 7])) → 3
```

## ⚠️ Частые ошибки / чек-лист

- ❌ **Забыть базу `node === null`** → `Cannot read properties of null (reading 'val')`.
  Это ошибка №1 на деревьях.
- ❌ **Проверять `node.left === null` вместо входа в `null`.** Правильный шаблон — сначала
  рекурсивный вызов, база ловится **внутри**. Иначе код обрастает лишними проверками.
- ❌ **Забыть `levelSize` в BFS** → уровни смешаются.
- ❌ **`queue.shift()`** — это `O(N)`. На маленьких деревьях допустимо, но **проговори**, что
  знаешь про стоимость и что правильнее указатель головы (см.
  [stack-queue.md](../03-linear-structures/02-stack-queue.md)).
- ❌ **Путать глубину и высоту.** Глубина узла — расстояние **от корня**; высота — расстояние
  **до самого дальнего листа**. Для дерева целиком они совпадают.
- ❌ **Проверять BST только «сын меньше отца»** — неверно, нужны **диапазоны** (см. задачу
  Validate BST).
- ❌ **Класть в результат общий массив без копии** в задачах про пути (`result.push([...path])`).
- ✅ Всегда проверяй: пустое дерево (`null`), дерево из одного узла, вырожденная «палка».

## ✅ Мини-опрос для самопроверки

1. Сформулируй универсальный рекурсивный контракт для задач на деревья.
2. Какой обход даёт отсортированную последовательность для BST и почему?
3. Чему равна память у DFS и у BFS, и в каких деревьях что выгоднее?
4. Зачем в BFS фиксировать `levelSize` перед внутренним циклом?
5. Почему проверка «левый потомок меньше узла, правый больше» **не** доказывает, что дерево — BST?
6. Когда для поиска пути выгоднее BFS, а не DFS?

<details>
<summary>Ответы</summary>

1. «Если `node === null` — вернуть ответ для пустого дерева. Иначе получить ответы от левого и
   правого поддеревьев (доверяя, что они верны) и скомбинировать их со значением текущего узла».
2. **In-order** (левое → узел → правое). По определению BST все значения слева меньше, справа
   больше; такой порядок посещения выдаёт их по возрастанию.
3. DFS — `O(h)` (глубина стека), BFS — `O(w)` (ширина уровня). Для **сбалансированного** дерева
   DFS выгоднее (`O(log N)` против `O(N)` — последний уровень содержит ~половину узлов).
   Для **глубокого/вырожденного** выгоднее BFS (`O(1)`–`O(w)` против `O(N)`).
4. Чтобы отделить текущий уровень от следующего: во время внутреннего цикла в очередь
   добавляются потомки, и `queue.length` меняется. Зафиксировав размер **до** цикла, мы
   обрабатываем ровно те узлы, что были на уровне.
5. Потому что условие BST — глобальное, а не локальное. Пример:
   `5 → left: 3 → right: 6`. Локально `6 > 3` ✅, но `6 > 5`, а находится в **левом** поддереве
   корня — свойство BST нарушено. Нужны диапазоны `(min, max)`, передаваемые вниз по рекурсии.
6. Когда нужен **кратчайший** путь или минимальная глубина: BFS находит ближайший подходящий
   узел раньше и может остановиться, тогда как DFS может сначала уйти в глубокую ветку.

</details>
