# Sorting (сортировки)

## 🎯 Идея

На интервью сортировка нужна в трёх ролях:

1. **Инструмент.** «Отсортирую — и задача станет простой»: дубликаты рядом, интервалы по
   порядку, можно применить two pointers или бинарный поиск.
2. **Знание про `Array.prototype.sort()`** — его ловушки, стабильность, сложность. Это чистый
   JS-вопрос, который любят на FE-секциях.
3. **Понимание алгоритмов** — merge sort и quick sort как примеры «разделяй и властвуй».
   Писать их с нуля просят реже, но **объяснить** обязаны уметь.

---

## ⚠️ Главная JS-ловушка: `sort()` без компаратора

```js
[1, 10, 2, 21].sort();            // [1, 10, 2, 21]  ← НЕ отсортировано!
```

**Почему.** Без компаратора `sort()` приводит элементы к **строкам** и сравнивает
лексикографически: `"10" < "2"`, потому что символ `'1'` идёт раньше `'2'`.

**Правильно для чисел:**
```js
[1, 10, 2, 21].sort((a, b) => a - b);    // [1, 2, 10, 21]   по возрастанию
[1, 10, 2, 21].sort((a, b) => b - a);    // [21, 10, 2, 1]   по убыванию
```

**Как читать компаратор.** `sort` ожидает функцию, которая возвращает:
- **отрицательное** → `a` идёт раньше `b`;
- **ноль** → порядок между ними не меняется;
- **положительное** → `b` идёт раньше `a`.

Отсюда мнемоника: `a - b` — «по возрастанию», `b - a` — «по убыванию».

### Другие важные факты про `sort()`

- **Мутирует исходный массив** и возвращает его же. Нужна копия — `[...arr].sort(...)`
  или `arr.toSorted(...)` (ES2023, есть в современных браузерах и Node 20+).
- **Стабильна** по спецификации начиная с ES2019: равные элементы сохраняют исходный
  относительный порядок. Это важно при сортировке по нескольким ключам.
- **Сложность** — `O(N log N)` времени. Память зависит от движка (V8 использует TimSort,
  `O(N)` в худшем случае).
- Для **строк** `sort()` без компаратора работает корректно, но не учитывает локаль
  (`'ё'`, регистр). Для человекочитаемой сортировки — `localeCompare`:
  ```js
  words.sort((a, b) => a.localeCompare(b));
  ```

## 🧠 Как распознать: «здесь поможет сортировка»

| Признак в условии | Что даёт сортировка |
|---|---|
| «есть ли дубликаты», «есть ли пара с суммой X» | одинаковые рядом → two pointers |
| **интервалы**: слияние, пересечение, «сколько переговорок» | обработка слева направо в одном порядке |
| «k-й по величине / по частоте» | сортировка + индекс `k` |
| «анаграммы» | сортировка **символов слова** как ключ (ты это уже делал в Group Anagrams) |
| «минимальная разница между элементами» | ближайшие элементы окажутся соседями |

> ⚠️ **Цена вопроса.** Сортировка — `O(N log N)`. Если существует решение через `Map`/`Set` за
> `O(N)`, сортировка будет **хуже**. Всегда спрашивай себя: «а нужен ли мне порядок, или
> достаточно частот?» Пример: Two Sum решается за `O(N)` через `Map`, сортировать не нужно.

## ⏱️ Сложность основных алгоритмов

| Алгоритм | Среднее | Худшее | Память | Стабильность |
|---|:---:|:---:|:---:|:---:|
| Bubble / Insertion | `O(N²)` | `O(N²)` | `O(1)` | стабильные |
| **Merge Sort** | `O(N log N)` | `O(N log N)` | `O(N)` | **стабильная** |
| **Quick Sort** | `O(N log N)` | **`O(N²)`** | `O(log N)` стек | нестабильная |
| Counting / Bucket | `O(N + K)` | `O(N + K)` | `O(K)` | стабильная |
| `Array.sort()` (V8) | `O(N log N)` | `O(N log N)` | `O(N)` | стабильная |

**Нижняя граница `O(N log N)`** доказана для любой сортировки **сравнениями**. Обойти её можно
только не сравнивая элементы — counting sort / bucket sort используют значения как индексы и
дают `O(N + K)`, но требуют ограниченного диапазона значений.
(Ты уже применял эту идею в Top K Frequent через bucket по частотам.)

## 📝 Эталонный разбор: Merge Sort

Merge sort — лучший пример «divide & conquer», и его шаг `merge` ты уже писал руками в
[Merge Sorted Arrays](../practice/02-arrays-strings/01-two-pointers/03-merge-sorted-arrays.md).

### Идея
1. **Divide:** разбить массив пополам.
2. **Conquer:** рекурсивно отсортировать каждую половину.
3. **Combine:** слить две отсортированные половины за `O(N)`.

```
[5, 2, 4, 1]
   ├── [5, 2] → [2, 5]
   └── [4, 1] → [1, 4]
слияние → [1, 2, 4, 5]
```

### Решение
```js
function mergeSort(arr) {
  if (arr.length <= 1) return arr;                 // база рекурсии

  const mid = Math.floor(arr.length / 2);
  const left = mergeSort(arr.slice(0, mid));
  const right = mergeSort(arr.slice(mid));

  return merge(left, right);
}

function merge(a, b) {
  const result = [];
  let i = 0;
  let j = 0;

  while (i < a.length && j < b.length) {
    if (a[i] <= b[j]) result.push(a[i++]);         // <= сохраняет стабильность
    else result.push(b[j++]);
  }

  // ровно один из хвостов непустой
  while (i < a.length) result.push(a[i++]);
  while (j < b.length) result.push(b[j++]);

  return result;
}
```

**Почему `O(N log N)`.** Глубина рекурсии — `log N` (каждый раз делим пополам), на каждом
уровне суммарно обрабатывается `N` элементов при слиянии. Итого `N × log N`.

**Почему память `O(N)`.** На каждом слиянии создаётся новый массив. Плюс `O(log N)` на стек
вызовов — но `O(N)` доминирует.

**Почему стабильна.** При равенстве (`a[i] <= b[j]`) берём элемент из **левой** половины, то
есть тот, что был раньше в исходном массиве. Замени `<=` на `<` — стабильность потеряется.

### Quick Sort — вторая половина пары

```js
function quickSort(arr) {
  if (arr.length <= 1) return arr;

  const pivot = arr[arr.length - 1];               // опорный элемент
  const less = [];
  const greater = [];

  for (let i = 0; i < arr.length - 1; i++) {
    if (arr[i] <= pivot) less.push(arr[i]);
    else greater.push(arr[i]);
  }

  return [...quickSort(less), pivot, ...quickSort(greater)];
}
```

Эта версия наглядна, но тратит `O(N)` памяти. «Настоящий» quick sort сортирует **на месте**
(in-place, схема Ломуто/Хоара) и использует `O(log N)` на стек.

**Худший случай `O(N²)`** — когда pivot каждый раз оказывается минимумом или максимумом
(например, уже отсортированный массив при выборе последнего элемента). Лечится случайным
выбором pivot или «медианой трёх».

**Merge vs Quick — что говорить на интервью:**
- Merge: гарантированные `O(N log N)`, стабильная, но `O(N)` памяти;
- Quick: в среднем быстрее на практике (лучше локальность кеша), `O(log N)` памяти, но худший
  случай `O(N²)` и нестабильность.

## ⚠️ Частые ошибки / чек-лист

- ❌ **`arr.sort()` для чисел** — лексикографическая сортировка. Всегда пиши компаратор.
- ❌ **Забыть, что `sort()` мутирует** исходный массив (сюрприз в React-состоянии!).
- ❌ **Компаратор, возвращающий `boolean`** (`(a, b) => a > b`) — `true`/`false` приводятся к
  `1`/`0`, «меньше» никогда не возвращается → результат непредсказуем.
- ❌ **Сортировать там, где хватило бы `Map`** — лишний `log N` в сложности.
- ❌ **Считать сложность неверно:** «сортировка + один проход» — это `O(N log N)`, а не `O(N)`,
  доминирует более дорогое слагаемое.
- ❌ Забыть про `localeCompare` при сортировке строк на русском.
- ✅ Если после сортировки применяются two pointers — не забудь **упомянуть общую сложность**:
  `O(N log N)` от сортировки + `O(N)` от прохода = `O(N log N)`.

## ✅ Мини-опрос для самопроверки

1. Что вернёт `[1, 10, 2].sort()` и почему?
2. Как отсортировать массив объектов по полю `age` по убыванию?
3. Что значит «стабильная сортировка» и когда это важно?
4. Почему нижняя граница сортировки сравнениями — `O(N log N)`, и как counting sort её обходит?
5. У quick sort «средняя `O(N log N)`, худшая `O(N²)`» — когда наступает худший случай?
6. Задача: «найти, есть ли в массиве пара с суммой X». Стоит ли сортировать?

<details>
<summary>Ответы</summary>

1. `[1, 10, 2]` — то есть массив не изменится. `sort()` без компаратора сравнивает **строковые**
   представления: `"1" < "10" < "2"`. Нужно `sort((a, b) => a - b)`.
2. `people.sort((a, b) => b.age - a.age)`. Если нужна копия — `[...people].sort(...)` или
   `people.toSorted(...)`.
3. Равные по ключу элементы сохраняют исходный относительный порядок. Важно при **многоключевой**
   сортировке: отсортировал по имени, затем стабильно по возрасту — внутри одного возраста
   порядок по имени сохранится. `Array.sort()` стабильна с ES2019.
4. Любая сортировка сравнениями — это дерево решений с `N!` листьями; его высота не меньше
   `log₂(N!) ≈ N log N`, а высота = число сравнений в худшем случае. Counting sort не сравнивает
   элементы, а использует их **значения как индексы** корзин, поэтому ограничение не действует —
   ценой `O(K)` памяти на диапазон значений.
5. Когда опорный элемент систематически оказывается крайним (минимум/максимум) — например, при
   выборе последнего элемента на уже отсортированном массиве. Тогда разбиение даёт части `N-1`
   и `0`, глубина рекурсии `N` вместо `log N`. Лечится случайным pivot или медианой трёх.
6. Нет, если достаточно `Set`: один проход, для каждого `n` проверяем `set.has(X - n)` →
   `O(N)` время. Сортировка + two pointers даст `O(N log N)` — хуже. Сортировка выигрывает,
   только если нужны **сами пары в порядке**, требуется `O(1)` память или массив уже отсортирован.

</details>
