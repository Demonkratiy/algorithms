# Algo — учимся решать

Учебный тренажёр для подготовки к Frontend / BigTech-интервью: теория, практика на
JavaScript и выполнение решений прямо в браузере. Без регистрации и без ИИ в проверке.

## Возможности

- Все темы и условия доступны для чтения.
- **Весь материал подключён: 101 задание по 22 темам.** Это 99 задач с Monaco Editor
  и автоматической проверкой кода и 2 мини-теста Event Loop.
- Алгоритмы, структуры данных, DP и Greedy — 81 задача. JS — 18 задач с кодом
  (утилиты, объекты, промисы, отмена) и 2 мини-теста.
- Throttle leading и leading + trailing — отдельные задания, как и другие самостоятельные
  части курса. Поэтому общее число выросло со 100 до 101.
- Подсказки открываются постепенно, разбор — после отдельного подтверждения.
- Во всех 99 кодовых задачах есть подсказки и свёрнутый разбор с JavaScript-решением.
  Для мини-тестов предусмотрены ответы и пояснения к каждому сниппету.
- Одна кнопка **«Проверить решение»** запускает полный набор тестов и сменяется на
  **«Остановить»** во время выполнения. Результаты и консоль сгруппированы по тестам;
  вывод до начала тестов показан отдельно.
- Код автоматически сохраняется в IndexedDB. Хранятся последние пять запусков задачи
  со снимками кода, оценки сложности и отметка успешной полной проверки.
- Темы интерфейса и редактора независимы: светлая, тёмная, системная.
- Условие, редактор и результаты — независимые панели с перетаскиваемыми границами,
  сворачиванием и временным разворачиванием на рабочую область.
- Оценки времени и памяти выбираются карточками. После успешной проверки сравниваются
  с целевыми оценками задачи, без автоматического анализа сложности кода.
- Прогресс можно экспортировать и импортировать в настройках.

Рекомендуемый сценарий — компьютер с актуальным Chromium-браузером. Чтение адаптировано
для небольших экранов; полноценное редактирование на телефоне пока не целевой сценарий.

## Запуск

Нужен Node.js 24 LTS и npm.

```sh
npm ci
npm run dev
```

Открой URL, указанный Vite. Зависимости Monaco загружаются из сборки приложения, не с CDN.
Смена порта или домена означает другое локальное хранилище: для переноса используй экспорт.

```sh
npm run build       # TypeScript + production-сборка
npm run preview     # Просмотр production-сборки
npm test            # Модульные тесты
npx playwright install chromium
npm run test:e2e    # Браузерные тесты; временный сервер запускается автоматически
```

Полнота материалов проверяется для каждого задания, без списка разрешённых пропусков.
`tests/reference-solutions.spec.ts` дополнительно исполняет код новых разборов первых
трёх паттернов прямо из Markdown на тех же тестах, что и решения пользователя.

Для проверки именно собранного приложения после `npm run build` в PowerShell:

```powershell
$env:ALGO_PREVIEW = '1'
npm run test:e2e -- app.spec.ts layout.spec.ts
npm run test:e2e -- task-batch.spec.ts --grep 'workspace|UI lists'
npm run test:e2e -- linear-structures.spec.ts --grep workspace
npm run test:e2e -- search-sort-heap.spec.ts --grep workspace
npm run test:e2e -- recursion-tree-graph.spec.ts --grep workspace
npm run test:e2e -- dp-greedy.spec.ts --grep workspace
npm run test:e2e -- js-scenarios.spec.ts --grep workspace
npm run test:e2e -- quiz.spec.ts
npm run test:e2e -- split-drafts.spec.ts
Remove-Item Env:\ALGO_PREVIEW
```

В VS Code также доступны задачи **Algo: dev** и **Algo: build**.

## Навигация по курсу

Слева — раскрываемые разделы, темы и ссылки на задачи. Название темы сразу открывает
теорию и раскрывает задачи. На странице этой темы повторный клик по названию
сворачивает/разворачивает список, не меняя страницу. Стрелка переключает только список.
Вся строка раздела переключает его раскрытие; темы без практики просто открывают теорию.
При переходе раскрывается текущая ветка и подсвечивается
активная страница; выбранную ветку можно свернуть вручную. Состояние раскрытия сохраняется
при переходах внутри приложения, после перезагрузки открывается текущая ветка.

Номера иерархические: `2.1` — Two Pointers, `2.1.1` — Valid Palindrome,
`2.1.2` — Move Zeroes. Номер задания виден в меню, списке практики и заголовке страницы.
Задания нумеруются по текущему порядку каталога, включая разделённые части, а не по
устаревшим номерам файлов. Темы согласованы с порядком теоретических файлов.
На странице «Все темы» карточки сгруппированы по восьми разделам.

Метки «Основная» / «Дополнительная» берутся из оглавления [практики](content/practice/README.md);
тесты сверяют их с явными заголовками задач. Сначала рекомендуется пройти основные,
дополнительные можно отложить. Доступ не блокируется. Номера и приоритеты не меняют
ID, пути или сохранённый прогресс.

## Расположение рабочего места

Меню **«Расположение»** предлагает три схемы: колонки, результаты снизу и вертикально.
У каждой схемы свои размеры. Схема, размеры и свёрнутые панели сохраняются для всего
рабочего места в localStorage, не для отдельной задачи. Они не входят в экспорт прогресса.

- Перетаскивай разделители мышью или касанием.
- С клавиатуры: Tab до разделителя, стрелки для изменения размера, Shift для большого
  шага, Home/End для минимального/максимального положения.
- Иконки в заголовках сворачивают панель до полоски или временно разворачивают её.
  Возврат из развёрнутого режима сохраняет прежние размеры и свёрнутые панели.
- **«Сбросить расположение»** возвращает исходную схему и размеры, не меняя код.
- На узком рабочем месте используется вертикальная схема, но выбор для широкого экрана
  не перезаписывается. Свободное перемещение панелей пока не реализуется.

Monaco и содержимое панелей не размонтируются при смене схемы или сворачивании:
код, курсор, undo, подсказки и результаты сохраняются в пределах открытой задачи.

Проверки компоновки: `npm run test:e2e -- layout.spec.ts`.

## Оценка сложности

В блоке **«Моя оценка сложности»** для Range Sum Query есть четыре группы карточек:
время и дополнительная память подготовки, время и дополнительная память одного запроса.
Для задач-функций — две группы: время и дополнительная память. Значение переменных,
учёт выходного массива и допустимые альтернативы поясняются в конкретной задаче.
Варианты не выбраны заранее; доступен ответ «Пока не знаю».
Блок расположен внутри панели редактора, сразу после кода и перед кнопкой проверки:
**код → необязательная оценка → проверка → результаты**. В небольшой панели содержимое
прокручивается, а кнопки проверки/остановки остаются доступны. История запусков — под панелями.

Общая кнопка **«Проверить решение»** фиксирует код и выбранные оценки в момент нажатия.
После успешных тестов результат содержит отдельную сверку с целями задачи:

- пустой выбор и «Пока не знаю» означают незаполненную оценку, но не блокируют тесты;
- несовпадение означает отличие от цели, а не ошибку в оценке конкретной реализации;
- при ошибке, провале тестов, отмене или таймауте сверка не проводится;
- изменение кода или выбора после успешного запуска делает сверку устаревшей;
- выбор, изменённый во время запуска, не подменяет снимок текущей попытки.

Выбор сохраняется между посещениями. Сама сверка относится к текущему запуску и после
перезагрузки не восстанавливается как актуальный результат. Прежние текстовые оценки
доступны для чтения и не преобразуются в карточки автоматически.

Варианты, определения переменных, цели и пояснения заданы в описаниях из
[tasks/](tasks/), а не в React-компоненте. `accepted` позволяет явно указать дополнительные
допустимые оценки, например сортировку и более быстрый подход из учебного материала.
Совпадение с целью **не подтверждает Big O самого кода**; в условии целевые оценки
уже открыто указаны.

## Самостоятельные части и старые решения

Самостоятельные цели A/B и существенные бонусы разделены на отдельные задачи.
Например, обнаружение цикла и поиск его входа, Meeting Rooms I/II, базовый Min-Heap,
Heap с компаратором и Heapify проверяются независимо. Примеры и внутренние helpers
одного алгоритма не разделяются.

У первой части сохранены прежние ID и пути, поэтому старый код и история остаются
на месте. У новых исполняемых частей есть ссылка на прежнюю общую задачу и кнопка **«Взять прежний код»**.
Копирование требует подтверждения, не изменяет источник и не переносит отметку успеха
или историю в новую часть: её нужно проверить отдельно.

## JS-сценарии и мини-тесты

JS-функции действительно исполняются в Worker. Для `debounce`, `throttle`, промисов
и отмены используются виртуальные таймеры: `Date.now()` / `performance.now()` движутся
вместе с контролируемыми часами, а между таймерами выполняются реальные микрозадачи.
Поэтому ждать несколько секунд в реальном времени не нужно. HTTP-запросы заменены
локальными mock-функциями; настоящий доступ к сети не предоставляется.

Каждый сценарий получает свежую копию модуля решения. Проверяются аргументы и `this`,
состояние, результат/ошибка, порядок, конкуренция, очистка таймеров и отмена по контракту.
Ограничения на время и логи остаются; бесконечный код можно остановить.

Event Loop — отдельные мини-тесты без Monaco и запуска пользовательского кода.
Пользователь выбирает ответ, при желании записывает объяснение и нажимает
**«Проверить ответы»**. Разбор открывается только для отвеченных вопросов после проверки.
Свободное объяснение не оценивается автоматически. Изменение ответа/заметки делает
сверку устаревшей; сохраняются текущие ответы и последние пять попыток.

Для автора: JS-задачи описываются `ScenarioRunner` с доверенными тестовыми script-body.
Хелперы: `subject`, `assert`, `clock`, `observe`, `deferred`, `flush`, `useFetch`,
`setDependency`. Тесты сценариев не являются решениями ученика и не должны импортировать
эталонные реализации. Node-helper `scenario-test-support.ts` используется только тестами
с фиксированными fixtures, никогда для кода посетителя.

## Добавление материалов и задач

1. Добавь Markdown в соответствующий раздел `content/`.
2. Для задачи используй шаблон из [practice/README.md](content/practice/README.md):
   условие, ограничения, подсказки, заготовка, оценка сложности и разбор.
3. Зарегистрируй тему или задачу в `content/course.ts`. ID не меняй при переименовании
   файла: к нему привязан прогресс. Добавь ссылку с 🔴/⚪ в `content/practice/README.md`:
   это источник приоритета; отсутствие или повтор декларации — ошибка.
4. Для проверки создай `tasks/<id>/starter.js`, `cases.ts` и `task.ts` с типом
   [TaskDefinition](tasks/types.ts). Внеси определение в [реестр](tasks/index.ts).
   `runnable` вычисляется из реестра; задача без определения остаётся материалом.
5. Выбери контракт: `function` (аргументы → значение/изменённый аргумент),
   `class` (конструктор/фабрика → вызовы), `linked-list`, `binary-tree`, `graph-clone`
   или `scenario` для JS-поведения с функциями, таймерами и промисами.
   Укажи точное имя функции/класса, соответствующее условию и стартовому шаблону.
6. Добавь варианты/цели сложности и тесты только для допустимых входов. Общий валидатор
   проверяет метаданные, ссылки на варианты, аргументы и формат случаев.
7. Добавь тестовые реализации только в `tests/fixtures/`, проверь корректный вариант
   и типичные ошибки. Запусти тесты и сборку; при расширении набора обнови проверки каталога.

Для поддержанных контрактов **React-компоненты и код runner менять не требуется**.
Новый вид контракта требует отдельной реализации. Мини-тесты регистрируются отдельно
в `tasks/quizzes.ts`; тексты сниппетов и разборов берутся из Markdown, не дублируются.

### Правила сравнения

- `exact` — строгое значение/тип и порядок элементов; аргументы копируются перед вызовом.
- `unordered` — массив примитивов без учёта порядка, но с учётом повторений (Top K).
- `nested-unordered` — группы примитивов: игнорируется порядок групп и элементов внутри,
  но сохраняются состав групп и повторения (Group Anagrams).
- `unordered-tuples` — не учитывает порядок кортежей, но сохраняет порядок внутри
  каждого кортежа (например, начало и конец интервала).
- `closest-points` — проверяет принадлежность исходным точкам, количество повторений
  и ближайшие расстояния. При равенстве расстояний допускается любой правильный набор.
  Ожидаемый массив в таком тесте — пример допустимого ответа, не единственный ответ.
- `approximate` — числа с объявленной абсолютной/относительной погрешностью;
  строки, NaN и бесконечности не подменяют конечный числовой ответ.
- `topological-order` — любой допустимый порядок всех курсов, а не единственная
  последовательность из примера. При цикле нужен пустой массив.
- `expectedUndefined` доступен и функциям: отсутствие значения не равно `null`.
- Для Move Zeroes проверяется изменённый аргумент, не возвращаемая копия.
- `preserveArgs` и `freshArray` применяются, когда условие запрещает изменение входа
  и требует новый массив (Merge Sorted Arrays). Нарушение показывается в результате теста.

### Списки и методы без результата

Для `linked-list` тест задаёт массивы значений и необязательный `cycleAt`: индекс узла,
на который ссылается хвост. Отсутствующий `cycleAt` или `-1` означает отсутствие цикла.
Runner создаёт реальные `{ val, next }` и передаёт функции головы списков, затем
дополнительные аргументы. Конструктор `ListNode(val = 0, next = null)` доступен в решении.
Обозначение `List(...)` в результатах — описание входа, а не массив вместо узла.

- Ожидание `node` сравнивает ссылку на исходный узел, не только значение.
- Ожидание `list` проверяет значения и завершение на `null`; цикл или лишние узлы
  выявляются ограниченным обходом, без зависания сериализации.
- `reuseNodes`, `nodeOrder`, `preserveInputs` включаются только по требованиям задачи.
  Равные значения из разных входных списков могут идти в любом порядке при merge.
- Обнаружение цикла (`hasCycle`) и поиск входа (`detectCycle`) — отдельные задачи,
  со своими стартовыми шаблонами и тестами.
- В контракте класса `ignoreReturn: true` означает, что значение `push`/`pop` не задано
  условием. Вызов всё равно выполняется, а эффект проверяется последующими запросами.
  Каждый сценарий класса должен содержать хотя бы один вызов с ожидаемым значением.
- `expectedUndefined: true` проверяет именно `undefined`, а не `null` или игнорирование
  результата; `property` позволяет проверять свойства, например `heap.size`.
- `factories` создаёт доверенные числовые/объектные компараторы внутри Worker:
  функции не сериализуются и не передаются в тестах строками кода.
- `factoryMethod` создаёт экземпляр через статическую фабрику, например
  `MinHeap.heapify(array, compare)`. При `preserveArgs` исходный массив не должен меняться
  ни при построении, ни при последующих операциях с кучей.

### Деревья и графы

`binary-tree` принимает compact level-order массив. Например, `[1, null, 2, 3]`
означает `1.right = 2`, `2.left = 3`, а не индексацию бинарной кучи.
Runner передаёт настоящие `TreeNode(val, left, right)`. `nodeArgs` ссылаются на позиции
непустых узлов в исходном массиве — LCA возвращает именно исходный узел.
Выходное дерево проверяется по структуре и значениям; циклы и общие потомки отвергаются
ограниченным обходом. Требования сохранения входа/переиспользования узлов задаются явно.

`graph-clone` создаёт реальные `Node(val, neighbors)` из списка смежности, включая циклы.
Вершины в списке смежности нумеруются с 1; `values` может задать собственные уникальные
значения, `start` — индекс корневой вершины с 0. Копия должна содержать новые узлы
и новые массивы соседей, не ссылаться на оригинал и сохранять соответствие «вершина → копия».
Порядок соседей не важен. Для пустого графа ожидается строго `null`.

Не помещай личное решение в публичный стартовый код. Условие не дублируется в тестах.
Разборы скрыты средствами интерфейса, а не являются секретными серверными данными.

## Выполнение и его ограничения

Код выполняется в Worker внутри sandboxed iframe с отдельным opaque origin и
ограничивающей CSP. Runner ограничивает длительность запуска и объём вывода; отмена
удаляет окружение запуска. Ошибки инфраструктуры и незавершённые запуски не засчитываются.
Исходники окружения включены в сборку: iframe использует `srcdoc`, Worker — временный
Blob URL. Дополнительного сервера выполнения и отдельных сетевых запросов к runner нет.

- Это учебная проверка, **не система защиты от списывания**: тесты и клиентский код доступны.
- Намеренно враждебный код внутри Worker может пытаться подделывать результаты.
- Надёжный лимит памяти процесса браузера не гарантируется; экстремальные выделения
  памяти способны повлиять на вкладку или браузер.
- Время запуска не доказывает Big O. Оценка времени и памяти остаётся самостоятельной.
- «Есть успешная проверка» означает исторический успех; после редактирования код нужно
  проверить заново. Успех означает прохождение полного набора, а не доказательство Big O.

Общий лимит консоли для всего запуска — 100 сообщений, по 1000 символов и 20 000 символов
суммарно. При сокращении вывода отображается предупреждение. Если тест выбросил исключение,
его логи сохраняются, а дальнейшая проверка останавливается. При таймауте или отмене
отчёт Worker не получен, поэтому промежуточные логи недоступны.

Не вставляй в решения секреты. Перед публичным размещением нужно проверить ограничения
изолированного окружения на выбранном хостинге и в целевых браузерах.

## Данные и резервные копии

Данные не синхронизируются между устройствами. Очистка данных сайта и приватный режим
могут привести к потере прогресса. Настройки хранятся в localStorage, решения — в IndexedDB.

JSON-экспорт версии 3 содержит код, последние запуски, прогресс, оценки сложности,
ответы и заметки мини-тестов, но не настройки тем. Импорт принимает версии 1, 2 и 3.
Импорт проверяет формат до записи и требует подтверждения: совпадающие ID заменяются,
остальные записи сохраняются. Лимит файла — 5 МБ. Ключей провайдеров или авторизации
в этом формате нет.
Старые попытки с режимом `example` сохраняются и импортируются как история; новые
попытки всегда записываются с режимом `check`.

## Что отложено

CI, расширенный прогресс в каталоге, аккаунты, синхронизация и ИИ-наставник.
Будущая панель наставника не влияет на независимость обычной проверки;
провайдеры и отправка кода сейчас не подключены.
